## Книга на полке

В библиотеке двести книг. Нужно найти «Алгоритмы». Если книги стоят в случайном порядке, придётся просмотреть корешки одну за другой. В худшем случае понадобится двести проверок.

Если книги расставлены по алфавиту, работает другой приём. Открываем середину, сравниваем название, отбрасываем половину полки и повторяем. Для двухсот книг хватает восьми проверок, потому что `2^8 = 256`.

Сортировка и поиск связаны. Сортировка стоит времени, но затем каждый поиск становится дешевле. Если искать один раз, проще перебрать. Если искать сотни раз, сортировка окупается.

Главная мысль занятия: **алгоритм выбирают по числу операций и по тому, сколько раз его вызовут**. Сортировка это подготовка данных, поиск это операция над подготовленными данными.

## Встроенная сортировка

В Python сортируют двумя способами:

```python
numbers = [42, 7, 19, 3, 25]
numbers.sort()
print(numbers)
print(sorted([42, 7, 19, 3, 25]))
```

```text
[3, 7, 19, 25, 42]
[3, 7, 19, 25, 42]
```

`sort` меняет список на месте и возвращает `None`. `sorted` возвращает новый список, а исходный не трогает. Ошибка `result = numbers.sort()` записывает в `result` значение `None`.

Обратный порядок задают параметром `reverse`:

```python
print(sorted(numbers, reverse=True))
```

```text
[42, 25, 19, 7, 3]
```

Для записей сортировка по полю выполняется через ключ:

```python
products = [
    {"name": "кружка", "price": 640},
    {"name": "блюдце", "price": 420},
    {"name": "коробка", "price": 40},
]

by_price = sorted(products, key=lambda item: item["price"])
print([p["name"] for p in by_price])
```

```text
['коробка', 'блюдце', 'кружка']
```

Ключ это функция, которая возвращает значение для сравнения. `lambda item: item["price"]` берёт цену. Сортировка не меняет сами словари, только их порядок в новом списке.

При равных значениях сортировка сохраняет исходный порядок. Это называется устойчивостью. Если нужен вторичный критерий, ключ возвращает кортеж:

```python
sorted(products, key=lambda item: (item["price"], item["name"]))
```

Сначала сравнивается цена, при равенстве имя.

## Как работает сортировка

Простейший алгоритм это сортировка пузырьком. Он сравнивает соседние элементы и меняет их местами, если порядок неверный. После первого прохода самый большой элемент оказывается в конце.

```python
values = [5, 3, 8, 1]
for i in range(len(values) - 1):
    for j in range(len(values) - 1 - i):
        if values[j] > values[j + 1]:
            values[j], values[j + 1] = values[j + 1], values[j]
print(values)
```

```text
[1, 3, 5, 8]
```

Пузырёк делает около `n^2` сравнений. Для ста элементов это десять тысяч операций. Встроенная сортировка Python использует более быстрый алгоритм и справляется за `n log n`, то есть примерно за тысячу операций для ста элементов.

Писать свою сортировку в рабочем коде не нужно. Но понимать её полезно: она показывает, почему порядок операций влияет на скорость.

## Линейный поиск

Линейный поиск перебирает элементы по порядку.

```python
def linear_search(values, target):
    for i, value in enumerate(values):
        if value == target:
            return i
    return -1

print(linear_search([3, 7, 12, 19, 25], 25))
print(linear_search([3, 7, 12, 19, 25], 8))
```

```text
4
-1
```

Возврат `-1` означает «не найдено». В худшем случае проверяются все `n` элементов, поэтому сложность линейного поиска `O(n)`.

Линейный поиск не требует порядка. Он работает и на списке, и на кортеже, и на строке.

## Бинарный поиск

Бинарный поиск работает только на отсортированных данных. Он смотрит в середину диапазона и отбрасывает половину.

```python
def binary_search(values, target):
    low = 0
    high = len(values) - 1
    while low <= high:
        mid = (low + high) // 2
        if values[mid] == target:
            return mid
        if values[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1
```

Проверим на списке `[3, 7, 12, 19, 25, 31, 42, 56]` и цели `25`.

1. `low = 0`, `high = 7`, `mid = 3`, значение `19`. `19 < 25`, значит `low = 4`.
2. `low = 4`, `high = 7`, `mid = 5`, значение `31`. `31 > 25`, значит `high = 4`.
3. `low = 4`, `high = 4`, `mid = 4`, значение `25`. Найдено.

Три сравнения вместо пяти. Для тысячи элементов нужно около десяти сравнений, для миллиона около двадцати.

::figure binary-search | Интерактивный бинарный поиск: нажимайте «Шаг» и следите за границами low, mid и high.

Условие `low <= high` важно. Если написать `low < high`, диапазон из одного элемента не будет проверен, и последний кандидат потеряется.

Середину считают через `(low + high) // 2`. В Python переполнения нет, но в других языках для больших чисел используют `low + (high - low) // 2`.

## Сложность и выбор

Сложность оценивают по числу шагов в худшем случае.

| Алгоритм | Худший случай | Что требует |
|---|---|---|
| Линейный поиск | `O(n)` | ничего |
| Бинарный поиск | `O(log n)` | отсортированный список |
| Сортировка пузырьком | `O(n^2)` | ничего |
| Встроенная сортировка | `O(n log n)` | сравнимые элементы |

`O(log n)` означает, что при удвоении данных число шагов растёт на единицу. `O(n)` означает, что число шагов растёт пропорционально данным. `O(n^2)` растёт квадратично и быстро становится неприемлемым.

Выбор зависит от задачи:

- один поиск в коротком списке: линейный;
- много поисков в большом списке: сортировка и бинарный поиск;
- данные часто меняются: сортировка после каждого изменения может быть дорогой;
- нужен поиск по ключу: словарь даёт почти мгновенный доступ без сортировки.

Словарь из предыдущей лекции это третий вариант: он не сортирует список, а строит индекс. Для поиска по точному ключу он обычно быстрее бинарного поиска.

## Границы и ошибки

**Поиск в неотсортированном списке.** Бинарный поиск даёт неверный результат без ошибки. Проверка: перед вызовом убедитесь, что список отсортирован.

**Потерянная граница.** `high = len(values)` вместо `len(values) - 1` приводит к `IndexError`. Верхняя граница включается в диапазон.

**Неверное обновление.** `low = mid` вместо `low = mid + 1` может зациклить поиск. Диапазон должен уменьшаться на каждом шаге.

**Сортировка словарей по значению без ключа.** `sorted(products)` сравнивает словари целиком и падает с `TypeError`. Нужен `key`.

**Смешение `sort` и `sorted`.** `sort` возвращает `None`. Результат нельзя присваивать, если нужен новый список.

**Дубликаты.** Бинарный поиск находит какой-то один индекс, не обязательно первый. Для первого вхождения после находки двигаются влево.

> [!PITFALL] Сортировка не делает поиск бесплатным. Если данные меняются после каждого поиска, сортировать заново дороже, чем один раз перебрать список.

## Итоги

- `sort` меняет список, `sorted` возвращает новый; ключ задаёт поле сравнения.
- Линейный поиск делает до `n` сравнений и не требует порядка.
- Бинарный поиск делает около `log n` сравнений и требует отсортированных данных.
- Встроенная сортировка работает за `O(n log n)`, пузырёк за `O(n^2)`.
- Алгоритм выбирают по числу поисков, объёму данных и частоте изменений.
