## Программа, которая падает на первом же вводе

Калькулятор просит число и делит сто на него:

```python
value = int(input("Делитель: "))
print(100 / value)
```

Запуск с числом `4` даёт `25.0`. Запуск с нулём даёт:

```text
Traceback (most recent call last):
  File "calc.py", line 2, in <module>
    print(100 / value)
ZeroDivisionError: division by zero
```

Запуск со словом `четыре` даёт другую ошибку:

```text
ValueError: invalid literal for int() with base 10: 'четыре'
```

Обе ошибки ожидаемы. Пользователь может ввести ноль или букву, и программа должна ответить понятным сообщением, а не стеком вызовов. Для этого исключение перехватывают.

Главная мысль занятия: **исключение это способ сообщить о проблеме, которую нельзя было предотвратить проверкой**. Его можно перехватить, обработать и продолжить работу. Но перехватывать всё подряд опаснее, чем не перехватывать ничего: программа перестаёт сообщать о настоящих дефектах.

## Виды ошибок

Ошибки делятся на две большие группы.

**Синтаксические** возникают до выполнения. Python не может разобрать код:

```python
if x > 0
    print(x)
```

```text
SyntaxError: expected ':'
```

Пропущено двоеточие. Пока синтаксис неверен, программа не запустится вообще.

**Ошибки времени выполнения** появляются при конкретных данных. Код синтаксически верен, но операция невозможна. Основные типы собраны в таблице.

| Исключение | Когда возникает |
|---|---|
| `NameError` | имя не определено |
| `TypeError` | операция не подходит для типа |
| `ValueError` | тип верный, значение нет |
| `IndexError` | индекс за пределами последовательности |
| `KeyError` | ключа нет в словаре |
| `ZeroDivisionError` | деление на ноль |
| `FileNotFoundError` | файл не найден |
| `AttributeError` | у объекта нет такого метода или поля |

Различать их полезно: по типу исключения часто понятно, что именно проверять.

```python
int("12")      # работает
int("12.5")    # ValueError
"12" + 5       # TypeError
[1, 2][5]      # IndexError
{"a": 1}["b"]  # KeyError
```

## try и except

Конструкция `try` пытается выполнить код, а `except` перехватывает выбранное исключение.

```python
try:
    value = int(input("Делитель: "))
    print(100 / value)
except ValueError:
    print("Нужно целое число.")
except ZeroDivisionError:
    print("На ноль делить нельзя.")
```

Если ввод корректен, блок `except` пропускается. Если возникает `ValueError`, выполняется первая ветвь. Если `ZeroDivisionError`, вторая.

Порядок ветвей важен. Более узкие исключения ставят раньше общих:

```python
except ZeroDivisionError:
    ...
except ArithmeticError:
    ...
except Exception:
    ...
```

`ZeroDivisionError` является подтипом `ArithmeticError`, поэтому при обратном порядке общая ветвь перехватила бы всё.

Пойманное исключение можно сохранить и изучить:

```python
try:
    value = int(raw)
except ValueError as error:
    print("Не удалось преобразовать:", error)
```

`error` содержит текст сообщения. Для пользователя он часто слишком технический, поэтому лучше выдавать своё объяснение, а исходный текст писать в журнал.

## else и finally

`else` выполняется, только если исключения не было:

```python
try:
    value = int(raw)
except ValueError:
    print("Нужно число.")
else:
    print("Квадрат:", value ** 2)
```

`finally` выполняется всегда: и при успехе, и при ошибке, и даже при `return` внутри `try`.

```python
try:
    f = open("data.txt", encoding="utf-8")
    text = f.read()
finally:
    f.close()
```

Для файлов удобнее `with`, но `finally` показывает общий принцип: освобождение ресурса не должно зависеть от того, чем закончилась операция.

## Собственные исключения

Иногда нужно сообщить о проблеме, для которой нет готового типа. Тогда создают своё исключение:

```python
class NegativePriceError(ValueError):
    pass

def check_price(price):
    if price < 0:
        raise NegativePriceError("Цена не может быть отрицательной")
    return price
```

`raise` прерывает функцию и передаёт исключение вызывающему коду. Наследование от `ValueError` позволяет перехватывать его и как `NegativePriceError`, и как `ValueError`.

Готовые исключения тоже можно поднимать:

```python
if not raw.isdigit():
    raise ValueError("Ожидалось целое число")
```

Своё сообщение должно объяснять, что не так и что ожидалось. Фраза «ошибка» без подробностей бесполезна.

## Чтение трассировки

Трассировка читается снизу вверх. Последняя строка содержит тип исключения и сообщение. Выше перечислены вызовы, от самого внешнего к самому внутреннему. Последний вызов перед ошибкой это место, где она возникла.

```text
Traceback (most recent call last):
  File "report.py", line 12, in <module>
    total = calculate(rows)
  File "report.py", line 7, in calculate
    return sum(row["price"] for row in rows)
KeyError: 'price'
```

Сначала смотрят `KeyError: 'price'`. Затем находят строку `report.py`, line 7, где ключ запрашивается. И только потом проверяют, почему в данных нет поля `price`.

Частая ошибка новичка: читать сверху и искать причину в первой строке. Первая строка это точка входа, а не место сбоя.

## Отладка без догадок

Отладка это проверка гипотез, а не перебор случайных правок.

**Печать значений.** Вставьте `print` перед подозрительной строкой и посмотрите, что реально лежит в переменной. Часто оказывается, что это строка, а не число.

**Проверка типов.** `print(type(value))` показывает тип. Для ввода это почти всегда `str`.

**Минимальный пример.** Уберите всё лишнее и оставьте три строки, которые воспроизводят ошибку. Так причина видна быстрее.

**Границы.** Проверьте пустой ввод, ноль, отрицательное число, очень большое число, отсутствующий файл.

**Точка останова.** В VS Code можно поставить точку останова и выполнять программу по шагам. Это удобнее десятка `print`, но требует привычки.

## Где обработка ошибок ломается

**Голый `except`.** `except:` перехватывает всё, включая опечатки и прерывание с клавиатуры. Исправление: указывать конкретный тип.

**Молчаливое проглатывание.** `except ValueError: pass` скрывает проблему. Пользователь не понимает, почему ничего не произошло. Исправление: сообщение или запись в журнал.

**Слишком широкий `try`.** В блоке десять строк, и непонятно, какая дала ошибку. Исправление: держать в `try` только операцию, которая может упасть.

**Неверный порядок `except`.** Общая ветвь стоит первой и перехватывает частные случаи. Исправление: от узкого к общему.

**Проверка после операции.** Сначала делят, потом проверяют делитель. Исправление: проверять до опасного действия, если это возможно.

**Исключение вместо проверки.** Ошибку используют для обычной логики, например для выхода из цикла. Это замедляет код и запутывает чтение.

> [!PITFALL] Перехваченное исключение не исчезает. Если его не обработать и не записать, причина сбоя теряется навсегда.

## Итоги

- Синтаксические ошибки мешают запуску, ошибки времени выполнения зависят от данных.
- `try` защищает опасную операцию, `except` перехватывает конкретный тип.
- `else` работает при успехе, `finally` выполняется всегда.
- `raise` поднимает исключение, своё исключение наследуют от подходящего встроенного.
- Трассировку читают снизу вверх: тип, затем строка, затем данные.

Q: Когда возникает `SyntaxError`?
+ До выполнения, при разборе кода
- При делении на ноль
- При неверном ключе
- При отсутствии файла
! Программа не запускается, пока синтаксис неверен.

Q: Что означает `ValueError`?
+ Тип верный, но значение не подходит
- Имя не определено
- Индекс за границей
- Файл не найден
! Например, `int("abc")`.

Q: Что означает `TypeError`?
+ Операция не подходит для этого типа
- Значение не подходит
- Ключ отсутствует
- Файл не найден
! Например, сложение строки и числа.

Q: Что перехватывает `except ZeroDivisionError`?
+ Деление на ноль
- Неверный ключ
- Неверный индекс
- Ошибку синтаксиса
! Это отдельный тип исключения.

Q: Когда выполняется `else` в конструкции try?
+ Когда исключения не было
- Всегда
- Только при ошибке
- Только при `return`
! `else` это успешная ветвь.

Q: Когда выполняется `finally`?
+ Всегда
- Только при успехе
- Только при ошибке
- Никогда
! `finally` нужен для освобождения ресурсов.

Q: Что делает `raise`?
+ Поднимает исключение
- Перехватывает исключение
- Печатает трассировку
- Игнорирует ошибку
! `raise` прерывает выполнение и передаёт исключение выше.

Q: С какой строки начинают читать трассировку?
+ С последней, где тип и сообщение
- С первой, где точка входа
- С середины
- С конца файла
! Последняя строка называет причину.

Q: Почему голый `except:` опасен?
+ Перехватывает все ошибки, включая опечатки
- Работает медленнее
- Не поддерживает `print`
- Требует `finally`
! Он скрывает настоящие дефекты.

Q: Какие исключения относятся к ошибкам данных?
+ `ValueError`
+ `KeyError`
+ `IndexError`
+ `ZeroDivisionError`
- `SyntaxError`
- `IndentationError`
! Последние две возникают при разборе кода.

Q: Какие блоки могут входить в обработку исключения?
+ `try`
+ `except`
+ `else`
+ `finally`
- `catch`
- `switch`
! В Python нет `catch` и `switch`.

Q: Какие действия помогают отладке?
+ Печать значений и типов
+ Минимальный пример
+ Проверка границ
+ Чтение трассировки снизу вверх
- Случайная правка кода
- Удаление всех проверок
! Отладка это проверка гипотез.

Q: Какое исключение возникает при `int("abc")`?
= ValueError
= value error
! Строка не является целым числом.

Q: Какое исключение возникает при делении на ноль?
= ZeroDivisionError
= zero division error
! Python сообщает `ZeroDivisionError`.

Q: Что выполняется всегда, независимо от ошибки?
= finally
= блок finally
! `finally` нужен для обязательных действий.
