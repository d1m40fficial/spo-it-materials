## Три списка вместо одного товара

В программе магазина товар описан тремя списками:

```python
names = ["Кружка", "Блюдце", "Коробка"]
prices = [640, 420, 40]
quantities = [3, 2, 10]
```

Чтобы посчитать стоимость кружки, нужно взять элемент с одним и тем же индексом из трёх списков. Если один список отредактировали, а другой забыли, данные разъедутся. Функция расчёта принимает три аргумента и не проверяет, что они относятся к одному товару.

Объект объединяет данные и действия:

```python
class Product:
    def __init__(self, name, price, quantity):
        self.name = name
        self.price = price
        self.quantity = quantity

    def total(self):
        return self.price * self.quantity

cup = Product("Кружка", 640, 3)
print(cup.total())
```

```text
1920
```

Теперь имя, цена, количество и расчёт лежат вместе. Новый товар создаётся одной строкой, а поля не могут перепутаться местами.

Главная мысль занятия: **класс это описание, объект это конкретное состояние по этому описанию**. Один класс обслуживает сколько угодно объектов, и каждый хранит свои значения.

## Класс и экземпляр

Класс объявляют через `class`. Имя класса пишут с заглавной буквы. Тело класса содержит методы.

```python
class Product:
    def __init__(self, name, price, quantity):
        self.name = name
        self.price = price
        self.quantity = quantity

    def total(self):
        return self.price * self.quantity

    def discount(self, percent):
        return self.total() * (1 - percent / 100)
```

`__init__` это конструктор. Он выполняется при создании объекта и заполняет поля. Первый параметр `self` это сам создаваемый объект.

```python
cup = Product("Кружка", 640, 3)
plate = Product("Блюдце", 420, 2)
```

`cup` и `plate` это два объекта одного класса. У них одинаковый набор полей и методов, но разные значения.

```python
print(cup.name, cup.total())
print(plate.name, plate.total())
```

```text
Кружка 1920
Блюдце 840
```

Класс это чертёж, объект это изделие по чертежу. Чертёж один, изделий много.

## self

`self` связывает метод с конкретным объектом. Когда вызывается `cup.total()`, Python передаёт `cup` в параметр `self`. Внутри метода `self.price` означает «цена этого объекта».

```python
def total(self):
    return self.price * self.quantity
```

Если забыть `self` в объявлении, вызов `cup.total()` передаст объект в первый параметр, которого нет, и возникнет `TypeError`. Если забыть `self` перед полем, Python будет искать глобальную переменную `price` и выдаст `NameError`.

Внутри класса методы вызывают друг друга через `self`:

```python
def discount(self, percent):
    return self.total() * (1 - percent / 100)
```

`self.total()` вызывает метод у того же объекта.

## Состояние

Поля объекта можно читать и менять.

```python
cup = Product("Кружка", 640, 3)
print(cup.quantity)
cup.quantity = 5
print(cup.total())
```

```text
3
3200
```

Метод `total` не хранит результат, а вычисляет его по текущим полям. Поэтому после изменения количества итог меняется автоматически.

Если нужно изменить состояние через метод, метод пишет в `self`:

```python
def add(self, amount):
    self.quantity += amount
```

```python
cup.add(2)
print(cup.quantity)
```

```text
5
```

Метод, который только читает поля, называют запросом. Метод, который меняет состояние, называют командой. Смешивать их в одном методе не запрещено, но затрудняет проверку.

## Класс или экземпляр

Поля, заданные в `__init__`, принадлежат объекту. Их называют атрибутами экземпляра.

```python
class Counter:
    count = 0

    def __init__(self):
        self.value = 0
```

`count` объявлен в теле класса и общий для всех объектов. `value` создаётся у каждого объекта свой. Изменение `Counter.count` видно всем, изменение `self.value` только одному.

Общие изменяемые атрибуты класса опасны:

```python
class Basket:
    items = []

    def add(self, item):
        self.items.append(item)
```

Все корзины будут делить один список. Правильно создавать список в `__init__`:

```python
class Basket:
    def __init__(self):
        self.items = []
```

## Печать объекта

По умолчанию `print(cup)` печатает нечто вроде `<__main__.Product object at 0x...>`. Это адрес, а не данные.

Метод `__str__` задаёт человекочитаемое представление:

```python
def __str__(self):
    return f"{self.name}: {self.total():.2f}"
```

```python
print(cup)
```

```text
Кружка: 1920.00
```

`__repr__` задаёт техническое представление для отладки. Часто достаточно `__str__`, но в отчётах об ошибках полезен и `__repr__`.

## Сравнение объектов

`==` по умолчанию сравнивает объекты по адресу. Два разных объекта с одинаковыми полями не равны.

```python
a = Product("Кружка", 640, 3)
b = Product("Кружка", 640, 3)
print(a == b)
```

```text
False
```

Чтобы сравнивать по значениям, определяют `__eq__`:

```python
def __eq__(self, other):
    return (self.name, self.price, self.quantity) == (other.name, other.price, other.quantity)
```

`is` сравнивает не значения, а тот ли это объект. `a is b` истинно только тогда, когда обе переменные указывают на один объект.

## Где классы ломаются

**Забытый `self`.** Метод объявлен как `def total():`, а вызывается у объекта. Python передаёт объект, но параметра нет. Исправление: `def total(self):`.

**Поле создаётся вне `__init__`.** Если `self.discount = 0` появляется только в одном методе, другой метод может обратиться к полю до его создания и получить `AttributeError`. Все поля создавайте в конструкторе.

**Изменяемый атрибут класса.** Список в теле класса общий для всех объектов. Исправление: создавать его в `__init__`.

**Забытый вызов `__init__`.** При создании объекта аргументы должны совпадать с конструктором. Лишний или недостающий аргумент даёт `TypeError`.

**Путаница класса и объекта.** `Product.total()` без объекта не работает: методу нужен `self`. Вызывайте метод у экземпляра.

**Слишком большой класс.** Класс на двадцать методов и десять полей трудно проверять. Разделите обязанности.

> [!PITFALL] `self` не является ключевым словом, но менять его имя без причины не стоит: читатель ожидает именно `self`.

## Итоги

- Класс описывает поля и методы, объект хранит конкретные значения.
- `__init__` заполняет поля при создании, `self` ссылается на объект.
- Методы читают и меняют состояние через `self`.
- Атрибуты экземпляра создаются в `__init__`, общие атрибуты класса опасны.
- `__str__` задаёт печать, `__eq__` сравнение по значениям.

+ `TypeError`
- Метод выполнится
- Объект удалится
- Поля обнулятся
! Python передаёт объект, но параметра для него нет.

+ В `__init__`

- В другом модуле
- В глобальной области
! Тогда все нужные поля существуют с момента создания.

Q: Какие утверждения о классах верны?
+ Один класс может создать много объектов
+ Поля хранят состояние объекта
+ Методы получают объект через `self`
+ Конструктор вызывается при создании

- Поля класса всегда личные
! Класс общий, состояния разные.

Q: Какие методы стоит определить для удобной работы с объектом?
+ `__init__`
+ `__str__`
+ `__eq__` при сравнении по значениям
- `__delete__`
- `__main__`
! Это стандартные методы объекта.
