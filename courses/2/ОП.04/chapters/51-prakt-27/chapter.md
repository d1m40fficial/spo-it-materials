## Что требуется

Доработать мини-проект `sales_report` из практики 26. Нужно добавить консольный интерфейс:

1. меню с командами;
2. чтение выбора с проверкой;
3. чтение суммы с проверкой;
4. добавление записи в память;
5. тесты на разбор ввода.

Расчёт и отчёт уже готовы. Менять их не нужно, кроме случаев, когда тест находит дефект.

## Ход работы

### Шаг 1. Запустите проект

```bash
python main.py
```

Проект печатает меню. Пока в `interface.py` остались `TODO`, команды не выполняются.

### Шаг 2. Разбор выбора

Функция `parse_choice(raw, allowed)` принимает строку и список допустимых номеров. Она возвращает число или `None`, если выбор неверный.

```python
parse_choice("2", {0, 1, 2, 3})   # 2
parse_choice("9", {0, 1, 2, 3})   # None
parse_choice("два", {0, 1})       # None
```

Функция не должна печатать и не должна читать ввод. Так её легко проверить тестом.

### Шаг 3. Разбор суммы

Функция `parse_amount(raw)` принимает строку и возвращает `float` или `None`.

Правила:

- пробелы по краям убираются;
- пустая строка даёт `None`;
- запятая как десятичный разделитель не принимается;
- отрицательное число даёт `None`;
- `0` допускается.

```python
parse_amount("1200.50")   # 1200.5
parse_amount(" 800 ")     # 800.0
parse_amount("-5")        # None
parse_amount("12,50")     # None
```

### Шаг 4. Меню

В `main.py` цикл показывает пункты и вызывает обработчик:

```text
1. Показать отчёт
2. Добавить запись
3. Найти по региону
0. Выход
```

Неверный пункт повторяет вопрос. Выход по `0` завершает цикл без лишних запросов.

### Шаг 5. Добавление записи

Команда добавления спрашивает дату, регион и сумму. Дата проверяется по шаблону из практики 24, сумма через `parse_amount`. Некорректный ввод повторяется или отменяется с сообщением.

Новая запись добавляется в список в памяти и сразу учитывается в отчёте.

### Шаг 6. Тесты

`tests/test_interface.py` проверяет `parse_choice` и `parse_amount` без чтения ввода. Запуск:

```bash
python -m unittest discover tests
```

Ожидается не меньше восьми тестов: обычные значения, границы и отказы.

### Шаг 7. Проверьте границы

| Что проверить | Ожидание |
|---|---|
| пустой ввод | повтор или отмена |
| выбор 0 | выход |
| выбор 9 | повтор |
| сумма с запятой | отказ |
| отрицательная сумма | отказ |
| сумма 0 | допускается |
| дата неверного формата | отказ |

### Шаг 8. Соберите отчёт

Заполните разделы: цель, структура проекта, код интерфейса, таблица проверок, результаты тестов, вывод. Вставьте скриншоты меню и тестов.

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
