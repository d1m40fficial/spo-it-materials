## Папки внутри папок

Каталог проекта содержит папки, а те содержат другие папки и файлы. Нужно посчитать общий размер. Заранее неизвестно, сколько уровней вложенности и сколько папок на каждом уровне.

Цикл по списку здесь не помогает: на каждом уровне структура повторяется, но её форма разная. Рекурсивная функция решает задачу одинаково на любом уровне:

```python
def total_size(folder):
    size = 0
    for item in folder["items"]:
        if item["type"] == "file":
            size += item["size"]
        else:
            size += total_size(item)
    return size
```

Функция вызывает саму себя для вложенной папки. Когда вложенных папок нет, цикл не выполняется, и возвращается ноль. Это и есть остановка.

Главная мысль занятия: **рекурсия заменяет повторение вложенности вызовом самой функции**. Чтобы она остановилась, нужен базовый случай, а чтобы продвинулась к нему, каждый вызов должен уменьшать задачу.

## База и шаг

У рекурсивной функции две обязательные части.

**База** это случай, в котором функция возвращает ответ без нового вызова. Без базы рекурсия не остановится.

**Шаг** это вызов самой себя с меньшей или более простой задачей. Шаг должен приближать к базе.

Факториал определяется так: `factorial(n) = n * factorial(n - 1)`, а `factorial(1) = 1`.

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(4))
```

```text
24
```

Разберём вызов.

1. `factorial(4)` не может вернуть результат, пока не получит `factorial(3)`.
2. `factorial(3)` ждёт `factorial(2)`.
3. `factorial(2)` ждёт `factorial(1)`.
4. `factorial(1)` попадает в базу и возвращает `1`.
5. `factorial(2)` возвращает `2 * 1 = 2`.
6. `factorial(3)` возвращает `3 * 2 = 6`.
7. `factorial(4)` возвращает `4 * 6 = 24`.

::figure recursion-chain | Вызовы идут вниз до базы, затем значения возвращаются вверх и умножаются на своё число.

Каждый вызов хранится в стеке. Глубина стека равна числу незавершённых вызовов. Для `factorial(4)` она равна четырём.

::gate Почему `factorial(1)` возвращает результат сразу, а `factorial(4)` ждёт три других вызова?

## Рекурсия на списке

Список тоже можно обрабатывать рекурсивно: сумма первого элемента и суммы остатка.

```python
def total(values):
    if not values:
        return 0
    return values[0] + total(values[1:])

print(total([4, 7, 2, 9]))
```

```text
22
```

База это пустой список. Шаг берёт первый элемент и вызывает функцию для хвоста. Список на каждом шаге короче, поэтому рекурсия завершается.

Такой код понятен, но неэкономен: `values[1:]` создаёт новый список на каждом вызове. Для длинного списка это лишняя память. Цикл по элементам делает то же самое без копий.

```python
def total_loop(values):
    result = 0
    for value in values:
        result += value
    return result
```

Рекурсия выигрывает на вложенных структурах, где форма данных повторяется. На плоском списке цикл обычно проще и быстрее.

## Дерево вызовов

Если функция вызывает себя дважды, вызовы образуют дерево. Классический пример это числа Фибоначчи.

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

Для `fib(4)` дерево содержит девять вызовов. Ветви `fib(2)` и `fib(1)` повторяются, и одни и те же значения вычисляются заново.

::figure fib-tree | Интерактивное дерево fib(4): нажимайте «Шаг» и смотрите, как вызовы раскрываются, а затем возвращают значения.

Число вызовов растёт экспоненциально. Для `fib(30)` это миллионы операций, хотя достаточно тридцати сложений. Причина в повторном вычислении одинаковых подзадач.

Решения два:

- запоминать уже вычисленные значения в словаре;
- заменить рекурсию циклом, который хранит два последних числа.

```python
def fib_loop(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

Цикл делает `n` шагов и не повторяет работу.

## Глубина и ограничения

Python ограничивает глубину рекурсии. По умолчанию это около тысячи вызовов. При превышении возникает `RecursionError`.

```python
def countdown(n):
    if n == 0:
        return
    countdown(n - 1)

countdown(2000)
```

```text
RecursionError: maximum recursion depth exceeded
```

Ограничение защищает стек от переполнения. Увеличивать его без необходимости не стоит: глубокая рекурсия занимает память и хуже отлаживается.

Для задач с глубиной больше тысячи используют цикл, стек вручную или обход в ширину. Рекурсия удобна, когда глубина заведомо небольшая: дерево каталогов, разбор выражения, обход небольшого графа.

## Где рекурсия ломается

**Нет базы.** Функция вызывает себя бесконечно и падает с `RecursionError`. Проверка: назовите вход, на котором вызова не будет.

**База не достигается.** `factorial(n - 2)` при чётном `n` перескочит через единицу и уйдёт в отрицательные числа. Шаг должен гарантированно вести к базе.

**База слишком широкая.** Если `if n <= 1` заменить на `if n < 0`, единица вызовет ноль, ноль вызовет минус один, и остановки не будет.

**Повторные вычисления.** Наивный `fib` пересчитывает одни и те же значения. Проверка: посчитайте число вызовов для `n = 20`.

**Изменение общего состояния.** Рекурсивная функция, которая дописывает в глобальный список, зависит от порядка вызовов. Передавайте состояние параметром или возвращайте результат.

**Слишком глубокая структура.** Вложенность в тысячи уровней упрётся в лимит. Исправление: итеративный обход.

> [!PITFALL] Рекурсия не обязана быть короче цикла. Если задача линейная, цикл обычно понятнее, быстрее и не упирается в глубину.

## Итоги

- Рекурсивная функция вызывает себя с более простой задачей.
- База завершает вызовы, шаг приближает к базе.
- Стек хранит незавершённые вызовы; его глубина ограничена.
- Ветвящаяся рекурсия может повторять вычисления и работать экспоненциально долго.
- На плоских данных цикл проще, на вложенных структурах рекурсия естественнее.

::quiz
Q: Что такое базовый случай?
+ Условие, при котором функция возвращает результат без нового вызова
- Первый вызов функции
- Самый глубокий вызов
- Ошибка в рекурсии
! База останавливает цепочку вызовов.

Q: Что должен делать шаг рекурсии?
+ Приближать задачу к базовому случаю
- Увеличивать глубину
- Повторять тот же вызов
- Печатать результат
! Иначе рекурсия не завершится.

Q: Что произойдёт без базового случая?
+ `RecursionError`
- Функция вернёт `None`
- Функция выполнится один раз
- Python исправит код сам
! Стек переполнится.

Q: Что хранит стек вызовов?
+ Незавершённые вызовы функций
- Только результаты
- Только параметры
- Исходный код
! Каждый вызов ждёт завершения следующего.

Q: Чему равен `factorial(1)`?
+ `1`
- `0`
- `2`
- Ошибка
! Это базовый случай факториала.

Q: Почему наивный `fib(n)` работает медленно?
+ Он повторно вычисляет одинаковые подзадачи
- Он использует цикл
- Он хранит слишком много значений
- Он не имеет базы
! Дерево вызовов растёт экспоненциально.

Q: Что такое глубина рекурсии?
+ Число незавершённых вызовов
- Число параметров
- Длина списка
- Число возвратов
! Глубина ограничена размером стека.

Q: Какая ошибка возникает при слишком глубокой рекурсии?
+ `RecursionError`
- `ValueError`
- `KeyError`
- `SyntaxError`
! Python ограничивает глубину стека.

Q: Когда рекурсия удобнее цикла?
+ При обходе вложенной структуры
- При сумме плоского списка
- При выводе чисел от 1 до 10
- При чтении файла построчно
! Вложенность повторяется на каждом уровне.

Q: Какие утверждения о рекурсии верны?
+ Нужен базовый случай
+ Шаг уменьшает задачу
+ Каждый вызов занимает место в стеке
+ Глубина ограничена
- Рекурсия всегда быстрее цикла
- База может быть любой
! База и шаг обязательны, глубина ограничена.

Q: Какие способы ускорить `fib` существуют?
+ Запоминать вычисленные значения
+ Заменить рекурсию циклом
+ Хранить два последних числа
- Увеличить глубину рекурсии
- Убрать базовый случай
! Повторные вычисления устраняют кэшем или циклом.

Q: Какие структуры естественно обходятся рекурсией?
+ Дерево каталогов
+ Вложенные списки
+ Дерево выражений
- Плоский массив чисел
- Строка фиксированной длины
! Рекурсия повторяет форму вложенности.

Q: Что вернёт `factorial(3)`?
= 6
= шесть
! 3 * 2 * 1 = 6.

Q: Какая функция вызывает саму себя?
= рекурсивная
= рекурсия
! Рекурсивная функция содержит вызов себя.

Q: Сколько вызовов сделает `fib(3)` вместе с базовыми?
= 5
