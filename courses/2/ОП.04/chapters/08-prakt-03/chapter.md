## Что требуется

Написать программу `loops.py`, которая выполняет пять частей работы. Каждая часть это короткий цикл с накоплением. Программа должна корректно работать не только на обычных данных, но и на границах: ноль итераций, одна итерация, все отрицательные числа, пустой ввод.

Части работы:

1. Сумма чисел от 1 до `n`.
2. Произведение чисел от 1 до `m`.
3. Счётчики положительных и чётных чисел в последовательности.
4. Максимум в потоке чисел без функции `max`.
5. Сумма и среднее с защитой от пустого ввода.

Результаты и код переносятся в `report_template.docx`, отчёт сохраняется как `report.docx`.

## Ход работы

### Шаг 1. Запустите заготовку

Откройте `starter.py` в VS Code, откройте терминал и выполните:

```bash
python starter.py
```

Заготовка проводит по пяти частям и просит данные. Пока в файле остались `TODO`, накопители не обновляются. Это ожидаемо.

### Шаг 2. Сумма чисел от 1 до n

Программа принимает `n` и считает сумму чисел от 1 до `n` включительно. Используйте `for` и `range`.

Проверьте на трёх значениях:

| `n` | Ожидаемая сумма |
|---:|---:|
| 10 | 55 |
| 1 | 1 |
| 0 | 0 |

Для `n = 0` цикл не выполнится ни разу, и останется начальное значение. Это и есть проверка границы.

Запишите в отчёт трассировочную таблицу для `n = 5`: столбцы `i`, `s` до тела, `s` после тела.

### Шаг 3. Произведение чисел от 1 до m

Программа принимает `m` и считает произведение чисел от 1 до `m`. Это факториал числа `m`.

Начальное значение произведения равно `1`, а не `0`. Если начать с нуля, любое умножение даст ноль.

| `m` | Ожидаемое произведение |
|---:|---:|
| 5 | 120 |
| 1 | 1 |
| 4 | 24 |

Отдельно ответьте в отчёте: что означает `m = 0` и почему произведение в этом случае равно `1`. Это пустое произведение, и оно принято равным единице, чтобы формулы оставались согласованными.

### Шаг 4. Счётчики

Программа читает числа до слова `стоп` и считает, сколько из них положительные и сколько чётные. Ноль не является положительным, но является чётным.

Для последовательности `4, -2, 7, 0, 9, -5` ожидается:

```text
Положительных: 3
Чётных: 3
```

Счётчики увеличиваются на единицу внутри условия. Не складывайте сами числа: счётчик отвечает на вопрос «сколько», а не «чему равна сумма».

Проверьте отдельно последовательность `0, 0, 0`: положительных `0`, чётных `3`.

### Шаг 5. Максимум в потоке

Программа читает числа до слова `стоп` и находит максимум, не используя `max`. Начальное значение берите из первого числа, а не из нуля.

Порядок действий:

1. Прочитать первое число и записать его в `maximum`.
2. Для каждого следующего числа сравнить его с `maximum`.
3. Если число больше, заменить `maximum`.

Проверьте на наборах:

| Последовательность | Ожидаемый максимум |
|---|---|
| 12, 7, 25, 42, 18 | 42 |
| -5, -2, -9 | -2 |
| 3 | 3 |
| стоп | сообщение «данных нет» |

Набор из отрицательных чисел важен: максимум, начатый с нуля, дал бы неверный ответ `0`.

### Шаг 6. Пустой ввод и среднее

Программа читает числа до слова `стоп`, считает сумму и среднее. Если чисел не было, среднее не вычисляется, потому что деление на ноль даст ошибку.

Проверьте:

| Последовательность | Ожидаемый результат |
|---|---|
| 10, 20, 30 | сумма 60, среднее 20.00 |
| 5 | сумма 5, среднее 5.00 |
| стоп | сообщение, что данных нет |

Среднее печатайте с двумя знаками после точки. Деление выполняйте только внутри ветви, где количество больше нуля.

### Шаг 7. Соберите таблицу проверок

Заполните таблицу по каждой части. В ней должны быть и обычные, и граничные наборы.

| Часть | Набор | Ожидалось | Получено |
|---|---|---|---|
| Сумма | n = 10 | 55 |  |
| Сумма | n = 0 | 0 |  |
| Произведение | m = 5 | 120 |  |
| Счётчики | 4, -2, 7, 0, 9, -5 | 3 и 3 |  |
| Максимум | -5, -2, -9 | -2 |  |
| Среднее | стоп | сообщение |  |

Добавьте строки для остальных проверок из `data.md`.

### Шаг 8. Соберите отчёт

Откройте `report_template.docx` и заполните разделы:

1. Тема и цель работы.
2. Код программы.
3. Результаты пяти частей.
4. Таблица проверок.
5. Вывод: почему сумма и произведение начинаются с разных значений.

Вставьте скриншот терминала с запуском части 4 на отрицательных числах. Сохраните отчёт как `report.docx`.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Программа не запускается или выполнено меньше половины частей |
| 3 | Основные части решены, но границы не проверены или начальные значения неверны |
| 4 | Все части решены, проверки выполнены, отчёт заполнен, есть мелкие недочёты |
| 5 | Все части решены, границы проверены, трассировка верна, выводы обоснованы |

## Что сдаётся

- `loops.py` с программой.
- `report.docx` с кодом, трассировкой и таблицей проверок.

> [!PITFALL] Ответ `0` для суммы и ответ `1` для произведения при пустом наборе это не ошибка. Ошибка начинается там, где пустой набор молча даёт среднее или максимум.
