## Что требуется

Написать программу `shop_model.py` с тремя классами:

1. `Product` хранит название, цену и количество, считает стоимость позиции.
2. `Order` хранит номер и список позиций, считает итог.
3. `Warehouse` хранит остатки и выдаёт товар.

Программа создаёт объекты, выполняет операции и печатает состояние. Результаты переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Запустите заготовку

```bash
python starter.py
```

Заготовка создаёт объекты и печатает пустые результаты. Пока в файле `TODO`, методы возвращают нули.

### Шаг 2. Класс Product

Поля: `name`, `price`, `quantity`. Метод `total()` возвращает `price * quantity`.

```python
cup = Product("Кружка", 640, 3)
print(cup.total())
```

```text
1920
```

Добавьте `__str__`, чтобы печать показывала название и стоимость. Проверьте на трёх товарах из `data.md`.

### Шаг 3. Класс Order

Поля: `number`, `items` (список). Методы:

- `add(product)` добавляет позицию;
- `total()` суммирует стоимости позиций;
- `count()` возвращает число позиций.

```python
order = Order(1)
order.add(Product("Кружка", 640, 2))
order.add(Product("Блюдце", 420, 1))
print(order.total())
```

```text
1700
```

Список позиций создавайте в `__init__`, а не в теле класса. Иначе все заказы будут делить один список.

### Шаг 4. Класс Warehouse

Поля: `stock` (словарь название → количество). Методы:

- `receive(name, quantity)` увеличивает остаток;
- `issue(name, quantity)` уменьшает остаток, если товара хватает;
- `report()` печатает остатки.

`issue` возвращает `True` при успехе и `False`, если товара недостаточно. Остаток при отказе не меняется.

Проверьте: принять 10 кружек, выдать 4, затем попробовать выдать 20. После отказа остаток остаётся 6.

### Шаг 5. Свяжите классы

Соберите сценарий:

1. создать три товара;
2. добавить два из них в заказ;
3. посчитать итог;
4. принять товары на склад;
5. выдать часть и проверить остаток.

Напечатайте состояние после каждого шага. Это показывает, что модель меняется предсказуемо.

### Шаг 6. Проверьте инварианты

Инвариант это условие, которое всегда истинно.

- количество товара не отрицательно;
- итог заказа равен сумме позиций;
- остаток склада не отрицателен;
- число позиций совпадает с длиной списка.

Добавьте проверки в конце программы. Если условие нарушено, выведите сообщение.

### Шаг 7. Проверьте границы

| Что проверить | Ожидание |
|---|---|
| количество 0 | стоимость 0 |
| пустой заказ | итог 0, позиций 0 |
| выдача больше остатка | отказ, остаток не меняется |
| товар без остатка | `issue` возвращает `False` |
| повторное добавление товара | две отдельные позиции |

### Шаг 8. Соберите отчёт

Заполните разделы:

1. Тема и цель.
2. Код.
3. Результаты пяти шагов.
4. Таблица проверок.
5. Вывод: почему состояние хранится в объектах, а не в отдельных списках.

Вставьте скриншот запуска.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Программа не запускается или выполнено меньше половины частей |
| 3 | Классы созданы, но состояние или проверки работают неверно |
| 4 | Все части решены, проверки выполнены, отчёт заполнен, есть мелкие недочёты |
| 5 | Все части решены, инварианты и границы проверены, модель объяснена |
