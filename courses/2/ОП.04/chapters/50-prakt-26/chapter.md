## Что требуется

Собрать мини-проект `sales_report` из нескольких файлов. Проект читает `data/sales.csv`, считает показатели и печатает отчёт.

Структура:

```text
sales_report/
  main.py
  app/
    __init__.py
    readers.py
    metrics.py
    report.py
  data/
    sales.csv
  tests/
    test_metrics.py
```

Результаты и код переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Скопируйте проект

Скопируйте папку `prakt-26` целиком. Запуск выполняется из корня проекта:

```bash
python main.py
```

Пока в модулях `TODO`, отчёт будет пустым.

### Шаг 2. Чтение выгрузки

`readers.py` читает CSV с разделителем «точка с запятой» и возвращает список словарей с полями `date`, `region`, `amount`.

Сумму преобразуйте в `float`, дату оставьте строкой. Проверьте, что число записей равно 5.

### Шаг 3. Показатели

`metrics.py` содержит три функции:

- `total(records)` сумму;
- `by_region(records)` словарь регион → сумма;
- `average(records)` среднее.

Для выгрузки ожидается: сумма 5100, среднее 1020, по регионам север 2700, юг 1700, запад 700.

### Шаг 4. Отчёт

`report.py` собирает строки отчёта. Формат денег `:.2f`, регионы выводятся по алфавиту.

```text
Всего: 5100.00
Записей: 5
Средняя: 1020.00
запад: 700.00
север: 2700.00
юг: 1700.00
```

### Шаг 5. Точка входа

`main.py` импортирует функции и связывает их:

```python
from app.readers import load_sales
from app.metrics import total, by_region, average
from app.report import build_report
```

Никаких расчётов в `main.py` быть не должно: он только вызывает функции и печатает результат.

### Шаг 6. Тесты

`tests/test_metrics.py` проверяет `metrics.py` на маленьком наборе, без чтения файла. Запуск:

```bash
python -m unittest discover tests
```

Тесты должны проходить после реализации `metrics.py`.

### Шаг 7. Проверьте границы

| Что проверить | Ожидание |
|---|---|
| пустой файл | 0 записей, сумма 0 |
| одна запись | среднее равно сумме |
| неизвестный регион | попадает в словарь |
| отрицательная сумма | учитывается |
| отсутствующий файл | понятное сообщение |

### Шаг 8. Соберите отчёт

Заполните разделы: цель, структура проекта, код модулей, результаты, тесты, вывод о разделении ответственности. Вставьте скриншоты запуска и тестов.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Проект не запускается или модули не связаны |
| 3 | Расчёт работает, но отчёт или тесты оформлены неверно |
| 4 | Все части решены, тесты проходят, отчёт заполнен |
| 5 | Все части и границы выполнены, структура и ответственность модулей объяснены |

## Что сдаётся

- Папка `sales_report` с модулями и данными.
- `report.docx` со структурой, результатами и тестами.
- Скриншоты запуска и тестов.

> [!PITFALL] Если `main.py` содержит расчёты, тесты не смогут проверить их отдельно. Логика живёт в модулях, точка входа только связывает вызовы.
