## Оценка, которая получилась не той

В журнале хранятся баллы за работу. Правило простое: от 90 баллов выставляется «Отлично», от 75 «Хорошо», от 60 «Зачтено», ниже «Не зачтено». Программист пишет:

```python
score = 82
if score >= 60:
    mark = "Зачтено"
elif score >= 75:
    mark = "Хорошо"
elif score >= 90:
    mark = "Отлично"
else:
    mark = "Не зачтено"
print(mark)
```

Программа выводит `Зачтено`, хотя при 82 баллах ожидалось «Хорошо». Ошибка не в сравнениях: каждое из них записано верно. Ошибка в порядке. Первое условие `score >= 60` истинно, поэтому остальные ветви даже не проверяются. До строки с 75 баллами управление не доходит.

Это главная мысль занятия: **ветвление это не набор независимых проверок, а последовательность решений, где порядок определяет результат**. Чтобы исправить программу, достаточно поставить самое строгое условие первым.

```python
if score >= 90:
    mark = "Отлично"
elif score >= 75:
    mark = "Хорошо"
elif score >= 60:
    mark = "Зачтено"
else:
    mark = "Не зачтено"
```

Теперь при 82 баллах первое условие ложно, второе истинно, и программа выдаёт «Хорошо». При 95 баллах срабатывает первое условие, остальные пропускаются.

## Условие и его значение

Условие это выражение, у которого есть одно из двух значений: `True` или `False`. Такие значения имеют тип `bool`. Условие получается из сравнения:

| Оператор | Смысл | Пример | Результат |
|---|---|---|---|
| `==` | равно | `7 == 7` | `True` |
| `!=` | не равно | `7 != 7` | `False` |
| `>` | больше | `7 > 3` | `True` |
| `<` | меньше | `7 < 3` | `False` |
| `>=` | больше или равно | `7 >= 7` | `True` |
| `<=` | меньше или равно | `7 <= 3` | `False` |

Сравнение не изменяет значения. Оно только отвечает на вопрос. Поэтому `7 > 3` можно сохранить в переменную:

```python
adult = age >= 18
print(adult)
```

Если `age` равно `20`, переменная `adult` получит `True`. Это обычное значение типа `bool`, с ним можно работать дальше.

Отдельно стоит запомнить разницу между `=` и `==`. Один знак равенства присваивает значение имени, два знака сравнивают. В условии нужно сравнение. Запись `if x = 5:` завершится синтаксической ошибкой, потому что присваивание не является условием.

Сравнивать можно не только числа. Строки сравниваются посимвольно по кодам символов:

```python
print("apple" == "apple")
print("apple" < "banana")
print("Apple" == "apple")
```

```text
True
True
False
```

Первые две строки дают ожидаемый результат. Третья показывает ловушку: заглавная и строчная буквы имеют разные коды, поэтому `"Apple"` и `"apple"` это разные строки. Если регистр не важен, строки приводят к одному виду через `lower()`.

## Ветвление if, elif, else

Ветвление записывают тремя конструкциями.

**Полное ветвление** выбирает один из двух путей:

```python
if temperature > 30:
    print("Жарко")
else:
    print("Не жарко")
```

**Неполное ветвление** выполняет действие только при истинном условии, а при ложном ничего не делает:

```python
if balance < 0:
    print("Баланс отрицательный")
```

**Лестница** проверяет несколько вариантов по очереди:

```python
if score >= 90:
    mark = "Отлично"
elif score >= 75:
    mark = "Хорошо"
elif score >= 60:
    mark = "Зачтено"
else:
    mark = "Не зачтено"
```

В лестнице выполняется ровно одна ветвь. Как только условие оказалось истинным, остальные проверки пропускаются. Если ни одно условие не истинно, срабатывает `else`. Поэтому `else` в лестнице необязателен, но полезен: он делает поведение полным и показывает, что предусмотрен случай «ни один вариант не подошёл».

Отступы в Python являются частью синтаксиса. Строки внутри ветви сдвинуты на четыре пробела. Если отступ потерян, программа либо завершится ошибкой `IndentationError`, либо ветвь окажется пустой и её смысл изменится.

::figure condition-flow | Лестница условий читается сверху вниз: первое истинное условие выбирает ветвь, остальные проверки пропускаются.

На схеме видно, почему порядок важен. Проверки идут от самого строгого условия к самому мягкому. Если поменять местами верхний и нижний ромб, нижняя ветвь перехватит все значения, которые должны были попасть выше.

## Логические связки

Одно условие часто недостаточно. Скидка даётся, если сумма больше 5000 **и** покупатель в клубе. Условие соединяют логическими операторами.

| Оператор | Истинно, когда | Пример |
|---|---|---|
| `and` | истинны оба условия | `total > 5000 and member` |
| `or` | истинно хотя бы одно | `day == "сб" or day == "вс"` |
| `not` | переворачивает значение | `not member` |

```python
total = 6400
member = True
discount = total > 5000 and member
print(discount)
```

```text
True
```

Если `member` равно `False`, результат будет `False`, потому что `and` требует истинности обоих операндов.

Оператор `or` удобен для проверки вхождения в набор:

```python
day = "сб"
weekend = day == "сб" or day == "вс"
print(weekend)
```

```text
True
```

Для длинных наборов есть более короткая запись через `in`:

```python
weekend = day in ("сб", "вс")
```

`not` применяют, когда удобнее проверить отсутствие условия:

```python
if not member:
    print("Скидка не положена")
```

Логические операторы вычисляются по приоритету: сначала `not`, затем `and`, затем `or`. Скобки меняют порядок и делают намерение явным. Сравните два условия:

```python
a = True
b = False
c = False
print(a or b and c)
print((a or b) and c)
```

```text
True
False
```

В первом выражении сначала вычисляется `b and c`, затем результат соединяется с `a` через `or`. Во втором скобки заставляют сначала вычислить `a or b`. Оба выражения синтаксически верны, но означают разное. Если логика сложнее двух условий, ставьте скобки.

Python вычисляет логические операторы лениво: второй операнд проверяется только тогда, когда от него зависит результат. В `a and b` при ложном `a` значение `b` не вычисляется. Это полезно, но может скрыть ошибку, если второй операнд должен был выполняться.

## Вложенные условия

Иногда решение зависит от двух признаков сразу, и удобнее проверить их по очереди. Вложенное условие это условие внутри ветви другого условия.

```python
age = 20
has_ticket = True

if age >= 18:
    if has_ticket:
        print("Проход разрешён")
    else:
        print("Нужен билет")
else:
    print("Вход только с 18 лет")
```

Вложенную конструкцию можно записать одной строкой через `and`, но не всегда. Вариант с `and` проверяет оба условия сразу и не различает, какое именно не выполнено. Вложенный вариант позволяет выдать точное сообщение. Выбор зависит от того, нужна ли пользователю причина отказа.

Глубокая вложенность усложняет чтение. Практическое правило: если внутри ветви появляется третье условие подряд, подумайте о лестнице `elif` или о вынесении проверки в отдельную функцию.

## Где условия ломаются

**Неверный порядок в лестнице.** Самое общее условие стоит первым и перехватывает все значения. Проверка: пройдите лестницу для каждого диапазона и убедитесь, что срабатывает нужная ветвь.

**Присваивание вместо сравнения.** `if x = 5:` не является условием. Исправление: `if x == 5:`.

**Сравнение строк без учёта регистра.** `"Да" == "да"` даёт `False`. Исправление: приводить обе строки к одному регистру.

**Забытая ветвь.** Лестница без `else` молча ничего не делает, если ни одно условие не истинно. Проверка: назовите, что должно произойти в этом случае.

**Условие, которое всегда истинно.** `if x >= 0 or x < 0:` покрывает все числа, но выглядит как проверка. Проверка: подставьте несколько значений и посмотрите, бывает ли результат `False`.

**Смешение `and` и `or` без скобок.** Выражение читается не так, как кажется. Исправление: расставить скобки и проверить таблицу истинности.

> [!PITFALL] `elif` не проверяется, если предыдущее условие уже истинно. Это не ошибка языка, а правило работы лестницы. Именно поэтому диапазоны перечисляют от строгого к мягкому.

## Итоги

- Условие это выражение со значением `True` или `False`, собранное из сравнений.
- `if` выбирает путь, `else` задаёт альтернативу, `elif` добавляет варианты.
- В лестнице выполняется ровно одна ветвь, поэтому порядок проверок определяет результат.
- `and`, `or` и `not` соединяют условия; скобки делают порядок вычисления явным.
- Вложенные условия дают точные сообщения, но ухудшают читаемость при большой глубине.
