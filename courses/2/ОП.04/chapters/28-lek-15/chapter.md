## Один список, разные товары

В каталоге лежат книги и ручки. У книги есть автор, у ручки цвет. Обе позиции имеют название и цену. Нужно напечатать описание каждой позиции.

Без общей модели появляются два независимых класса и две функции:

```python
def describe_book(book):
    return f"Книга «{book.name}», автор {book.author}"

def describe_pen(pen):
    return f"Ручка «{pen.name}», цвет {pen.color}"
```

Список смешанный, поэтому приходится проверять тип:

```python
for item in items:
    if isinstance(item, Book):
        print(describe_book(item))
    else:
        print(describe_pen(item))
```

Каждый новый тип товара требует новой ветви. Через месяц появляется блокнот, и код снова правится.

Наследование убирает ветвление. Общий родитель объявляет метод `describe`, наследники переопределяют его, а цикл вызывает один и тот же метод у всех:

```python
for item in items:
    print(item.describe())
```

Главная мысль занятия: **наследование выносит общее в родителя, а полиморфизм позволяет вызывать общий метод, не зная точного класса**. Код цикла не меняется при добавлении нового наследника.

## Базовый класс

Родитель описывает общие поля и методы.

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def describe(self):
        return f"Товар «{self.name}», {self.price:.2f}"
```

Метод `describe` задаёт поведение по умолчанию. Наследник может его использовать или заменить.

```python
class Book(Product):
    def __init__(self, name, price, author):
        super().__init__(name, price)
        self.author = author

    def describe(self):
        return f"Книга «{self.name}», автор {self.author}, {self.price:.2f}"
```

Запись `class Book(Product)` означает «Book наследует Product». `super().__init__(name, price)` вызывает конструктор родителя, чтобы заполнить общие поля. Затем наследник добавляет своё поле `author`.

`describe` переопределён: у книги свой текст. Поля `name` и `price` не дублируются, они приходят из родителя.

```python
class Pen(Product):
    def __init__(self, name, price, color):
        super().__init__(name, price)
        self.color = color

    def describe(self):
        return f"Ручка «{self.name}», цвет {self.color}, {self.price:.2f}"
```

::figure class-tree | Общий родитель хранит имя и цену, наследники добавляют автора и цвет и переопределяют describe.

## Переопределение и super

Переопределение это замена метода родителя своим. Если наследнику нужно дополнить поведение, он вызывает родительский метод через `super()`.

```python
class DiscountedBook(Book):
    def describe(self):
        return super().describe() + " (со скидкой)"
```

`super().describe()` выполняет версию родителя, затем наследник добавляет свой текст.

Переопределять можно не только методы, но и атрибуты. Однако поля лучше задавать в конструкторе, иначе легко получить рассинхронизацию.

Наследование не копирует код. Наследник получает доступ к методам родителя, но сами методы остаются в родителе. Если исправить метод в родителе, изменение увидят все наследники. Это главное преимущество перед копированием.

## Полиморфизм

Полиморфизм это возможность вызвать один и тот же метод у разных объектов и получить разное поведение.

```python
items = [
    Book("Алгоритмы", 1200, "Кормен"),
    Pen("Ручка", 150, "синий"),
    Book("Python", 900, "Лутц"),
]

for item in items:
    print(item.describe())
```

```text
Книга «Алгоритмы», автор Кормен, 1200.00
Ручка «Ручка», цвет синий, 150.00
Книга «Python», автор Лутц, 900.00
```

Цикл не знает, что перед ним книга или ручка. Он вызывает `describe`, а Python выбирает реализацию по классу объекта. Это называют динамическим связыванием.

::figure polymorph-lab | Интерактивный список: вызывайте describe() у объектов по одному или сразу у всех. Ответ зависит от класса.

Полиморфизм позволяет писать код, который работает с новыми типами без изменений. Достаточно, чтобы новый класс имел нужный метод.

## Проверка типов

`isinstance` проверяет, является ли объект экземпляром класса или его наследника.

```python
print(isinstance(Book("Алгоритмы", 1200, "Кормен"), Product))
print(type(book) is Book)
```

```text
True
True
```

`isinstance` учитывает наследование, `type(...) is ...` требует точного совпадения. Для проверки «подходит ли объект» обычно используют `isinstance`.

Но злоупотреблять проверками не стоит. Если код снова и снова спрашивает тип, чтобы выбрать действие, значит, полиморфизм не использован.

```python
for item in items:
    if isinstance(item, Book):
        print(item.author)
    elif isinstance(item, Pen):
        print(item.color)
```

Такой код придётся править при каждом новом классе. Лучше добавить метод в классы.

## Утиная типизация

Python не требует формального наследования, чтобы вызвать метод. Достаточно, чтобы у объекта был нужный метод.

```python
class Pencil:
    def __init__(self, name, price, hardness):
        self.name = name
        self.price = price
        self.hardness = hardness

    def describe(self):
        return f"Карандаш «{self.name}», твёрдость {self.hardness}"
```

`Pencil` не наследует `Product`, но у него есть `describe`, поэтому он подходит туда, где ожидается метод `describe`.

Такая гибкость удобна, но требует дисциплины. Если классы должны быть взаимозаменяемы, общий родитель документирует контракт.

## Где наследование ломается

**Забытый `super().__init__`.** Общие поля не создаются, и обращение к ним даёт `AttributeError`. Исправление: вызвать конструктор родителя первой строкой.

**Наследование ради переиспользования одного метода.** Если классу нужна одна функция, проще вынести её отдельно. Иерархия должна выражать отношение «является».

**Неверная иерархия.** `Квадрат` наследует `Прямоугольник` по математике, но изменение ширины ломает квадрат. Проверяйте, что наследник действительно может заменить родителя.

**Переопределение с другим смыслом.** Метод `area` у наследника возвращает периметр. Формально код работает, но контракт нарушен.

**Слишком глубокая иерархия.** Пять уровней наследования трудно проследить. Часто хватает двух.

**Дублирование вместо выноса.** Если два наследника содержат одинаковый код, его место в родителе.

> [!PITFALL] Наследование не делает код короче автоматически. Если между классами нет отношения «является», лучше использовать композицию: объект хранит другой объект как поле.

## Итоги

- Наследник получает поля и методы родителя и может переопределить поведение.
- `super()` вызывает реализацию родителя.
- Полиморфизм выбирает метод по классу объекта во время выполнения.
- `isinstance` учитывает наследование, но злоупотреблять проверками не стоит.
- Наследование оправдано отношением «является», иначе используют композицию.

::quiz
Q: Что получает наследник от родителя?
+ Поля и методы
- Только поля
- Только методы
- Ничего
! Наследник использует общее поведение родителя.

Q: Как объявить наследование?
+ `class Book(Product):`
- `class Book from Product:`
- `class Book extends Product:`
- `class Book: Product`
! Родитель указывается в скобках.

Q: Что делает `super().__init__(...)`?
+ Вызывает конструктор родителя
- Создаёт новый класс
- Удаляет родителя
- Печатает объект
! Так заполняются общие поля.

Q: Что такое переопределение?
+ Замена метода родителя своим в наследнике
- Создание второго объекта
- Удаление метода
- Импорт модуля
! Наследник задаёт своё поведение.

Q: Что такое полиморфизм?
+ Один вызов метода даёт разное поведение у разных классов
- Наследование всех полей
- Копирование кода
- Проверка типов
! Реализация выбирается по классу объекта.

Q: Что проверяет `isinstance(obj, Product)`?
+ Является ли объект экземпляром класса или его наследника
- Совпадает ли тип точно
- Есть ли у объекта поле `price`
- Можно ли объект напечатать
! Наследники тоже подходят.

Q: Чем `type(obj) is Book` отличается от `isinstance(obj, Book)`?
+ Требует точного класса, без наследников
- Учитывает наследников
- Работает только со строками
- Проверяет поля
! `isinstance` мягче.

Q: Почему злоупотребление `isinstance` плохо?
+ Код приходится править при каждом новом классе
- Проверка работает медленно
- Она запрещена в Python
- Она удаляет методы
! Полиморфизм должен убрать ветвление по типам.

Q: Что такое утиная типизация?
+ Достаточно наличия нужного метода, формальное наследование не требуется
- Наследование только от одного класса
- Проверка всех типов
- Запрет на методы
! Python смотрит на поведение, а не на родословную.

Q: Какие утверждения о наследовании верны?
+ Наследник может переопределить метод
+ `super()` вызывает родительскую версию
+ Исправление в родителе видят все наследники
+ Наследование выражает отношение «является»
- Наследование всегда короче композиции
- Наследник обязан переопределить все методы
! Наследование не универсальная замена композиции.

Q: Какие ошибки типичны при наследовании?
+ Забытый `super().__init__`
+ Неверная иерархия
+ Переопределение с другим смыслом
- Использование `self`
- Вызов метода у объекта
! Первые три ломают контракт.

Q: Какие классы подходят для общего родителя?
+ Книга и ручка как товары
+ Круг и прямоугольник как фигуры
+ Файл и папка как элементы
- Книга и автомобиль
- Круг и число
! Родитель объединяет общее поведение.

Q: Что вернёт `Book(...).describe()` при переопределённом методе?
= описание книги
= текст книги
! Вызывается реализация наследника.

Q: Какой метод вызывает родительскую реализацию?
= super
= super()
! `super()` даёт доступ к методам родителя.

Q: Сколько реализаций `describe` будет выбрано для списка из книги и ручки?
= 2
= две
! По одной на каждый класс.
