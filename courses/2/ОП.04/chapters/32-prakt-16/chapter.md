## Что требуется

Дан модуль `bugs.py` с четырьмя функциями и набор тестов `test_bugs.py`. Часть тестов падает. Нужно:

1. запустить набор;
2. прочитать отчёт;
3. найти причину каждого падения;
4. исправить функции в `bugs.py`;
5. прогнать все тесты и убедиться, что набор зелёный.

Тесты менять нельзя: они описывают ожидаемое поведение.

## Ход работы

### Шаг 1. Запустите тесты

```bash
python -m unittest test_bugs.py
```

В отчёте будет несколько падений. Одно из них может быть не `FAIL`, а `ERROR`: это значит, что функция завершилась исключением, а не вернула неверное значение.

### Шаг 2. Разберите первое падение

В отчёте найдите:

- имя теста;
- входные данные;
- ожидаемое значение;
- фактическое значение или тип исключения.

Сформулируйте причину одной фразой: «функция не проверяет пустой список», «условие чётности перевёрнуто».

### Шаг 3. Сузьте поиск

Если причина не очевидна, вызовите функцию вручную:

```python
from bugs import average
print(average([]))
```

Печать промежуточных значений допустима, но после исправления её нужно убрать.

### Шаг 4. Исправьте функцию

Правьте `bugs.py`, а не тест. Если тест кажется неверным, сначала объясните, почему ожидание в нём ошибочно. В этой работе все тесты корректны.

После каждого исправления запускайте только один тест, чтобы видеть результат:

```bash
python -m unittest test_bugs.TestAverage.test_empty
```

### Шаг 5. Проверьте остальные падения

Функции независимы, но исправление одной может изменить поведение другой, если они вызывают друг друга. В этом наборе зависимости простые, но привычка прогонять всё остаётся.

### Шаг 6. Прогоните весь набор

```bash
python -m unittest test_bugs.py
```

Ожидается `OK` и число пройденных тестов. Если осталось падение, вернитесь к шагу 2.

### Шаг 7. Заполните таблицу дефектов

Для каждого падения запишите:

| Функция | Вход | Ожидалось | Было | Причина | Исправление |
|---|---|---|---|---|---|
| average | [] | 0.0 | ZeroDivisionError | нет проверки пустого списка | вернуть 0.0 |
| is_even |  |  |  |  |  |
| clamp |  |  |  |  |  |
| find_index |  |  |  |  |  |

### Шаг 8. Соберите отчёт

Заполните разделы: цель, код до и после, таблица дефектов, результат прогона, вывод о разнице между `FAIL` и `ERROR`. Вставьте скриншот зелёного набора.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Исправлено меньше половины дефектов |
| 3 | Дефекты исправлены, но причины описаны неточно |
| 4 | Все дефекты исправлены, таблица заполнена, набор зелёный |
| 5 | Все дефекты исправлены, причины и разница FAIL и ERROR объяснены |

## Что сдаётся

- `bugs.py` с исправлениями.
- `report.docx` с таблицей дефектов и скриншотом.
- Скриншот зелёного прогона.

> [!PITFALL] Если изменить ожидание в тесте под фактический результат, дефект не исчезнет, а станет невидимым. Сначала докажите, что неверна функция.
