## Что требуется

Написать набор тестов для модуля `pricing.py`. В модуле три функции:

- `discount(total, percent)` считает сумму со скидкой;
- `delivery(total, zone)` считает доставку;
- `order_total(price, quantity, percent)` считает итог заказа.

Тесты размещаются в `test_pricing.py`. Запуск:

```bash
python -m unittest test_pricing.py
```

Результаты и разбор падений переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Прочитайте модуль

Откройте `pricing.py`. Функции уже реализованы, менять их не нужно. Прочитайте правила:

- скидка не может быть меньше 0 и больше 100 процентов;
- при скидке 100 итог равен нулю;
- доставка в город стоит 300, от 3000 бесплатно;
- доставка в область стоит 500;
- самовывоз бесплатный.

### Шаг 2. Запустите пустой набор

```bash
python -m unittest test_pricing.py
```

Пока тесты не заполнены, набор проходит. Это нормально: тест без утверждения ничего не проверяет.

### Шаг 3. Обычные значения

Для `discount(1000, 10)` ожидается `900`. Для `order_total(640, 3, 10)` ожидается `1728`. Напишите тесты с `assertEqual`.

Имена тестов должны описывать поведение: `test_discount_ten_percent`, а не `test1`.

### Шаг 4. Границы

Проверьте:

- скидку 0;
- скидку 100;
- скидку больше 100;
- сумму 0;
- сумму ровно 3000;
- сумму 2999.

Для дробных результатов используйте `assertAlmostEqual`, иначе `0.1 + 0.2` даст ложное падение.

### Шаг 5. Исключения

Для недопустимой зоны или отрицательной цены модуль поднимает `ValueError`. Проверьте это через `assertRaises`:

```python
with self.assertRaises(ValueError):
    delivery(1000, "луна")
```

Тест на исключение тоже является тестом поведения.

### Шаг 6. Запустите и разберите падения

Если тест падает, в отчёте укажите:

1. имя теста;
2. входные данные;
3. ожидаемое значение;
4. фактическое значение;
5. причину расхождения.

Не меняйте ожидание под фактический результат, пока не убедились, что ошибочен тест, а не функция.

### Шаг 7. Проверьте покрытие

Убедитесь, что каждая функция проверена хотя бы одним обычным и одним граничным тестом. Отметьте в таблице, какие ветви покрыты.

### Шаг 8. Соберите отчёт

Заполните разделы: цель, код модуля и тестов, таблица тестов, разбор падений, вывод о границах. Вставьте скриншот запуска.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Тесты не запускаются или проверяют меньше половины функций |
| 3 | Основные тесты есть, но границы или исключения не покрыты |
| 4 | Все функции покрыты, падения разобраны, отчёт заполнен |
| 5 | Все функции и границы покрыты, разбор падений точный, выводы обоснованы |

> [!PITFALL] Тест, который всегда зелёный, бесполезен. Если в тесте нет `assert` или метода `assert...`, он ничего не проверяет.
