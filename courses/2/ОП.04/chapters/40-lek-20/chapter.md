## Лестница и медленная рекурсия

На лестнице шесть ступеней. За один шаг можно подняться на одну или две ступени. Сколько существует способов добраться до верха?

Наивная рекурсия перебирает варианты:

```python
def ways(n):
    if n <= 1:
        return 1
    return ways(n - 1) + ways(n - 2)
```

Для `n = 6` функция работает быстро. Для `n = 35` она делает миллионы вызовов, потому что `ways(30)` вычисляется заново десятки раз.

Динамическое программирование заменяет повторные вычисления таблицей:

```python
def ways(n):
    dp = [0] * (n + 1)
    dp[0] = 1
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(ways(6))
```

```text
13
```

Каждое значение считается один раз. Для `n = 35` цикл делает 35 шагов вместо миллионов.

Главная мысль занятия: **если задача повторяет одни и те же подзадачи, их результаты сохраняют и переиспользуют**. Таблица превращает экспоненциальный перебор в линейный проход.

## Подзадачи и состояние

Динамическое программирование опирается на три вопроса.

**Что является подзадачей?** Для лестницы это «сколько способов подняться на `i` ступеней». Подзадача меньше исходной и похожа на неё.

**Что хранит состояние?** Одно число `dp[i]` это ответ для `i` ступеней. Состояние должно полностью описывать подзадачу: если для ответа нужны ещё какие-то данные, их добавляют в состояние.

**Как перейти от меньших подзадач к большей?** На последнем шаге мы пришли с `i - 1` или с `i - 2`. Значит, `dp[i] = dp[i - 1] + dp[i - 2]`.

К этому добавляются базовые случаи: `dp[0] = 1` и `dp[1] = 1`. Без них переход не с чего начать.

## Порядок заполнения

Таблицу заполняют так, чтобы к моменту вычисления `dp[i]` нужные значения уже были готовы. Обычно это слева направо, от меньших индексов к большим.

```python
dp = [0] * 7
dp[0] = 1
dp[1] = 1
for i in range(2, 7):
    dp[i] = dp[i - 1] + dp[i - 2]
print(dp)
```

```text
[1, 1, 2, 3, 5, 8, 13]
```

Порядок нарушать нельзя. Если начать с `i = 6` и идти вниз, `dp[5]` и `dp[4]` ещё неизвестны.

Для задач на таблице, например пути по сетке, порядок задаётся вложенными циклами: сначала строки, затем столбцы. Главное правило одно: к моменту вычисления все зависимости уже посчитаны.

## Память и восстановление

Для лестницы хранить весь массив не обязательно: нужны только два предыдущих значения.

```python
def ways_fast(n):
    a, b = 1, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

Это тот же переход, но память постоянная. Такой вариант называют оптимизацией памяти. Он удобен, когда нужен только ответ, а не вся таблица.

Если нужно восстановить сам маршрут, таблицу сохраняют. Для лестницы можно идти с конца: если `dp[i - 1]` и `dp[i - 2]` дают вместе `dp[i]`, выбирают шаг, который оставляет решение возможным.

```python
def build_path(n):
    dp = [0] * (n + 1)
    dp[0] = 1
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    path = []
    i = n
    while i > 0:
        if i >= 2 and dp[i] == dp[i - 1] + dp[i - 2]:
            path.append(2)
            i -= 2
        else:
            path.append(1)
            i -= 1
    return path[::-1]
```

Маршрут не единственный. Функция возвращает один из возможных, и это нормально.

## Когда применимо

Динамическое программирование работает, когда выполняются два условия.

**Оптимальная подструктура.** Ответ для большой задачи складывается из ответов для подзадач. Для лестницы это сумма двух вариантов.

**Перекрывающиеся подзадачи.** Одни и те же подзадачи встречаются многократно. Именно поэтому кэш или таблица дают выигрыш.

Если подзадачи не повторяются, таблица только добавляет память. Если задачу нельзя разбить на независимые части, динамика не подходит.

Типичные задачи:

- число способов подняться по лестнице;
- минимальная стоимость пути по сетке;
- размен монет;
- наибольшая общая подпоследовательность;
- рюкзак с ограничением веса.

## Где динамика ломается

**Неверная база.** `dp[0] = 0` вместо `1` обнулит все ответы. База должна соответствовать смыслу задачи.

**Неверный переход.** Сумма вместо минимума или пропущенный вариант дают правдоподобный, но неверный ответ. Проверка: выпишите переход словами.

**Неверный порядок.** Обращение к ещё не заполненной ячейке даёт ноль или мусор. Проверка: нарисуйте стрелки зависимостей.

**Забытая инициализация.** Массив создан, но базовые значения не заданы. Исправление: заполнить базу до цикла.

**Лишняя память.** Хранится вся таблица, хотя нужен только ответ. Исправление: два последних значения.

**Неверное восстановление.** Путь строится по значению, которое не участвовало в переходе. Проверка: сумма выбранных шагов должна давать ответ.

> [!PITFALL] Динамическое программирование не ускоряет любую задачу. Оно ускоряет только задачи с повторяющимися подзадачами.

## Итоги

- Динамика разбивает задачу на подзадачи и сохраняет их ответы.
- Состояние, база и переход описывают решение полностью.
- Таблицу заполняют в порядке, при котором зависимости уже готовы.
- Для одного ответа достаточно двух последних значений.
- Метод применим при оптимальной подструктуре и перекрывающихся подзадачах.
