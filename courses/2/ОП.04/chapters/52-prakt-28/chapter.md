## Что требуется

Завершить итоговый проект и подготовить его защиту. Проект это программа на Python, которая читает данные, обрабатывает их и формирует отчёт.

Требования к проекту:

1. не меньше двух модулей и точки входа;
2. чтение данных из файла;
3. обработка и расчёт показателей;
4. отчёт или выгрузка;
5. набор тестов;
6. README с описанием запуска;
7. отчёт о работе.

Защита занимает 5-7 минут: демонстрация, тесты, объяснение кода и ответы на вопросы.

## Ход работы

### Шаг 1. Выберите тему

Тема должна быть связана с учебными задачами дисциплины:

- каталог товаров с ценами и остатками;
- журнал событий с уровнями и фильтрами;
- расписание задач и загрузка;
- обработка списка измерений;
- склад и движение товаров;
- частотный анализ текста.

Тема согласуется с преподавателем. Одна тема на одного студента или на группу из двух человек, если объём больше.

### Шаг 2. Зафиксируйте требования

Запишите в README:

- какие данные принимает программа;
- какие команды поддерживает;
- какие файлы создаёт;
- какие ошибки обрабатывает.

Требования не должны быть слишком широкими. Лучше три команды, которые работают, чем десять, которые не запускаются.

### Шаг 3. Соберите проект

Минимальная структура:

```text
project/
  main.py
  app/
    __init__.py
    readers.py
    metrics.py
    report.py
  data/
    input.csv
  tests/
    test_metrics.py
  README.md
```

Расчёты находятся в модулях, точка входа только связывает вызовы. Это позволяет тестировать логику без чтения файла.

### Шаг 4. Подготовьте демонстрацию

Сценарий на 5 минут:

1. показать структуру проекта;
2. запустить программу на подготовленных данных;
3. показать обычный сценарий и одну ошибку ввода;
4. показать отчёт;
5. запустить тесты;
6. объяснить одно сложное решение.

Демонстрация идёт на заранее подготовленных данных. Не нужно вводить длинные значения вручную.

### Шаг 5. Подготовьте тесты

Тесты должны покрывать:

- обычный расчёт;
- пустой ввод;
- граничное значение;
- неверный формат.

Команда запуска указывается в README:

```bash
python -m unittest discover tests
```

На защите показывается зелёный прогон и одно объяснение: что именно проверяет каждый тест.

### Шаг 6. Подготовьте ответы

Разберите вопросы из `defense_questions.md`. Ответ должен опираться на код, а не на общие слова.

Пример: на вопрос «почему расчёт вынесен в модуль» ответ звучит так: «чтобы тестировать `metrics.py` без чтения файла и чтобы `main.py` не содержал логики».

### Шаг 7. Соберите отчёт

Заполните `report_template.docx`:

1. тема и цель;
2. требования;
3. структура проекта;
4. демонстрация;
5. тесты;
6. трудности и решения;
7. вывод.

Вставьте скриншоты запуска и тестов.

### Шаг 8. Проверьте перед защитой

| Что проверить | Ожидание |
|---|---|
| проект запускается на чистой папке | да |
| данные лежат рядом | да |
| тесты проходят | да |
| README описывает запуск | да |
| демонстрация укладывается в 5 минут | да |
| ответы на вопросы подготовлены | да |

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Проект чужой или не объясняется |
| 2 | Программа не запускается или не выполнены требования |
| 3 | Программа работает, но тесты, отчёт или объяснение неполные |
| 4 | Все требования выполнены, демонстрация и ответы уверенные |
| 5 | Проект цельный, тесты и отчёт полные, решения обоснованы |

## Что сдаётся

- Папка проекта с кодом, данными, тестами и README.
- `report.docx` с описанием и скриншотами.
- Демонстрация на защите.

> [!PITFALL] Защита проверяет понимание, а не объём кода. Большой проект, который студент не может объяснить, оценивается ниже небольшого и понятного.
