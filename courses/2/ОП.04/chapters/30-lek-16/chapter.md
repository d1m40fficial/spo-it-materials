## Скидка, которая ушла в минус

Функция считает стоимость со скидкой:

```python
def discount(total, percent):
    return total - total * percent / 100
```

Проверка на обычных данных проходит: `discount(1000, 10)` возвращает `900`. Проверка на нуле тоже: `discount(500, 0)` возвращает `500`.

Затем кто-то вводит скидку 150 процентов, и функция возвращает `-50`. Отрицательная стоимость ломает отчёт, но ошибка обнаруживается через неделю.

Тест поймал бы это сразу:

```python
assert discount(100, 150) == 0
```

Утверждение падает, потому что фактическое значение `-50` не равно ожидаемому `0`. Разработчик видит проблему до того, как код попадёт в работу.

Главная мысль занятия: **тест это исполняемое ожидание**. Он не доказывает отсутствие ошибок, но фиксирует поведение, которое нельзя случайно сломать.

## Утверждение

Простейший тест это `assert`.

```python
def test_discount():
    assert discount(1000, 10) == 900
    assert discount(500, 0) == 500
    assert discount(100, 150) == 0
```

Если условие истинно, ничего не происходит. Если ложно, возникает `AssertionError`. Это удобно для быстрых проверок в учебном коде.

`assert` не заменяет обработку ошибок. При запуске с флагом `-O` интерпретатор удаляет утверждения, поэтому проверять ими пользовательский ввод нельзя. Для тестов это нормально, для рабочей логики нет.

## unittest

Стандартная библиотека содержит модуль `unittest`. Тесты оформляют как методы класса.

```python
import unittest
from pricing import discount

class TestDiscount(unittest.TestCase):
    def test_usual(self):
        self.assertEqual(discount(1000, 10), 900)

    def test_zero_percent(self):
        self.assertEqual(discount(500, 0), 500)

    def test_over_hundred(self):
        self.assertEqual(discount(100, 150), 0)
```

Запуск:

```bash
python -m unittest test_pricing.py
```

Отчёт показывает число тестов, время и список падений. Если все прошли, выводится `OK`. Если нет, для каждого падения печатается имя теста, ожидаемое и фактическое значения.

Методы проверки:

| Метод | Что проверяет |
|---|---|
| `assertEqual(a, b)` | равенство |
| `assertNotEqual(a, b)` | неравенство |
| `assertTrue(x)` | истинность |
| `assertFalse(x)` | ложность |
| `assertIn(a, b)` | вхождение |
| `assertAlmostEqual(a, b)` | близость дробных чисел |
| `assertRaises(Error)` | что возникло исключение |

Для дробных чисел используют `assertAlmostEqual`, потому что `0.1 + 0.2` не равно `0.3` точно.

## Структура теста

Хороший тест состоит из трёх частей:

1. подготовка данных;
2. вызов проверяемого действия;
3. утверждение о результате.

```python
def test_total_with_quantity(self):
    product = Product("Кружка", 640, 3)
    result = product.total()
    self.assertEqual(result, 1920)
```

Имя теста описывает поведение, а не метод: `test_total_with_quantity` лучше, чем `test1`. По имени должно быть понятно, что сломалось, когда тест упал.

Один тест проверяет одну мысль. Если в методе пять независимых утверждений, при падении трудно понять, какое из них виновато. Разделяйте на несколько тестов.

## Граничные значения

Ошибки живут на границах. Для функции скидки важны:

- скидка 0;
- скидка 100;
- скидка больше 100;
- сумма 0;
- отрицательная сумма;
- очень большая сумма.

Граничные значения делят вход на классы. Если внутри класса поведение одинаково, достаточно проверить по одному представителю и сами границы.

| Класс | Пример | Ожидание |
|---|---|---|
| обычная скидка | 10 | сумма уменьшается |
| нет скидки | 0 | сумма не меняется |
| полная скидка | 100 | ноль |
| недопустимая | 150 | ноль или ошибка |
| пустая сумма | 0 | ноль |

Тест на `150` и обнаружил дефект. Без него функция выглядела правильной.

## Регрессия

Регрессия это ошибка, которая появилась после изменения кода. Тест, написанный после исправления, не даёт вернуть дефект.

Порядок работы:

1. воспроизвести ошибку тестом;
2. убедиться, что тест падает;
3. исправить код;
4. убедиться, что тест проходит;
5. прогнать все тесты, а не только новый.

Пятый шаг важен: исправление в одном месте может сломать другое.

Этот цикл называют «красный, зелёный, рефакторинг». Красный означает падающий тест, зелёный проходящий, рефакторинг улучшает код без изменения поведения.

## Качество кода

Тесты помогают, но качество начинается с самого кода.

**Имена.** `total`, `discount`, `apply_discount` говорят о смысле. `a`, `b`, `tmp2` заставляют читателя догадываться.

**Размер функции.** Функция на двадцать строк с пятью ветвями трудна для теста. Разделите её на короткие шаги.

**Один уровень абстракции.** Функция не должна одновременно читать файл, считать скидку и печатать отчёт.

**Отсутствие дублирования.** Одинаковая формула в трёх местах разъедется после первого исправления. Вынесите её в функцию.

**Документация.** Короткая строка документации объясняет назначение и единицы измерения. Комментарий внутри объясняет неочевидное решение, а не пересказывает код.

**Обработка ошибок.** Понятное сообщение полезнее трассировки. Но не прячьте ошибку молча.

## Где тесты ломаются

**Тест без утверждения.** Он выполняется и всегда зелёный. Проверка: в тесте есть `assert` или метод `assert...`.

**Тест зависит от порядка.** Второй тест рассчитывает на данные, оставленные первым. Каждый тест готовит своё состояние.

**Тест проверяет реализацию.** Он смотрит на внутреннюю переменную вместо результата. После рефакторинга такой тест падает без причины. Проверяйте поведение.

**Нет границ.** Проверены только обычные значения. Дефект на нуле или на пределе остаётся.

**Случайные данные без seed.** Тест то падает, то проходит. Зафиксируйте данные.

**Медленные тесты.** Модульный тест должен работать за миллисекунды. Работа с сетью и большими файлами выносится в интеграционные.

> [!PITFALL] Зелёный тест не означает, что программа правильная. Он означает только, что проверенные случаи ведут себя как ожидалось.

## Итоги

- Тест фиксирует ожидаемое поведение и ловит регрессии.
- `assert` подходит для быстрых проверок, `unittest` даёт отчёт и набор методов.
- Тест состоит из подготовки, действия и утверждения.
- Границы и недопустимые значения находят больше ошибок, чем обычные данные.
- Качество кода складывается из имён, размера функций и отсутствия дублирования.

::quiz
Q: Что такое тест?
+ Исполняемое ожидание поведения
- Комментарий в коде
- Функция без параметров
- Отчёт о работе программы
! Тест проверяет результат автоматически.

Q: Что делает `assert`?
+ Проверяет условие и падает при ложности
- Печатает значение
- Завершает программу всегда
- Создаёт функцию
! При ложном условии возникает `AssertionError`.

Q: Что проверяет `assertEqual(a, b)`?
+ Равенство значений
- Что `a` больше `b`
- Что `a` существует
- Тип значения
! Это основная проверка `unittest`.

Q: Зачем нужны граничные значения?
+ На границах чаще возникают ошибки
- Они быстрее выполняются
- Они заменяют все тесты
- Они нужны только для строк
! Ноль, предел и недопустимые значения выявляют дефекты.

Q: Что такое регрессия?
+ Ошибка, появившаяся после изменения кода
- Первый запуск теста
- Ошибка синтаксиса
- Медленный тест
! Тест не даёт вернуть старый дефект.

Q: Из каких частей состоит тест?
+ Подготовка, действие, утверждение
- Ввод, вывод, печать
- Класс, объект, метод
- Файл, строка, список
! Это структура Arrange, Act, Assert.

Q: Почему тест не должен зависеть от порядка?
+ Каждый тест должен работать отдельно
- Так быстрее
- Иначе не запустится Python
- Порядок задаёт `unittest`
! Независимость делает падения понятными.

Q: Что означает зелёный тест?
+ Проверенные случаи ведут себя как ожидалось
- Программа без ошибок
- Код готов к публикации
- Все ветви покрыты
! Тест подтверждает только свои проверки.

Q: Что делать после падения теста?
+ Найти причину, исправить код и прогнать все тесты
- Удалить тест
- Закомментировать `assert`
- Изменить ожидание под результат
! Иначе дефект останется.

Q: Какие проверки относятся к `unittest`?
+ `assertEqual`
+ `assertTrue`
+ `assertRaises`
+ `assertAlmostEqual`
- `assertPrint`
- `assertImport`
! Остальные не существуют.

Q: Какие значения стоит проверить для функции скидки?
+ 0 процентов
+ 100 процентов
+ Больше 100 процентов
+ Нулевая сумма
- Только 10 процентов
- Только положительную сумму
! Границы и недопустимые значения важнее обычного примера.

Q: Какие свойства хорошего теста?
+ Одно поведение на тест
+ Понятное имя
+ Независимость от других тестов
+ Быстрый запуск
- Проверка внутренних переменных
- Случайные данные без фиксации
! Тест проверяет поведение и работает изолированно.

! `assert` поднимает `AssertionError`.

Q: Какой модуль стандартной библиотеки используют для тестов?

= модуль unittest
! `unittest` входит в стандартную библиотеку.
