## «У меня не воспроизводится»

Пользователь пишет, что заявка не сохраняется. Разработчик открывает систему, создаёт заявку, всё работает. Через час выясняется: ошибка возникает, когда тема содержит кавычку, а пользователь работает в другом браузере.

**Дефект** это расхождение между ожидаемым и фактическим поведением. Пока дефект не воспроизведён, причина остаётся догадкой.

Главная мысль занятия: **отладка это проверка гипотез, а не перебор строк**. Каждый шаг должен сужать область поиска.

## Воспроизведение

Сначала фиксируют условия:

- версия и окружение;
- данные пользователя;
- последовательность действий;
- время и идентификатор запроса.

Если дефект не воспроизводится, условие ещё не найдено. «Иногда» означает, что не хватает фактора: данные, роль, нагрузка, браузер.

## Факты

Источники фактов:

- журнал приложения;
- журнал веб-сервера;
- трассировка стека;
- состояние базы;
- сетевой запрос в браузере.

::figure debug-flow | Порядок отладки: воспроизвести, собрать факты, выдвинуть гипотезу, проверить, исправить. Если гипотеза не подтвердилась, возврат к фактам.

Журнал должен содержать время, уровень, сообщение и идентификатор запроса. Без идентификатора события разных пользователей смешиваются.

## Гипотеза и проверка

**Гипотеза** это проверяемое предположение: «ошибка возникает при пустом поле», «запрос падает на кавычке», «дефект появился после коммита с новой проверкой».

Проверка должна дать однозначный ответ. Если гипотеза не подтвердилась, её отбрасывают и возвращаются к фактам.

## Bisect

**git bisect** находит коммит, после которого поведение изменилось. Он делит историю пополам и отмечает хорошие и плохие версии.

```bash
git bisect start
git bisect bad
git bisect good v1.2
```

Для небольших проектов достаточно просмотреть последние коммиты, но при длинной истории bisect экономит время.

## Исправление

Исправление включает:

1. минимальную правку причины;
2. тест, который падал до правки;
3. проверку соседних сценариев;
4. запись в changelog, если дефект был в выпуске.

Если правка лечит симптом, дефект вернётся.

## Оформление дефекта

Дефект содержит:

- заголовок с условием;
- шаги воспроизведения;
- ожидаемый результат;
- фактический результат;
- окружение;
- важность.

Пример:

> При теме с кавычкой заявка не сохраняется. Ожидается сохранение или понятная ошибка. Фактически ответ 500, данные потеряны.

## Где отладка ломается

**Правка наугад.** Меняют код, пока не заработает, причину не понимают.

**Нет воспроизведения.** Дефект закрывают как «не подтвердился».

**Один журнал на всех.** Нельзя найти события конкретного запроса.

**Исправление без теста.** Ошибка возвращается при следующем изменении.

**Симптом вместо причины.** Обходят ошибку, источник остаётся.

**Долгий поиск без гипотез.** Перебирают всё подряд.

> [!PITFALL] Успешный запуск после правки не доказывает, что причина устранена. Нужен тест, который воспроизводил дефект до изменения.

## Итоги

- Дефект начинают с воспроизведения и условий.
- Журналы и трассировка дают факты.
- Гипотеза проверяется однозначно.
- Bisect сужает историю до коммита.
- Исправление закрепляют тестом и оформляют дефект.

Q: Что такое дефект?
+ Расхождение ожидаемого и фактического поведения
- Любая ошибка в тексте
- Новая функция
- Отсутствие теста
! Поведение.

Q: С чего начинают отладку?
+ С воспроизведения условий
- С переписывания кода
- С удаления журналов
- С выпуска версии
! Воспроизведение.

Q: Что даёт идентификатор запроса?
+ Связывает события одного запроса
- Ускоряет базу
- Шифрует трафик
- Меняет версию
! Поиск в журнале.

Q: Что такое гипотеза?
+ Проверяемое предположение о причине
- Любая догадка
- Готовое исправление
- Тест-кейс
! Проверяемое.

Q: Что делает git bisect?
+ Находит коммит, после которого поведение изменилось
- Удаляет историю
- Создаёт ветку
- Сливает изменения
! Поиск коммита.

Q: Что должно входить в исправление?
+ Правка причины и тест
- Только правка
- Только тест
- Только отчёт
! Причина и проверка.

Q: Что содержит оформленный дефект?
+ Шаги, ожидание, факт, окружение
- Только заголовок
- Только имя автора
- Только код
! Полное описание.

Q: Почему правка наугад опасна?
+ Причина остаётся неизвестной
- Код становится короче
- Тесты ускоряются
- Ветка удлиняется
! Нет понимания.

Q: Что означает «не воспроизводится»?
+ Не найдены условия возникновения
- Дефекта не существует
- Пользователь ошибся
- Тесты не нужны
! Условия не найдены.

Q: Какие источники фактов используют?
+ Журнал приложения
+ Трассировка стека
+ Состояние базы
+ Сетевой запрос
- Цвет интерфейса
- Название проекта
! Остальное не факты.
