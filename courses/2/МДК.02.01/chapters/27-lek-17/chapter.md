## «У меня собирается»

Разработчик передаёт проект архивом. На другом компьютере не хватает библиотеки, версия Python другая, а файл базы лежит в личной папке. Сборка существует только на машине автора.

**Релиз** это версия продукта, которую можно передать и установить по инструкции. Он включает артефакт, номер версии и список изменений.

Главная мысль занятия: **релиз должен собираться повторяемо**. Если результат зависит от настроек автора, это не релиз.

## Воспроизводимая сборка

Сборка воспроизводима, когда:

- зависимости зафиксированы;
- команда сборки записана;
- артефакт получается из чистого репозитория;
- результат не зависит от локальных файлов.

Для Python фиксируют версии в `requirements.txt`, для .NET используют файл проекта и `dotnet publish`.

## Конвейер

::figure release-pipeline | Конвейер релиза: коммит, тесты, сборка, версия, changelog и установка. Внизу правила semver.

Этапы:

1. проверить коммит;
2. прогнать тесты;
3. собрать артефакт;
4. присвоить версию;
5. заполнить changelog;
6. установить на чистую среду.

Автоматизация не обязательна на первом шаге. Важна повторяемость команд.

## Semver

**Semver** задаёт три числа: `MAJOR.MINOR.PATCH`.

| Часть | Когда меняется |
|---|---|
| MAJOR | несовместимое изменение |
| MINOR | новая возможность без поломки |
| PATCH | исправление |

Пример: `1.4.2` значит четвёртая minor-версия, второе исправление.

Номер версии сообщает пользователю, чего ждать. Молча сломать совместимость и оставить `1.4.3` нельзя.

## Changelog

Changelog пишут по категориям:

- добавлено;
- изменено;
- исправлено;
- удалено;
- безопасность.

Каждая запись отвечает на вопрос пользователя: что изменится для меня.

Плохо: «Рефакторинг модуля».
Хорошо: «Заявку можно закрыть с комментарием».

## Артефакт

**Артефакт** это файл, который передают для установки: архив, пакет, исполняемый файл, образ.

Артефакт содержит:

- собранный код;
- файлы конфигурации без секретов;
- инструкцию;
- номер версии.

В артефакт не попадают личные данные, журналы и временные файлы.

## Проверка установки

Установку проверяют на чистой среде:

1. взять артефакт;
2. выполнить инструкцию;
3. запустить продукт;
4. пройти главный сценарий;
5. убедиться, что версия отображается.

Если для установки нужны файлы с рабочего стола автора, релиз не готов.

## Где релиз ломается

**Сборка на машине автора.** Зависимости не зафиксированы.

**Версия на глаз.** Номер не отражает изменения.

**Changelog из коммитов.** Пользователь не понимает записей.

**Секреты в артефакте.** Пароль базы попадает в архив.

**Нет проверки установки.** Ошибка находится у пользователя.

**Артефакт без инструкции.** Непонятно, что делать дальше.

> [!PITFALL] Релиз без проверки на чистой среде проверяет только машину разработчика, а не продукт.

## Итоги

- Релиз собирается повторяемо из чистого репозитория.
- Semver связывает номер версии с типом изменения.
- Changelog пишут для пользователя, а не из коммитов.
- Артефакт содержит всё нужное и не содержит секретов.
- Установку проверяют на чистой среде.

::quiz
Q: Что такое релиз?
+ Передаваемая версия продукта с артефактом и изменениями
- Любой коммит
- Папка на рабочем столе
- Ветка Git
! Готовая версия.

Q: Что значит воспроизводимая сборка?
+ Получается по инструкции из чистого репозитория
- Собирается только автором
- Не требует зависимостей
- Всегда занимает минуту
! Повторяемость.

Q: Что задаёт semver?
+ Три числа версии и правила их изменения
- Имя проекта
- Список файлов
- Пароль базы
! Версии.

Q: Когда меняется MAJOR?
+ При несовместимом изменении
- При исправлении
- При новой возможности
- При смене автора
! Совместимость.

Q: Когда меняется PATCH?
+ При исправлении
- При новой возможности
- При несовместимом изменении
- При смене лицензии
! Исправление.

Q: Что содержит changelog?
+ Изменения, важные пользователю
- Все коммиты
- Исходный код
- Пароли
! История для читателя.

Q: Что входит в артефакт?
+ Собранный код и инструкция
- Личные файлы автора
- Журналы разработки
- Пароли
! Готовый продукт.

Q: Где проверяют установку?
+ На чистой среде
- На машине автора
- В личной папке
- В редакторе
! Чистая среда.

Q: Почему «рефакторинг модуля» плохая запись?
+ Не говорит, что изменится для пользователя
- Слишком длинная
- Написана по-русски
- Содержит термин
! Нет пользы читателю.

Q: Какие категории есть в changelog?
+ Добавлено
+ Изменено
+ Исправлено
+ Удалено
- Пароли
- Сотрудники
! Остальное лишнее.

Q: Какие ошибки релиза типичны?
+ Сборка на машине автора
+ Версия на глаз
+ Секреты в артефакте
+ Нет проверки установки
- Фиксированные зависимости
- Проверка на чистой среде
! Остальное хорошо.

Q: Что проверяют при установке?
+ Запуск продукта
+ Главный сценарий
+ Отображение версии
+ Отсутствие секретов
- Цвет иконки
- Имя автора
! Остальное не проверки.

Q: Как называют файл, который передают для установки?
= артефакт
= artifact
! Готовый продукт.

Q: Какая часть версии отвечает за совместимость?
= MAJOR
= major
! Несовместимое изменение.

Q: Что перечисляет изменения версии?
= changelog
= журнал изменений
! История для пользователя.
