## Две задачи одновременно

Один разработчик правит форму заявки, другой меняет проверку прав. Оба работают в основной ветке: изменения смешиваются, половина коммитов ломает чужую работу.

**Ветка** это отдельная линия истории. Она позволяет вести задачу изолированно и вернуться к основной версии, когда работа готова.

Главная мысль занятия: **ветка изолирует работу, а слияние возвращает её обратно**. Чем меньше ветка живёт, тем проще слияние.

## Ветки в Git

```bash
git switch -c feature/request-form
git status
```

`switch -c` создаёт ветку и переключается на неё. Коммиты в ветке не меняют основную.

Основные команды:

| Команда | Что делает |
|---|---|
| `git branch` | показывает ветки |
| `git switch имя` | переключает ветку |
| `git switch -c имя` | создаёт и переключает |
| `git merge имя` | сливает ветку в текущую |
| `git rebase основа` | переносит коммиты на новую основу |

## Merge

**merge** создаёт коммит слияния с двумя родителями. История сохраняет обе линии.

::figure branch-merge | Переключайте merge и rebase: видно, как меняется история. При merge появляется общий коммит, при rebase коммиты переносятся на новую основу.

Merge удобен, когда ветка уже опубликована и её историю нельзя менять.

## Rebase

**rebase** переносит коммиты ветки на новую основу. История становится линейной.

После rebase хеши коммитов меняются. Поэтому общую ветку не переписывают: у других участников останутся старые коммиты.

## Конфликт

**Конфликт** возникает, когда две ветки изменили одну и ту же строку.

Git оставляет маркеры:

```text
<<<<<<< HEAD
status = "new"
=======
status = "open"
>>>>>>> feature/statuses
```

Порядок:

1. прочитать оба варианта;
2. выбрать правильный или соединить;
3. удалить маркеры;
4. запустить тесты;
5. завершить слияние коммитом.

Нельзя просто удалить чужую строку, не поняв, зачем она была.

## Стратегии ветвления

**Feature branch.** Каждая задача в отдельной ветке, затем пул-реквест. Подходит большинству команд.

**Trunk based.** Короткие ветки на день-два, частое слияние в основную. Меньше конфликтов, выше дисциплина.

**Release branch.** Ветка под выпуск, исправления идут отдельно. Нужна при поддержке нескольких версий.

Правило общее: **чем дольше ветка живёт, тем дороже слияние**.

## Пул-реквест

**Пул-реквест** это предложение слить ветку. В нём есть описание, изменения и проверки.

Хороший пул-реквест:

- небольшой;
- решает одну задачу;
- содержит тесты;
- описывает, что и зачем изменено.

## Где ветки ломаются

**Долгая ветка.** Пока она живёт, основная ушла далеко.

**Слияние без тестов.** Конфликт разрешён, но поведение сломано.

**Rebase опубликованной ветки.** История расходится у участников.

**Огромный пул-реквест.** Его никто не читает внимательно.

**Ветка на всё.** В одной ветке смешаны три задачи.

> [!PITFALL] Разрешение конфликта не означает, что код правильный. Тесты после слияния обязательны.

## Итоги

- Ветка изолирует задачу от основной версии.
- Merge сохраняет историю, rebase делает её линейной.
- Rebase опасен для опубликованных веток.
- Конфликт разрешают по смыслу, а не удалением чужих строк.
- Короткие ветки и небольшие пул-реквесты упрощают слияние.

- Новую ветку
- Удаление истории
- Тег версии
! Точка слияния.

Q: Что делает rebase?
+ Переносит коммиты на новую основу
- Создаёт коммит слияния
- Удаляет ветку
- Копирует файлы
! Линейная история.

Q: Что меняется после rebase?
+ Хеши коммитов
- Имена файлов
- Автор проекта
- Адрес сервера
! Новая история.

Q: Когда возникает конфликт?
+ Две ветки изменили одну строку
- Ветка создана давно
- Коммитов больше десяти
- Автор один
! Пересечение изменений.

Q: Что делать после разрешения конфликта?
+ Запустить тесты и завершить слияние
- Удалить ветку
- Сделать rebase
- Отправить без проверки
! Проверка поведения.

Q: Какая стратегия использует короткие ветки?
+ Trunk based
- Долгая feature branch
- Ветка на год
- Без веток
! Частое слияние.

Q: Почему опасен rebase опубликованной ветки?
+ История расходится у участников
- Коммиты удаляются навсегда
- Ветка становится длиннее
- Тесты перестают работать
! Общая история.
