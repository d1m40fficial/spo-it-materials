## final_v2_final

В папке проекта лежат файлы `отчёт.docx`, `отчёт_новый.docx`, `отчёт_новый_исправленный.docx` и `отчёт_финал.docx`. Непонятно, какой из них последний, что изменилось и можно ли вернуть вчерашнюю версию.

**Система контроля версий** хранит историю изменений и позволяет перейти к любому сохранённому состоянию. **Git** это распределённая система: полная история есть у каждого участника.

Главная мысль занятия: **коммит это снимок законченного изменения с объяснением**. Пока изменение не закоммичено, оно живёт только на диске и легко теряется.

## Снимки, а не разница файлов

Git хранит состояние проекта в коммитах. У коммита есть:

- идентификатор (хеш);
- автор и дата;
- сообщение;
- ссылка на предыдущий коммит.

История это цепочка коммитов. По ней видно, что и когда менялось.

## Три области и сервер

| Область | Что содержит |
|---|---|
| рабочий каталог | файлы на диске |
| индекс | изменения, подготовленные к коммиту |
| локальный репозиторий | история коммитов |
| удалённый репозиторий | копия истории на сервере |

::figure git-areas | Нажимайте команды: подсвечивается путь изменения между рабочим каталогом, индексом, репозиторием и сервером.

Команда `git add` переносит изменение в индекс, `git commit` сохраняет индекс в историю, `git push` отправляет коммиты на сервер, `git pull` забирает чужие изменения.

Индекс нужен, чтобы собрать один осмысленный коммит из нескольких правок и не тащить в него случайные файлы.

## Основные команды

| Команда | Что делает |
|---|---|
| `git init` | создаёт репозиторий в папке |
| `git status` | показывает состояние файлов |
| `git add файл` | готовит файл к коммиту |
| `git commit -m "сообщение"` | сохраняет снимок |
| `git log --oneline` | показывает историю |
| `git diff` | показывает изменения |
| `git remote add origin адрес` | связывает с сервером |
| `git push` | отправляет коммиты |
| `git pull` | забирает изменения |

Сообщение коммита отвечает на вопрос «что изменено», а не «что делал». «Добавить проверку пустой темы заявки» лучше, чем «правки».

## Что не коммитят

В репозиторий не попадают:

- пароли, ключи и токены;
- виртуальные окружения и зависимости;
- собранные файлы и архивы;
- временные файлы редактора;
- базы данных с реальными данными.

Список исключений задаёт `.gitignore`. Если секрет уже попал в историю, недостаточно удалить файл: он останется в старых коммитах, ключ нужно сменить.

## Ветки

**Ветка** это отдельная линия истории. В ней можно делать изменения, не затрагивая основную версию. После проверки ветку сливают с основной.

Ветки позволяют вести параллельные задачи и проверять изменения до попадания в общую версию. Подробно слияние разберём позже.

## Где работа с Git ломается

**Один огромный коммит.** В нём смешаны правки по разным задачам, историю нельзя прочитать.

**Сообщение «fix».** Через месяц непонятно, что исправлено.

**Секрет в репозитории.** Пароль остаётся в истории, даже если файл удалён.

**Коммит чужих файлов.** В репозиторий попадают настройки редактора и собранные архивы.

**Работа без веток.** Все изменения сразу в основной версии, проверить их отдельно нельзя.

> [!PITFALL] Git не заменяет резервную копию. Он хранит историю кода, но сервер может быть недоступен, а база данных в репозиторий не входит.

## Итоги

- Git хранит историю снимков проекта.
- Изменение проходит через рабочий каталог, индекс и репозиторий.
- Коммит делают по законченному изменению с понятным сообщением.
- `.gitignore` исключает лишние и секретные файлы.
- Ветки позволяют вести параллельные изменения.
