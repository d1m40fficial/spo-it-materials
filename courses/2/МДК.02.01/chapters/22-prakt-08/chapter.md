## Что требуется

Подготовить набор проверок для учебной системы «Заявки колледжа» и автоматизировать основные.

Работа состоит из четырёх частей:

1. тест-кейсы для ключевых сценариев;
2. классы эквивалентности и границы;
3. автотесты;
4. прогон и отчёт о покрытии.

Результаты переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Выберите сценарии

Возьмите пять сценариев из требований: создание заявки, просмотр своих заявок, закрытие с правами, закрытие без прав, ошибка ввода.

Для каждого напишите тест-кейс с ожидаемым результатом.

### Шаг 2. Разберите значения

Для поля «тема» и статуса выделите классы эквивалентности и границы. Запишите, какие значения будете проверять и почему.

Не перебирайте все строки: достаточно представителей классов.

### Шаг 3. Напишите автотесты

Дополните `tests_template.py`. Каждый тест должен проверять одно утверждение и иметь понятное имя.

Для проверки ошибок используйте ожидание исключения, а не пустой `except`.

### Шаг 4. Запустите прогон

```bash
python -m pytest -q
```

Запишите число тестов, результат и время. Если тест падает, разберитесь, что именно он проверяет.

### Шаг 5. Проверьте покрытие

Запустите покрытие удобным способом, например:

```bash
python -m pytest --cov=app
```

Запишите, какие ветви не покрыты. Объясните, почему каждая из них осталась без теста.

### Шаг 6. Закрепите дефект

Возьмите известный дефект из практики отладки или придумайте крайний случай. Напишите тест, который падал бы до исправления.

### Шаг 7. Соберите отчёт

Заполните таблицы, вставьте вывод прогона и ответьте на вопросы.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Тесты отсутствуют или не запускаются |
| 3 | Часть тестов написана, границы не проверены |
| 4 | Все части выполнены, отчёт заполнен, есть мелкие недочёты |
| 5 | Тесты проверяют права и границы, падение и покрытие объяснены |

## Что сдаётся

- `test_app.py` с автотестами.
- `report.docx` с тест-кейсами, прогоном и покрытием.

> [!PITFALL] Тест без утверждения проходит всегда. Проверьте, что при поломке кода он действительно падает.
