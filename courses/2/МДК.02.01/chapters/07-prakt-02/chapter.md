## Что требуется

Создать репозиторий для учебного продукта и собрать историю из нескольких осмысленных коммитов.

Работа состоит из четырёх частей:

1. создание репозитория и файла исключений;
2. первые коммиты с документами проекта;
3. проверка истории;
4. объяснение состава коммитов.

Результаты переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Создайте репозиторий

В папке проекта выполните:

```bash
git init
git status
```

Убедитесь, что Git видит файлы и показывает их как неотслеживаемые.

### Шаг 2. Настройте исключения

Создайте `.gitignore` и внесите в него то, что не должно попадать в историю: виртуальное окружение, собранные файлы, временные файлы, локальные настройки.

Не добавляйте в исключения исходный код и документы проекта.

### Шаг 3. Сделайте первый коммит

Добавьте описание продукта и паспорт требований:

```bash
git add brief.md
git commit -m "Добавить описание учебного продукта"
```

Сообщение должно объяснять, что появилось в проекте.

### Шаг 4. Добавьте остальные документы

Сделайте ещё два-три коммита по законченным частям: требования, глоссарий, границы системы. Не смешивайте разные задачи в одном коммите.

Проверяйте состояние перед каждым коммитом:

```bash
git status
```

### Шаг 5. Проверьте историю

```bash
git log --oneline
git diff HEAD~1 HEAD
```

Запишите, какие файлы изменились в последнем коммите и что показала разница.

### Шаг 6. Проверьте чистоту

После коммитов `git status` должен показать, что неотслеживаемых изменений нет. Если остались файлы, объясните, почему они не попали в историю.

### Шаг 7. Соберите отчёт

Заполните таблицу коммитов, вставьте вывод команд и ответьте на вопросы.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Репозиторий не создан или история отсутствует |
| 3 | Коммиты есть, но сообщения не отражают изменения |
| 4 | Все части выполнены, отчёт заполнен, есть мелкие недочёты |
| 5 | История читается, коммиты разделены по задачам, исключения обоснованы |

## Что сдаётся

- `report.docx` с таблицей коммитов и выводом команд.
- Скриншот `git log --oneline` и содержимого `.gitignore`.

> [!PITFALL] Коммит «всё сразу» удобен один раз. Через неделю по такой истории нельзя понять, где появилась ошибка и какое изменение откатывать.
