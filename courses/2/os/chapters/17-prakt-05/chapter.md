## Цель работы

Научиться управлять службой Windows и заданием по расписанию, не полагаясь на графические окна. На стенде `os-lab` в гостевой `win-lab` проверяется служба печати, читаются её зависимости и тип запуска, затем создаётся задание Планировщика, которое запускает сценарий проверки и оставляет запись в журнале.

Результат работы это восстановленная служба печати, задание с понятным триггером и отчёт с фактическим состоянием до и после каждого действия. Отдельно фиксируется исходное состояние, чтобы после работы стенд остался таким, каким был до неё.

## Оборудование и программное обеспечение

- Персональный компьютер с VirtualBox.
- Виртуальная машина `win-lab` с Windows 10 и учётной записью администратора `admin`.
- PowerShell 5.1 или новее, командная строка Windows.
- Права локального администратора внутри гостевой системы.
- Снимок `clean` в VirtualBox, сделанный до начала работы.
- Текстовый редактор для отчёта.

## Краткие теоретические сведения

Служба Windows это программа, которой управляет диспетчер служб. Она запускается до входа пользователя, работает в фоне и не имеет окна. У службы есть имя, отображаемое имя, состояние, тип запуска, учётная запись и список зависимостей.

Состояние `Running` означает, что процесс работает. `Stopped` означает, что процесс не запущен. Тип запуска `Automatic` включает автозагрузку, `Manual` разрешает запуск по требованию, `Disabled` запрещает запуск. Режим `Automatic (Delayed Start)` откладывает старт, чтобы не удлинять загрузку системы.

Зависимости делятся на две группы. `RequiredServices` это службы, без которых данная служба не запустится. `DependentServices` это службы, которые зависят от данной. Остановка службы с зависимыми компонентами затрагивает их тоже, поэтому перед изменением состояния нужно смотреть оба списка.

Учётная запись службы определяет её права. `LocalSystem` имеет широкие права на локальной машине, `LocalService` ограничена, `NetworkService` работает от имени компьютера в сети. Прикладные службы часто запускают от отдельной учётной записи, чтобы ограничить ущерб при ошибке.

Планировщик заданий запускает программу по триггеру: по времени, при входе, при запуске системы или по событию. У задания есть действие, условие и параметры. Результат последнего запуска хранится в свойстве `LastTaskResult`: ноль означает успех, `0x41301` означает, что задание ещё выполняется.

Автозагрузка Windows не сводится к службам. Программа может стартовать из папки автозагрузки пользователя, из ключа реестра `Run` или из задания с триггером «при входе». Поэтому поиск причины автозапуска начинается со списка `Win32_StartupCommand`, а не с одного места.

## Ход работы

### Шаг 1. Проверить стенд и исходное состояние

Запустите `win-lab`, откройте PowerShell от имени администратора. Проверьте машину, учётную запись и версию системы.

```powershell
hostname
whoami
(Get-CimInstance Win32_OperatingSystem).Caption
(Get-CimInstance Win32_OperatingSystem).Version
```

`whoami` печатает имя пользователя в формате `имя-машины\логин`. Если запись не содержит `admin`, вы работаете не в той учётной записи. Версия системы нужна, чтобы отличить Windows 10 от серверной сборки и понимать доступный набор командлетов.

### Шаг 2. Собрать список служб

Посмотрите общее число служб и распределение по состояниям. Командлет `Measure-Object` считает объекты, `Group-Object` группирует их по значению свойства.

```powershell
Get-Service | Measure-Object
Get-Service | Group-Object Status | Select-Object Name,Count
Get-Service | Group-Object StartType | Select-Object Name,Count
```

`Get-Service` без параметров возвращает все службы. `Group-Object Status` делит их на `Running` и `Stopped`. `Group-Object StartType` показывает, сколько служб запускается автоматически, вручную и отключено.

Найдите службы из таблицы. Часть полей заполните сами по выводу PowerShell.

| Служба | Назначение | Состояние | Тип запуска |
|---|---|---|---|
| Spooler | очередь печати |  |  |
| W32Time | синхронизация времени |  |  |
| WinDefend | защита Windows |  |  |
| EventLog | журнал событий |  |  |

```powershell
Get-Service -Name Spooler,W32Time,WinDefend,EventLog |
  Select-Object Name,DisplayName,Status,StartType
```

Если командлет сообщает, что служба не найдена, запишите это как факт: в разных редакциях Windows набор служб отличается. Не выдумывайте состояние.

### Шаг 3. Прочитать зависимости и учётную запись

Свойства `Get-Service` не показывают путь и учётную запись. Их даёт объект `Win32_Service`.

```powershell
Get-CimInstance Win32_Service -Filter "Name='Spooler'" |
  Select-Object Name,State,StartMode,StartName,PathName
Get-Service -Name Spooler -RequiredServices
Get-Service -Name Spooler -DependentServices
```

`StartName` это учётная запись, `PathName` командная строка, `StartMode` тип запуска. `RequiredServices` перечисляет зависимости, `DependentServices` показывает, кто зависит от печати.

Заполните таблицу по фактическому выводу. Первая строка служит образцом.

|---|---|
| Имя службы | Spooler |
| Учётная запись |  |
| Зависит от |  |
| От неё зависят |  |

Объясните в отчёте, что произойдёт с зависимыми службами при остановке `Spooler`. Ответ должен опираться на список, а не на общие слова.

### Шаг 4. Остановить и запустить службу

Зафиксируйте состояние до изменения, остановите службу, проверьте результат, затем запустите снова.

```powershell
Get-Service -Name Spooler | Select-Object Name,Status,StartType
Stop-Service -Name Spooler
Get-Service -Name Spooler | Select-Object Name,Status
Start-Service -Name Spooler
Get-Service -Name Spooler | Select-Object Name,Status
```

`Stop-Service` останавливает процесс, но не меняет тип запуска. Если служба не останавливается, командлет сообщит об ошибке. В этом случае прочитайте сообщение и запишите его в отчёт, а не повторяйте команду с ключом `-Force` без разбора.

Проверьте очередь печати после остановки и после запуска. Откройте параметры принтеров или выполните `Get-PrintJob`, если командлет доступен. Очередь может быть пустой, это нормально: важен не документ, а реакция службы.

### Шаг 5. Изменить тип запуска и вернуть исходный

Переведите службу в ручной запуск, проверьте свойство, затем верните автоматический запуск.

```powershell
Set-Service -Name Spooler -StartupType Manual
Get-Service -Name Spooler | Select-Object Name,Status,StartType
Set-Service -Name Spooler -StartupType Automatic
Get-Service -Name Spooler | Select-Object Name,Status,StartType
```

`Set-Service` меняет только тип запуска. Текущее состояние `Running` при этом сохраняется: служба продолжает работать до остановки или перезагрузки. Это важное различие, которое нужно отразить в отчёте.

Сравните поведение с `systemctl disable` в Linux: там команда тоже убирает автозагрузку, но не останавливает процесс. Запишите одно сходство и одно различие двумя предложениями.

### Шаг 6. Найти программы в автозагрузке

Посмотрите, что запускается вместе с Windows. Командлет `Win32_StartupCommand` собирает записи из папки автозагрузки и ключей реестра.

```powershell
Get-CimInstance Win32_StartupCommand |
  Select-Object Name,Command,Location,User
```

`Location` показывает источник записи. Если в списке есть программы, о которых вы не знаете, не удаляйте их сразу: сначала выясните назначение. В учебной машине список короткий, но привычка проверять источник важнее количества записей.

Дополнительно посмотрите задания с триггером входа.

```powershell
Get-ScheduledTask | Where-Object {
  $_.Triggers.CimClass.CimClassName -contains 'MSFT_TaskLogonTrigger'
} | Select-Object TaskName,State
```

`Get-ScheduledTask` возвращает объекты заданий, `Triggers` содержит триггеры. Фильтр оставляет только задания, которые срабатывают при входе пользователя. Запишите в отчёт не менее двух найденных источников автозагрузки или объясните, почему список пуст.

### Шаг 7. Создать сценарий проверки

Создайте в домашнем каталоге папки `os-lab\bin` и `os-lab\logs`. Сценарий будет проверять состояние службы печати и дописывать строку в журнал.

```powershell
$base = Join-Path $env:USERPROFILE 'os-lab'
New-Item -ItemType Directory -Force -Path (Join-Path $base 'bin'),(Join-Path $base 'logs') | Out-Null
$script = Join-Path $base 'bin\heartbeat.ps1'
@'
$logDir = Join-Path $env:USERPROFILE 'os-lab\logs'
New-Item -ItemType Directory -Force -Path $logDir | Out-Null
$state = (Get-Service -Name Spooler).Status
$line = '{0} Spooler: {1}' -f (Get-Date -Format 'yyyy-MM-dd HH:mm:ss'), $state
Add-Content -Path (Join-Path $logDir 'heartbeat.log') -Value $line -Encoding UTF8
'@ | Set-Content -Path $script -Encoding UTF8
```

Разберите сценарий по строкам. `Join-Path` собирает путь без ручного склеивания, `New-Item -Force` не считает ошибкой существующий каталог, `Get-Service` читает состояние, `Add-Content` дописывает строку. Запустите сценарий вручную и проверьте журнал.

```powershell
& $script
Get-Content (Join-Path $env:USERPROFILE 'os-lab\logs\heartbeat.log')
```

Если в журнале появилась строка с датой и состоянием, сценарий готов к запуску по расписанию. Если появилась ошибка, прочитайте её и исправьте причину до следующего шага.

### Шаг 8. Создать задание по расписанию

Создайте задание, которое запускает сценарий один раз через небольшой интервал. Сначала подготовьте действие и триггер, затем зарегистрируйте задание.

```powershell
$script = Join-Path $env:USERPROFILE 'os-lab\bin\heartbeat.ps1'
$action = New-ScheduledTaskAction -Execute 'powershell.exe' `
  -Argument "-NoProfile -WindowStyle Hidden -File `"$script`""
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(2)
Register-ScheduledTask -TaskName 'OSLab-Heartbeat' -Action $action -Trigger $trigger `
  -Description 'Проверка службы печати на учебном стенде' -Force
```

`New-ScheduledTaskAction` описывает программу и аргументы. `-Execute 'powershell.exe'` запускает PowerShell, `-File` передаёт путь к сценарию. Вложенные кавычки вокруг пути нужны, потому что имя пользователя может содержать пробел. `New-ScheduledTaskTrigger -Once -At` задаёт однократный запуск.

Проверьте задание сразу после регистрации.

```powershell
Get-ScheduledTask -TaskName 'OSLab-Heartbeat' | Select-Object TaskName,State
Get-ScheduledTaskInfo -TaskName 'OSLab-Heartbeat'
Start-ScheduledTask -TaskName 'OSLab-Heartbeat'
Start-Sleep -Seconds 5
Get-ScheduledTaskInfo -TaskName 'OSLab-Heartbeat'
```

`Start-ScheduledTask` запускает задание немедленно, не дожидаясь триггера. `Start-Sleep` даёт процессу время завершиться. `Get-ScheduledTaskInfo` показывает `LastRunTime`, `LastTaskResult` и следующее время запуска.

### Шаг 9. Проверить результат и журнал

Проверьте, что сценарий действительно выполнился, а не только что задание зарегистрировано. Сравните число строк в журнале до и после запуска.

```powershell
$log = Join-Path $env:USERPROFILE 'os-lab\logs\heartbeat.log'
(Get-Content $log).Count
Start-ScheduledTask -TaskName 'OSLab-Heartbeat'
Start-Sleep -Seconds 5
(Get-Content $log).Count
Get-Content $log -Tail 3
```

Число строк должно увеличиться. Если оно не изменилось, проверьте `LastTaskResult` и аргументы действия. Код `0x1` обычно означает неверный путь или синтаксическую ошибку сценария. Код `0x41301` означает, что задание ещё выполняется, и проверку нужно повторить.

Посмотрите журнал Планировщика, если он включён.

```powershell
Get-WinEvent -LogName 'Microsoft-Windows-TaskScheduler/Operational' -MaxEvents 10 -ErrorAction SilentlyContinue |
  Select-Object TimeCreated,Id,LevelDisplayName,Message
```

Если журнал отключён, командлет вернёт пустой результат. Это не ошибка работы: основной признак успеха это код результата и новая строка в файле.

### Шаг 10. Вернуть стенд в исходное состояние

Удалите учебное задание и восстановите тип запуска службы, который был до работы. Если до работы `Spooler` был в состоянии `Stopped`, оставьте его остановленным.

```powershell
Unregister-ScheduledTask -TaskName 'OSLab-Heartbeat' -Confirm:$false -ErrorAction SilentlyContinue
Set-Service -Name Spooler -StartupType Automatic
Start-Service -Name Spooler
Get-Service -Name Spooler | Select-Object Name,Status,StartType
Get-ScheduledTask -TaskName 'OSLab-Heartbeat' -ErrorAction SilentlyContinue
```

`Unregister-ScheduledTask` удаляет задание, `-Confirm:$false` отключает запрос подтверждения. Последняя команда должна вернуть пустой результат: задания с таким именем больше нет.

## Требования к отчёту

Отчёт содержит титульную часть с названием работы, именем машины и учётной записью. Далее идут разделы по шагам с фактическим выводом.

1. Таблица исходного состояния: машина, учётная запись, выпуск и версия Windows.
2. Таблица служб с состоянием и типом запуска для четырёх имён.
3. Сведения о `Spooler`: учётная запись, зависимости, зависимые службы.
4. Таблица состояний до остановки, после остановки и после запуска.
5. Параметры созданного задания и код результата последнего запуска.
6. Доказательство выполнения: фрагмент журнала с новой строкой.
7. Подтверждение восстановления: состояние службы и отсутствие задания.

В отчёте достаточно текстовых блоков с выводом PowerShell. Если снимок помогает, на нём должны быть видны имя задания или службы и результат, а не только фон рабочего стола.

## Что сдать

- отчёт с таблицами служб и состояний;
- сведения о зависимостях и учётной записи службы `Spooler`;
- параметры задания `OSLab-Heartbeat` и код результата;
- фрагмент журнала `heartbeat.log` с новой строкой после запуска;
- подтверждение удаления задания и восстановления типа запуска службы.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.
- **5**: состояние службы прочитано до и после каждого действия, зависимости объяснены, тип запуска изменён и возвращён, задание создано и проверено по журналу, стенд восстановлен полностью.
- **4**: работа выполнена, но одна таблица заполнена не полностью или код результата задания указан без проверки журнала.
- **3**: служба остановлена и запущена, но зависимости не прочитаны, задание создано без проверки выполнения, исходное состояние восстановлено частично.
- **2**: работа не выполнена или служба оставлена в изменённом состоянии без объяснения.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
