## Цель работы

Научиться двум операциям, которые администратор выполняет чаще всего: управлять программами через пакетный менеджер и подключать новый диск к файловой системе. В работе устанавливаются пакеты с зависимостями, проверяется состояние базы `dpkg`, создаётся раздел на втором виртуальном диске, форматируется в ext4, монтируется постоянно через `fstab` и проверяется утилитой `fsck`. Дополнительно готовится образ носителя `media.iso` с файлами и проверяется его чтение.

Результат работы это подключённый раздел `/srv/data`, который переживает перезагрузку, и образ `media.iso` с контрольной суммой. Оба артефакта понадобятся в следующих работах: на разделе удобно хранить копии и отчёты, а образ показывает, как переносить данные между машинами без общей папки.

## Краткие теоретические сведения

Пакетный менеджер `apt` работает с тремя источниками знаний: списками пакетов из репозиториев, базой установленных пакетов и кешем скачанных файлов. Команда `apt update` обновляет списки, `apt install` строит план установки с зависимостями, `apt remove` удаляет программу, `apt purge` удаляет её вместе с настройками. Низкоуровневая база `/var/lib/dpkg/status` хранит состояние каждого пакета: установлен, удалён, оставлены настройки.

Зависимость это другой пакет, без которого программа не запустится. Например, `ncdu` зависит от библиотеки `libncursesw6`. Пакетный менеджер сам добавляет её в план, поэтому пользователь не работает с библиотеками напрямую. Если поставить `.deb` через `dpkg -i`, зависимости не разрешаются, и установка может завершиться ошибкой.

Диск проходит три стадии. Таблица разделов делит его на области. Файловая система описывает блоки, inode и имена внутри раздела. Точка монтирования присоединяет раздел к дереву каталогов. Без таблицы разделов нет раздела, без файловой системы раздел нельзя смонтировать, без монтирования файлы не видны.

Для постоянного подключения используется `/etc/fstab`. В нём указывают UUID файловой системы, точку монтирования, тип, опции и порядок проверки. UUID не меняется при изменении порядка дисков, поэтому он надёжнее имени `/dev/sdb1`. Опция `nofail` позволяет системе загрузиться, если диск отсутствует.

`fsck` проверяет файловую систему и исправляет ошибки метаданных. Запускать его можно только на отмонтированном разделе: работающая файловая система меняется во время проверки, и утилита может принять нормальные данные за повреждение.

Образ ISO это файл, содержащий файловую систему ISO 9660. Его можно смонтировать через loop-устройство и прочитать как обычный диск. Так готовят носитель для передачи данных, установки программ или проверки образа перед записью.

У файловой системы ext4 есть особенность, о которой узнают при первом расчёте места. Часть блоков зарезервирована для root, обычно 5 процентов. Резерв позволяет службам писать журналы и завершать работу, даже когда пользователь заполнил раздел. Для раздела с данными резерв уменьшают, но не отключают полностью: полностью заполненный диск всё равно создаёт проблемы.

Количество inode фиксируется при создании файловой системы. Один inode хранит имя, права, размер и указатели на блоки. Если на разделе много мелких файлов, inode заканчиваются раньше блоков, и запись останавливается при видимом свободном месте. Поэтому в проверку входит не только `df -h`, но и `df -i`.

## Ход работы

### Шаг 1. Зафиксируйте исходное состояние

В настройках выключенной машины `ubuntu-lab` добавьте второй диск: «Носители», контроллер SATA, «Добавить жёсткий диск», «Создать новый диск», тип VDI, размер 6 ГБ, динамический. Назовите файл `data-disk.vdi`. Запустите машину.

В терминале выполните команды и запишите результат.

```bash
lsblk -f
df -h
df -i
free -h
```

Первая команда показывает устройства и файловые системы, вторая занятое место, третья inode, четвёртая память. Новый диск должен появиться как `sdb` без разделов и без файловой системы.

| Проверка | Команда | До работы | После работы |
|---|---|---|---|
| Новый диск | `lsblk` | sdb, 6 ГБ, без разделов | sdb1, ext4, /srv/data |
| Свободное место корня | `df -h /` |  |  |
| Свободные inode | `df -i /` |  |  |
| Занятая память | `free -h` |  |  |

Строка про новый диск дана как образец заполнения. Если `sdb` не появился, проверьте, что диск подключён к контроллеру и машина загружена после изменения настроек. Иногда ядро назначает имя `sdc`, если уже есть другие устройства: ориентируйтесь на размер 6 ГБ, а не только на букву.

Имя `sdb` не является постоянным. Оно зависит от порядка обнаружения устройств и может измениться после добавления ещё одного диска. Для разметки это не важно, потому что вы работаете с конкретным устройством прямо сейчас. Для `fstab` такое имя опасно: после перезагрузки раздел может оказаться на `sdc`, и строка перестанет работать. Поэтому постоянное монтирование настраивают по UUID.

### Шаг 2. Обновите списки и установите пакеты

Сначала обновите списки и посмотрите, какие версии предлагает репозиторий.

```bash
sudo apt update
apt-cache policy htop ncdu tree vim genisoimage
```

`apt-cache policy` показывает установленную версию, кандидата и репозиторий. Заполните таблицу по выводу команды. Для неустановленных пакетов в поле «Установлено» будет `(none)`.

| Пакет | Кандидат | Репозиторий | Установлено |
|---|---|---|---|
| htop |  |  |  |
| ncdu |  |  |  |
| tree |  |  |  |
| vim |  |  |  |
| genisoimage |  |  |  |

Установите пакеты одной командой.

```bash
sudo apt install -y htop ncdu tree vim genisoimage
```

В выводе найдите строку `The following NEW packages will be installed`. В ней перечислены не только запрошенные программы, но и зависимости. Запишите, сколько пакетов установлено всего и какие из них вы не указывали.

Проверьте каждый пакет.

```bash
dpkg -l htop ncdu tree vim genisoimage
which htop ncdu tree vim genisoimage
htop --version
tree --version
```

`dpkg -l` показывает состояние `ii` для установленных пакетов. `which` находит исполняемые файлы. `htop --version` и `tree --version` подтверждают, что программы запускаются. Если `which` ничего не выводит, пакет не установился или исполняемый файл имеет другое имя.

Сравните число запрошенных и установленных пакетов. В команде указано пять имён, а `apt` мог поставить десять или больше. Разница это зависимости: библиотеки, модули и вспомогательные утилиты. Зависимости не являются «мусором»: без них программы не запустятся. `apt autoremove` удаляет только те пакеты, которые были установлены автоматически и больше не нужны ни одной программе.

### Шаг 3. Разберите установку, удаление и кеш

Посмотрите зависимости и файлы одного пакета.

```bash
apt-cache depends ncdu
dpkg -L ncdu
dpkg -S /usr/bin/ncdu
```

`apt-cache depends` перечисляет зависимости, `dpkg -L` показывает файлы пакета, `dpkg -S` находит пакет по файлу. Запишите, от каких библиотек зависит `ncdu` и в каком каталоге лежит исполняемый файл.

Теперь проверьте разницу между удалением и полной очисткой на пакете `vim`.

```bash
sudo apt remove -y vim
dpkg -l vim
sudo apt purge -y vim
dpkg -l vim
```

После `remove` строка состояния может начинаться с `rc`: программа удалена, настройки остались. После `purge` пакет исчезает из списка. Запишите оба состояния в таблицу.

| Действие | Команда | Состояние в `dpkg -l` | Остались ли настройки |
|---|---|---|---|
| Удаление | `apt remove vim` |  |  |
| Очистка | `apt purge vim` |  |  |

Проверьте кеш пакетов до и после очистки.

```bash
du -sh /var/cache/apt/archives
sudo apt clean
du -sh /var/cache/apt/archives
```

Первая команда показывает размер кеша, вторая очищает его, третья показывает результат. Кеш может занимать сотни мегабайт после установки крупных пакетов. Очистка безопасна: скачанные файлы можно получить из репозитория снова.

Удалите лишние зависимости и проверьте, что система осталась работоспособной.

```bash
sudo apt autoremove -y
sudo apt update
```

`autoremove` удаляет пакеты, которые были установлены как зависимости и больше никому не нужны. Перед подтверждением прочитайте список: в него иногда попадают программы, которыми вы пользуетесь.

### Шаг 4. Создайте таблицу разделов и раздел

Проверьте, что на новом диске нет данных, и создайте таблицу GPT.

```bash
lsblk /dev/sdb
sudo parted /dev/sdb --script mklabel gpt
sudo parted /dev/sdb --script mkpart data ext4 1MiB 100%
sudo partprobe /dev/sdb
lsblk -f /dev/sdb
```

Разберём команды. `mklabel gpt` создаёт новую таблицу и стирает старую. `mkpart data ext4 1MiB 100%` создаёт раздел с именем `data` от отметки 1 МиБ до конца диска. `partprobe` просит ядро перечитать таблицу. `lsblk -f` показывает новый раздел `sdb1` без файловой системы.

| Параметр | Значение |
|---|---|
| Устройство | /dev/sdb |
| Размер диска |  |
| Таблица разделов | GPT |
| Имя раздела | data |
| Начало раздела | 1 МиБ |
| Конец раздела | 100% |
| Имя раздела в системе | /dev/sdb1 |

Проверьте таблицу командой `sudo fdisk -l /dev/sdb`. В выводе должны быть строка `Disklabel type: gpt` и раздел `sdb1` размером около 6 ГБ. Если раздел не появился, повторите `partprobe` и проверьте, что диск не смонтирован.

### Шаг 5. Создайте файловую систему и смонтируйте раздел

Отформатируйте раздел в ext4 с меткой `data`.

```bash
sudo mkfs.ext4 -L data /dev/sdb1
```

В выводе `mkfs` найдите UUID, количество блоков и количество inode. Запишите UUID: он понадобится для `fstab`. Проверьте идентификатор командой `sudo blkid /dev/sdb1`.

Создайте точку монтирования и подключите раздел.

```bash
sudo mkdir -p /srv/data
sudo mount /dev/sdb1 /srv/data
findmnt /srv/data
df -h /srv/data
```

`mkdir -p` создаёт каталог вместе с родительскими каталогами. `mount` подключает раздел. `findmnt` показывает источник, тип и опции, `df -h` размер и свободное место.

| Проверка | Команда | Значение |
|---|---|---|
| UUID | `sudo blkid /dev/sdb1` |  |
| Метка | `sudo blkid /dev/sdb1` | data |
| Тип | `findmnt /srv/data` | ext4 |
| Размер | `df -h /srv/data` |  |
| Свободно | `df -h /srv/data` |  |

Назначьте владельца каталога и создайте контрольный файл.

```bash
sudo chown student:student /srv/data
echo "data disk ready" > /srv/data/check.txt
cat /srv/data/check.txt
```

Файл создаётся от пользователя `student`, потому что каталог принадлежит ему. Если владелец не изменён, запись завершится ошибкой `Permission denied`.

### Шаг 6. Сделайте монтирование постоянным

Откройте `/etc/fstab` редактором с правами root.

```bash
sudo nano /etc/fstab
```

Добавьте строку, заменив UUID на свой. Остальные поля оставьте как в образце.

```text
UUID=ваш-uuid /srv/data ext4 defaults,nofail 0 2
```

Разберите поля: устройство, точка монтирования, тип файловой системы, опции, дамп, порядок проверки. `nofail` разрешает загрузку без этого диска. `0 2` означает, что `dump` не используется, а `fsck` проверяет раздел после корневого.

Ошибка в `fstab` опаснее ошибки в обычной команде. Если строка ссылается на несуществующий UUID и не содержит `nofail`, система при загрузке уйдёт в аварийный режим. Исправление потребует консоли и повторного монтирования корня. Поэтому строку проверяют `mount -a` до перезагрузки, а снимок машины делают заранее.

Проверьте настройку без перезагрузки.

```bash
sudo systemctl daemon-reload
sudo mount -a
findmnt --verify
findmnt /srv/data
```

`daemon-reload` перечитывает настройки systemd. `mount -a` монтирует всё из `fstab`. `findmnt --verify` проверяет синтаксис и предупреждает об ошибках. Если команда `mount -a` ничего не вывела, это хороший признак: ошибок нет.

Размонтируйте и смонтируйте раздел снова, чтобы проверить, что `fstab` действительно используется.

```bash
sudo umount /srv/data
findmnt /srv/data
sudo mount -a
findmnt /srv/data
```

После `umount` команда `findmnt` не должна находить точку монтирования. После `mount -a` раздел возвращается. Перезагрузите машину и проверьте, что файл `check.txt` на месте.

```bash
sudo reboot
```

После загрузки выполните `findmnt /srv/data` и `cat /srv/data/check.txt`. Если раздел не подключился, проверьте строку в `fstab` и вывод `journalctl -xe`.

### Шаг 7. Проверьте файловую систему

Отмонтируйте раздел и запустите проверку.

```bash
sudo umount /srv/data
sudo fsck -f /dev/sdb1
echo $?
```

`fsck -f` проверяет даже чистую файловую систему. Код возврата `0` означает отсутствие ошибок, `1` означает, что ошибки найдены и исправлены. Запишите код в таблицу.

Коды возврата стоит запомнить, потому что они попадают в сценарии и журналы. `0` это чистая файловая система, `1` это исправленные ошибки, `2` требует перезагрузки, `4` означает, что ошибки остались, `8` операционную ошибку, `16` ошибку использования, `32` отмену пользователем. Для учебной работы достаточно различать `0`, `1` и всё остальное: последнее требует разбора, а не повторного запуска.

Посмотрите параметры файловой системы.

```bash
sudo tune2fs -l /dev/sdb1 | grep -E "Filesystem volume name|Filesystem state|Block count|Block size|Inode count|Reserved block count"
```

`tune2fs -l` показывает метку, состояние, количество блоков и inode. `Reserved block count` это резерв для root, обычно 5 процентов. Сравните его с общим числом блоков и объясните, почему свободного места меньше размера раздела.

Проверьте inode и смонтируйте раздел обратно.

```bash
sudo mount /srv/data
df -i /srv/data
df -h /srv/data
```

`df -i` показывает использование inode. Для раздела с небольшим числом файлов процент будет низким. Если `IUse%` близок к 100, новые файлы не создадутся, даже когда место есть.

### Шаг 8. Подготовьте образ носителя

Создайте каталог с файлами для образа.

```bash
mkdir -p ~/media
echo "file one" > ~/media/one.txt
echo "file two" > ~/media/two.txt
ls -l ~/media
```

Соберите ISO-образ.

```bash
genisoimage -o ~/media.iso -R -J ~/media
file ~/media.iso
sha256sum ~/media.iso
```

`-o` задаёт имя образа, `-R` включает длинные имена в формате Rock Ridge, `-J` добавляет поддержку Joliet для Windows. `file` должен показать `ISO 9660 CD-ROM filesystem data`. `sha256sum` вычисляет контрольную сумму: по ней проверяют, что образ не изменился при передаче.

Смонтируйте образ через loop-устройство и прочитайте файлы.

```bash
sudo mkdir -p /mnt/media
sudo mount -o loop ~/media.iso /mnt/media
ls -l /mnt/media
cat /mnt/media/one.txt
df -h /mnt/media
sudo umount /mnt/media
```

`mount -o loop` подключает файл как блочное устройство. После проверки образ отключается. Скопируйте его на раздел данных и сравните хеш.

```bash
cp ~/media.iso /srv/data/
sha256sum ~/media.iso /srv/data/media.iso
```

Обе суммы должны совпасть. Запишите размер образа, его хеш и результат сравнения.

ISO отличается от ZIP тем, что содержит не сжатый архив, а файловую систему. Такой образ можно смонтировать и читать без распаковки, а также записать на оптический носитель или подключить как установочный диск. ZIP удобнее для передачи документов, ISO для носителей и установки. Контрольная сумма проверяет целостность в обоих случаях.

Проверьте, что после перезагрузки раздел подключён, файл `check.txt` читается, а образ `media.iso` лежит на разделе. Это итоговое состояние работы.

Если раздел после перезагрузки не подключился, начните с `journalctl -b -p err` и `findmnt --verify`. Сообщение `can't find UUID` означает, что UUID в `fstab` не совпадает с реальным. Сообщение `unknown filesystem type` означает опечатку в типе. Сообщение `mount point does not exist` означает, что каталог `/srv/data` не создан. Во всех случаях строку исправляют и повторяют `mount -a`, не перезагружая машину.

## Требования к отчёту

Отчёт содержит:

- цель работы и исходное состояние дисков и памяти;
- таблицу пакетов с версиями, репозиториями и зависимостями;
- результат сравнения `apt remove` и `apt purge`;
- размер кеша до и после `apt clean`;
- параметры нового диска, раздела и файловой системы;
- вывод `blkid` с UUID и строку из `fstab`;
- результат `fsck` и код возврата;
- параметры образа `media.iso` и совпадение хешей;
- заполненный паспорт раздела.

Снимки экрана приводятся для вывода `lsblk -f`, `findmnt`, `fsck` и `sha256sum`. На снимке должны быть видны команда и результат, а не только фрагмент текста.

## Что сдать

- отчёт с таблицами пакетов, раздела и образа;
- файл `media.iso` или его копию на разделе `/srv/data`;
- заполненный паспорт раздела с UUID и строкой `fstab`;
- вывод `fsck` с кодом возврата;
- снимок экрана с результатом `findmnt /srv/data` после перезагрузки.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

- **5**: пакеты установлены и проверены, разница `remove` и `purge` показана, раздел создан и размечен, ext4 смонтирована постоянно через UUID, `fstab` проверен, `fsck` выполнен на отмонтированном разделе, образ создан и хеши совпали, паспорт заполнен.
- **4**: работа выполнена, но одна-две проверки не записаны, в `fstab` использован путь устройства вместо UUID или хеш образа вычислен только с одной стороны.
- **3**: пакеты установлены, раздел создан, но постоянное монтирование не работает, `fsck` не выполнен или образ не проверен.
- **2**: работа не выполнена или раздел не создан.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
