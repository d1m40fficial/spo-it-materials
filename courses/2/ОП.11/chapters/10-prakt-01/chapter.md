## Что требуется

Дана сеть `192.168.10.0/24`. Нужно разделить её на четыре подсети под отделы, заполнить таблицу адресов и проверить связь между двумя машинами.

Отделы:

| Отдел | Нужно узлов |
|---|---:|
| продажи | 50 |
| гости | 30 |
| склад | 20 |
| серверная | 10 |

Результат оформляется в `report_template.docx`: таблица адресов, вывод команд проверки и объяснение.

## Ход работы

### Шаг 1. Определите размеры подсетей

Для каждого отдела подберите минимальную маску, которая вмещает нужное число узлов с запасом.

Помните формулу: `2^h - 2` узлов, где `h` это число бит узла. Для 50 узлов нужен `/26`, для 30 и 20 подходит `/27`, для 10 хватает `/28`.

Запишите выбранные маски в таблицу.

### Шаг 2. Выделите блоки

Начинайте с самой большой подсети. Блоки не должны пересекаться, шаг равен числу адресов в блоке.

| Отдел | Маска | Адрес сети | Первый узел | Последний узел | Широковещательный |
|---|---|---|---|---|---|
| продажи |  |  |  |  |  |
| гости |  |  |  |  |  |
| склад |  |  |  |  |  |
| серверная |  |  |  |  |  |

Проверьте, что адрес сети кратен размеру блока, а последний узел на единицу меньше широковещательного.

### Шаг 3. Настройте две машины

Возьмите две виртуальные машины в одной подсети, например продажи.

- первой назначьте первый узел;
- второй назначьте второй узел;
- маску и шлюз укажите одинаковые;
- шлюзом может быть первый адрес подсети, если он не занят узлом.

Проверьте настройки командой `ip addr` в Linux или `ipconfig` в Windows.

### Шаг 4. Проверьте связь

С первой машины выполните:

```bash
ping 192.168.10.2
```

Ожидается ответ. Если ответа нет, проверьте маску, адрес и режим адаптера виртуальной машины.

Затем переведите вторую машину в другую подсеть, например гости, и повторите `ping`. Без маршрутизатора связь пропадёт: машины в разных подсетях.

### Шаг 5. Проверьте служебные адреса

Попробуйте назначить машине адрес сети или широковещательный адрес. Система может предупредить или связь не заработает. Запишите результат.

Объясните в отчёте, почему эти адреса заняты.

### Шаг 6. Посчитайте остаток

После четырёх подсетей часть адресов осталась свободной. Укажите, сколько адресов осталось и под какой блок их можно выделить.

### Шаг 7. Соберите отчёт

Заполните `report_template.docx`:

1. цель;
2. таблица адресов;
3. настройки двух машин;
4. вывод `ping` в одной подсети;
5. вывод `ping` в разных подсетях;
6. объяснение служебных адресов;
7. вывод.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Таблица не заполнена или подсети пересекаются |
| 3 | Адреса верны, но проверки на машинах не выполнены |
| 4 | Все пункты выполнены, отчёт заполнен, есть мелкие недочёты |
| 5 | Все пункты выполнены, расчёт и проверки объяснены, границы служебных адресов показаны |

## Что сдаётся

- `report.docx` с таблицей адресов и выводами команд.
- Скриншоты `ping` в одной и разных подсетях.

> [!PITFALL] Маска и адрес проверяются вместе. Один и тот же адрес с разной маской может оказаться в другой подсети.
