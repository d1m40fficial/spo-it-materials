## Из одной сети в другую

Коммутатор передаёт кадры внутри сегмента. Но если получатель находится в другой сети, кадр до него не дойдёт: MAC-адреса действуют только в локальном сегменте.

**Сетевой уровень** решает задачу доставки между сетями. Он добавляет к данным **IP-адреса** отправителя и получателя и выбирает маршрут через промежуточные устройства.

IP не гарантирует доставку. Он передаёт пакет «как есть», а надёжность появляется на транспортном уровне. Это делает сеть проще и быстрее.

Главная мысль занятия: **IP отвечает за адрес и маршрут, но не за порядок и не за повторную передачу**. Потерянный пакет замечает TCP, а не IP.

## Заголовок IPv4

Заголовок IPv4 содержит 20 байт обязательных полей.

| Поле | Что означает |
|---|---|
| версия | 4 для IPv4 |
| длина заголовка | сколько байт занимает заголовок |
| общая длина | заголовок и данные |
| идентификатор | общий для фрагментов одного пакета |
| флаги и смещение | управление фрагментацией |
| TTL | сколько переходов осталось |
| протокол | TCP, UDP, ICMP |
| контрольная сумма | проверка заголовка |
| адрес отправителя | 32 бита |
| адрес получателя | 32 бита |

Версия нужна, чтобы устройства понимали формат. Длина заголовка позволяет найти данные после необязательных полей. Общая длина ограничивает пакет.

Поле протокола говорит, что внутри: TCP (6), UDP (17), ICMP (1). Без него получатель не знал бы, какому модулю передать данные.

## TTL и переходы

**TTL** это счётчик оставшихся переходов. Отправитель ставит 64 или 128. Каждый маршрутизатор уменьшает значение на единицу.

Когда TTL доходит до нуля, пакет отбрасывается, а отправителю отправляется сообщение ICMP. Так сеть защищается от пакетов, которые ходят по кругу из-за ошибки маршрутизации.

`traceroute` использует это свойство: отправляет пакеты с TTL 1, 2, 3 и собирает адреса маршрутизаторов, которые отвечают.

## Фрагментация

У каждого канала есть **MTU**, максимальный размер кадра. Для Ethernet это обычно 1500 байт полезных данных.

Если пакет больше MTU, его делят на фрагменты. Каждый фрагмент получает свой заголовок, общий идентификатор и смещение. Получатель собирает пакет обратно.

Фрагментация полезна, но дорога: увеличивает число пакетов и риск потери. Современные сети стараются её избегать, подбирая MTU и используя Path MTU Discovery.

## Таблица маршрутов

Маршрутизатор выбирает путь по таблице. В простом виде строка содержит сеть, маску, следующий узел и интерфейс.

```text
10.0.1.0/24   напрямую   eth0
10.0.2.0/24   via 10.0.12.2
0.0.0.0/0     via 203.0.113.1
```

Если подходят несколько строк, выбирается **самый длинный префикс**. Маршрут `/24` точнее, чем `/16`, и `/0` используется только тогда, когда других вариантов нет.

Метрика сравнивает маршруты одинаковой длины. Меньшая метрика означает лучший путь по выбранному критерию: числу переходов, задержке или стоимости.

::figure route-hop | Нажимайте «Шаг»: пакет проходит два маршрутизатора, TTL уменьшается, таблица показывает решение на каждом шаге.

## Где сетевой уровень ломается

**Нет маршрута.** Таблица не содержит сети назначения и нет маршрута по умолчанию. Проверка: `ip route` и `traceroute`.

**Неверная маска.** Устройство считает получателя локальным или удалённым. Проверка: адрес и маска на обоих концах.

**TTL слишком мал.** Пакет не доходит до цели. Проверка: значение TTL и число переходов.

**Фрагментация теряет часть.** Один фрагмент не пришёл, и весь пакет отбрасывается. Проверка: MTU и счётчики фрагментов.

**Петля маршрутизации.** Пакет ходит между двумя маршрутизаторами, пока TTL не станет нулём. Проверка: `traceroute` и таблицы.

**Смешение MAC и IP.** Для маршрута пытаются использовать MAC. Проверка: MAC действует в сегменте, IP между сетями.

> [!PITFALL] IP не гарантирует порядок доставки. Пакеты могут прийти не по порядку, и это нормально. Порядок обеспечивает TCP.

## Итоги

- Сетевой уровень доставляет пакеты между сетями по IP-адресам.
- IP не гарантирует доставку и не сохраняет порядок.
- TTL ограничивает число переходов и защищает от петель.
- Большой пакет фрагментируется по MTU канала.
- Маршрут выбирается по самому длинному совпавшему префиксу.
