## Что требуется

Работа состоит из двух частей.

**Часть 1. Служба.** Запустить веб-службу на виртуальной машине, проверить её локально и с хоста через проброс порта.

**Часть 2. Удалённый доступ.** Настроить SSH-доступ к машине и локальный туннель к той же службе.

Результаты переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Запустите службу

На виртуальной машине в каталоге с файлами выполните:

```bash
python3 -m http.server 8080
```

Служба слушает порт 8080. Проверьте на самой машине:

```bash
curl -I http://localhost:8080/
```

Ожидается ответ `200 OK`.

### Шаг 2. Проверьте адрес машины

```bash
ip addr
```

Запишите адрес машины в режиме NAT, например `10.0.2.15`. В режиме моста адрес будет из физической сети.

### Шаг 3. Настройте проброс порта

В VirtualBox откройте настройки машины, раздел «Сеть», «Дополнительно», «Проброс портов».

Добавьте правило:

| Параметр | Значение |
|---|---|
| Имя | web |
| Протокол | TCP |
| Порт хоста | 8080 |
| Порт гостя | 8080 |

Запустите машину и откройте на хосте `http://127.0.0.1:8080/`. Должна открыться страница службы.

### Шаг 4. Проверьте SSH

Убедитесь, что на машине работает SSH-сервер. Добавьте второе правило проброса:

| Параметр | Значение |
|---|---|
| Имя | ssh |
| Протокол | TCP |
| Порт хоста | 2222 |
| Порт гостя | 22 |

С хоста:

```bash
ssh -p 2222 user@127.0.0.1
```

Если вход прошёл, SSH-доступ работает.

### Шаг 5. Постройте локальный туннель

Не закрывая SSH-сессию, выполните на хосте:

```bash
ssh -L 9090:localhost:8080 -p 2222 user@127.0.0.1
```

Теперь откройте `http://127.0.0.1:9090/`. Запрос идёт на порт 9090 хоста, попадает в SSH-туннель и доходит до службы на машине.

Локальный туннель не требует отдельного правила проброса для 9090.

### Шаг 6. Сравните способы

| Способ | Что делает | Где настраивается |
|---|---|---|
| Проброс порта | открывает порт гостя на хосте | VirtualBox |
| SSH-туннель | шифрует соединение через SSH | клиент SSH |

Проброс удобен для постоянного доступа. Туннель удобен, когда нужен защищённый канал и доступ без изменения настроек гипервизора.

### Шаг 7. Проверьте маршрут

С хоста выполните `traceroute` до адреса машины. В режиме NAT первый переход будет адресом гипервизора.

Объясните в отчёте, почему машина в NAT не видна соседям по физической сети.

### Шаг 8. Соберите отчёт

Заполните разделы: цель, схема, таблица портов, результаты `curl` и `ssh`, сравнение способов, вывод.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Служба не запускается или доступ не настроен |
| 3 | Проброс работает, но туннель или схема неполные |
| 4 | Все части выполнены, отчёт заполнен, есть мелкие недочёты |
| 5 | Все части выполнены, разница способов объяснена, схема точная |

## Что сдаётся

- `report.docx` со схемой, таблицей портов и результатами проверок.

> [!PITFALL] Проброс порта и туннель решают разные задачи. Проброс открывает порт, туннель шифрует соединение и не требует менять настройки гипервизора.
