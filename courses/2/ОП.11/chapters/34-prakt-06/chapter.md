## Что требуется

Провести наблюдение за виртуальной машиной: какие порты открыты, кто подключён, что записано в журнале входа. Затем создать несколько неудачных попыток входа и найти их в журнале.

Работа состоит из трёх частей:

1. список портов и служб;
2. активные соединения;
3. журнал попыток входа и вывод.

Результаты переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Подготовьте доступ

Включите машину в режиме NAT и убедитесь, что SSH-сервер работает. В настройках адаптера добавьте проброс порта:

| Имя | Протокол | Порт хоста | Порт гостя |
|---|---|---:|---:|
| ssh | TCP | 2222 | 22 |

Проверьте вход с хоста:

```bash
ssh -p 2222 user@127.0.0.1
```

### Шаг 2. Снимите список портов

На машине выполните:

```bash
sudo ss -tulpn
```

Команда показывает протокол, адрес и порт, а также процесс. Заполните таблицу: порт, протокол, служба, нужна ли она.

Для сравнения посмотрите состояние до запуска службы и после:

```bash
python3 -m http.server 8080
sudo ss -tulpn | grep 8080
```

### Шаг 3. Посмотрите активные соединения

Откройте второе окно и подключитесь по SSH. На машине выполните:

```bash
ss -tan state established
```

Запишите, какие адреса и порты видны. Объясните, почему соединение SSH имеет две разные пары портов на двух концах.

### Шаг 4. Создайте события входа

С хоста выполните три попытки с неверным паролем:

```bash
ssh -p 2222 wrong@127.0.0.1
```

Повторите три раза, каждый раз вводя неверный пароль. Затем войдите с правильным.

### Шаг 5. Найдите события в журнале

На машине:

```bash
sudo journalctl -u ssh --since "15 min ago" | grep "Failed password"
```

Если журнал хранится в файле, подойдёт:

```bash
sudo grep "Failed password" /var/log/auth.log | tail -n 10
```

Запишите: время, имя пользователя, адрес источника, число попыток. Обратите внимание, что адрес источника это адрес хоста, а не машины.

### Шаг 6. Уберите лишнюю службу

Остановите `http.server`, если он ещё работает. Проверьте, что порт исчез:

```bash
sudo ss -tulpn | grep 8080
```

Запишите, что изменилось в списке портов.

### Шаг 7. Прочитайте правила фильтрации

Посмотрите, какие правила действуют на машине:

```bash
sudo ufw status verbose
```

Если `ufw` не установлен, прочитайте правила напрямую:

```bash
sudo iptables -S
```

Запишите политику по умолчанию и наличие разрешающих правил. Ничего не меняйте: на этом шаге нужен только разбор.

### Шаг 8. Соберите отчёт

Заполните разделы: цель, таблица портов, таблица соединений, таблица событий, вывод о состоянии узла.

В выводе ответьте: какие службы открыты наружу, какие события входа подозрительны, что стоит изменить.

## Критерии оценки

| Балл | Что оценивается |
|---:|---|
| 1 | Работа сделана с ИИ или скопирована без возможности объяснить и исправить |
| 2 | Порты и журнал не сняты, вывод отсутствует |
| 3 | Таблицы заполнены частично, события найдены не все |
| 4 | Все части выполнены, отчёт заполнен, есть мелкие недочёты |
| 5 | Все части выполнены, события сопоставлены с действиями, вывод обоснован |

## Что сдаётся

- `report.docx` с таблицами портов, соединений и событий.
- Скриншоты `ss -tulpn` и строк журнала о неудачных входах.

> [!PITFALL] Неудачные попытки входа это не всегда атака. Сначала проверьте, не ошибся ли паролем свой пользователь, и только потом делайте вывод.
