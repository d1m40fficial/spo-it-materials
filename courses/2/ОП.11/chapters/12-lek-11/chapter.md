## Куда отправить пакет

Маршрутизатор получает пакет и должен решить, в какой интерфейс его передать. Ответ хранится в **таблице маршрутов**.

Простейшая таблица:

```text
10.0.1.0/24   напрямую   eth0
10.0.2.0/24   via 10.0.12.2
0.0.0.0/0     via 203.0.113.1
```

Первая строка означает, что сеть подключена к интерфейсу `eth0`. Вторая отправляет пакеты через соседний маршрутизатор. Третья задаёт маршрут по умолчанию для всего остального.

**Маршрутизация** это построение таблицы. **Коммутация пакетов** это выбор строки для конкретного пакета. Маршрутизатор делает и то, и другое.

Главная мысль занятия: **выбирает не первый совпавший маршрут, а самый точный**. Чем длиннее префикс, тем конкретнее сеть.

## Самый длинный префикс

Пусть в таблице есть три маршрута:

```text
10.0.0.0/8    via R1
10.1.0.0/16   via R2
10.1.2.0/24   via R3
```

Для адреса `10.1.2.55` подходят все три. Выбирается `/24`, потому что он самый длинный: 24 бита совпали, а не 16 и не 8.

Для `10.1.5.7` подходят `/8` и `/16`, побеждает `/16`. Для `10.2.3.4` подходит только `/8`. Для `8.8.8.8` не подходит ни один, и используется маршрут по умолчанию.

::figure route-choice | Нажимайте на адрес назначения: маршрутизатор подсвечивает самую точную строку таблицы.

## Статические и динамические маршруты

**Статический маршрут** задаёт администратор. Он прост, предсказуем и не создаёт служебного трафика. Минус: при изменении сети его нужно править вручную.

```bash
ip route add 10.0.2.0/24 via 10.0.12.2
```

**Динамический маршрут** появляется в результате работы протокола маршрутизации. Маршрутизаторы обмениваются сведениями и перестраивают таблицу при обрыве.

| Протокол | Область | Особенность |
|---|---|---|
| RIP | небольшие сети | считает переходы |
| OSPF | средние и крупные | учитывает стоимость каналов |
| BGP | интернет | обмен между автономными системами |

Динамические протоколы нужны там, где топология меняется. В маленькой сети из двух маршрутизаторов хватает статики.

## Метрика и административное расстояние

Если два маршрута ведут в одну сеть с одинаковой длиной префикса, сравнивают **метрику**. Она показывает стоимость пути по критерию протокола: число переходов, задержку, пропускную способность.

Перед метрикой может учитываться **административное расстояние**: доверие к источнику маршрута. Маршрут, заданный вручную, обычно предпочтительнее изученного по протоколу.

Порядок выбора:

1. самый длинный совпавший префикс;
2. административное расстояние;
3. метрика.

Маршрут по умолчанию `0.0.0.0/0` имеет самый короткий префикс и используется последним.

## Пересылка пакета

Маршрутизатор получает кадр, снимает канальный заголовок, уменьшает TTL, проверяет контрольную сумму и ищет маршрут.

Затем он строит новый кадр для следующего участка: MAC-адрес следующего узла, свой MAC отправителя. IP-адреса не меняются.

Если сети назначения нет и маршрута по умолчанию тоже нет, пакет отбрасывается, а отправителю уходит сообщение ICMP «сеть недоступна».

## Где маршрутизация ломается

**Нет маршрута.** Таблица не содержит сеть, и пакет отбрасывается. Проверка: `ip route get`.

**Петля.** Два маршрутизатора отправляют пакет друг другу, пока TTL не станет нулём. Проверка: `traceroute`.

**Неверный шлюз.** Соседний адрес указан неправильно. Проверка: доступность шлюза.

**Маршрут по умолчанию перекрывает всё.** Слишком общий маршрут забирает трафик, который должен идти напрямую. Проверка: порядок префиксов.

**Асимметричный маршрут.** Пакет идёт туда по одному пути, обратно по другому. Проверка: трассировка в обе стороны.

**Метрика без смысла.** Выбран медленный путь из-за настроек. Проверка: значения метрик.

> [!PITFALL] Маршрутизатор не проверяет, существует ли получатель. Он выбирает путь по адресу и передаёт пакет дальше.

## Итоги

- Таблица маршрутов хранит сети, следующий узел и интерфейс.
- Выбирается самый длинный совпавший префикс.
- Статические маршруты задаёт администратор, динамические строят протоколы.
- При равном префиксе сравнивают административное расстояние и метрику.
- Маршрут по умолчанию используется, когда других совпадений нет.
