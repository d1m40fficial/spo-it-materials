## Страница по запросу

Браузер открывает `https://example.ru/index.html`. Он отправляет запрос, сервер возвращает страницу и связанные файлы.

**HTTP** описывает формат этого обмена. Клиент формирует **запрос**, сервер отвечает **ответом**. Каждое сообщение состоит из стартовой строки, заголовков, пустой строки и тела.

HTTP не хранит состояние: сервер не помнит предыдущий запрос, если клиент не передал данные явно. Состояние добавляют cookie или токены.

Главная мысль занятия: **HTTP прост и расширяем, а HTTPS добавляет защиту канала**. Формат сообщений при этом не меняется.

## Запрос

```text
GET /index.html HTTP/1.1
Host: example.ru
User-Agent: Mozilla/5.0
Accept: text/html
Connection: keep-alive

```

Стартовая строка содержит метод, путь и версию. Заголовки уточняют запрос. Пустая строка завершает заголовки, дальше может идти тело.

Основные методы:

| Метод | Назначение |
|---|---|
| GET | получить данные |
| POST | отправить данные |
| PUT | заменить ресурс |
| PATCH | изменить часть |
| DELETE | удалить ресурс |
| HEAD | получить только заголовки |

Метод говорит о намерении, но сервер сам решает, что разрешено.

## Ответ

```text
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 1256
Cache-Control: max-age=300

<!DOCTYPE html> ...
```

Коды состояния делятся на группы.

| Код | Значение |
|---|---|
| 200 | успех |
| 301, 302 | перенаправление |
| 304 | не изменилось, взять из кэша |
| 400 | неверный запрос |
| 401, 403 | требуется вход или доступ запрещён |
| 404 | не найдено |
| 500 | ошибка сервера |

Код 404 означает, что сервер доступен, но ресурса нет. Ошибка соединения выглядит иначе: браузер не получает ответа вовсе.

## HTTPS

**HTTPS** это HTTP внутри **TLS**. Перед обменом данными стороны устанавливают защищённый канал:

1. клиент и сервер договариваются о параметрах;
2. сервер предъявляет сертификат;
3. проверяется цепочка доверия и имя;
4. создаются ключи шифрования.

После этого запросы и ответы передаются в зашифрованном виде. Промежуточный узел видит адрес сервера и примерный объём, но не путь и не содержимое.

Сертификат подтверждает, что сервер принадлежит указанному домену. Если сертификат просрочен или выдан другому имени, браузер предупреждает.

## Заголовки и состояние

Заголовки управляют кэшем, форматом, языком, сжатием и соединением.

- `Content-Type` говорит, что за данные;
- `Content-Length` задаёт размер;
- `Cache-Control` задаёт правила кэша;
- `Set-Cookie` просит клиента сохранить cookie;
- `Authorization` передаёт данные входа.

Cookie это небольшие данные, которые браузер возвращает серверу. Они позволяют узнавать сессию, но сами по себе не защищают от подделки.

## Где HTTP ломается

**Неверный метод.** GET используют для удаления. Проверка: семантика метода.

**Код 200 при ошибке.** Сервер отвечает успехом, а в теле сообщение об ошибке. Проверка: тело и журналы.

**Кэш мешает обновлению.** Браузер держит старую версию. Проверка: `Cache-Control` и жёсткое обновление.

**Сертификат просрочен.** HTTPS не открывается. Проверка: срок и цепочка.

**Смешанное содержимое.** Страница по HTTPS загружает ресурсы по HTTP. Браузер блокирует часть.

**Cookie без защиты.** Значение передаётся открыто. Проверка: флаги `Secure` и `HttpOnly`.

> [!PITFALL] HTTPS защищает канал, но не гарантирует честность сайта. Фишинговый сайт тоже может иметь действующий сертификат.

## Итоги

- HTTP состоит из запроса и ответа с заголовками и телом.
- Методы задают намерение, коды состояния сообщают результат.
- HTTP не хранит состояние, его добавляют cookie и токены.
- HTTPS это HTTP внутри TLS с проверкой сертификата.
- Заголовки управляют кэшем, форматом и безопасностью.
