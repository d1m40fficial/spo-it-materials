## Что требуется

Работа состоит из двух частей.

**Часть 1. Неисправности.** В виртуальной машине по очереди вводятся четыре неисправности: неверная маска, неверный шлюз, неверный DNS и остановленная служба. Для каждой нужно найти причину по цепочке проверок и восстановить работу.

**Часть 2. Аренда адреса.** Разобрать, как машина получает адрес по DHCP: сервер, выданные параметры, срок аренды. Сравнить аренду в режиме NAT и в режиме моста.

Результаты переносятся в `report_template.docx`.

## Ход работы

### Шаг 1. Снимите исходное состояние

Включите адаптер в режиме NAT и запишите вывод команд:

```bash
ip addr
ip route
cat /etc/resolv.conf
ping -c 2 10.0.2.2
nslookup example.com
```

В Windows те же сведения даёт `ipconfig /all`, проверка шлюза идёт через `ping 10.0.2.2`, а имя проверяется через `nslookup example.com`.

Заполните строку «Исходное» в таблице проверок. Адрес шлюза в NAT обычно `10.0.2.2`, адрес машины `10.0.2.15`.

### Шаг 2. Неверная маска

Поставьте маске значение `/30`. Имя интерфейса возьмите из вывода `ip addr`:

```bash
sudo ip addr change 10.0.2.15/30 dev enp0s3
```

Проверьте шлюз и внешний адрес:

```bash
ping -c 2 10.0.2.2
ping -c 2 93.184.216.34
```

Запишите результат. Адрес у машины есть, но шлюз оказался вне её подсети. Объясните в отчёте, почему `ping` до шлюза не проходит.

Верните маску `/24` той же командой.

### Шаг 3. Неверный шлюз

Замените маршрут по умолчанию:

```bash
sudo ip route replace default via 10.0.2.99
```

Проверьте:

```bash
ping -c 2 10.0.2.2
ping -c 2 93.184.216.34
nslookup example.com
```

Запишите, какие проверки прошли и какие нет. Верните шлюз `10.0.2.2`.

### Шаг 4. Неверный DNS

Временно укажите несуществующий сервер имён:

```bash
echo "nameserver 192.0.2.53" | sudo tee /etc/resolv.conf
```

Проверьте имя и адрес:

```bash
nslookup example.com
ping -c 2 93.184.216.34
```

Сравните два результата. Верните исходный файл: перезапустите службу сети или переподключите адаптер.

### Шаг 5. Остановленная служба

Запустите простую службу в каталоге с файлами:

```bash
python3 -m http.server 8080
```

В другом окне терминала проверьте её и остановите:

```bash
curl -I http://localhost:8080/
```

Остановите службу сочетанием `Ctrl+C` и повторите запрос. Запишите текст ошибки. Объясните, чем «порт закрыт» отличается от «узел не отвечает».

### Шаг 6. Разберите аренду адреса

Переключите адаптер в NAT и переподключите его. Затем посмотрите параметры аренды.

В Linux:

```bash
ip addr show
ip route
nmcli device show | grep -i dhcp
```

Если `nmcli` недоступен, подойдёт `journalctl -u NetworkManager | grep -i dhcp` или `networkctl status`.

В Windows:

```powershell
ipconfig /all
```

Заполните таблицу аренды: сервер DHCP, выданный адрес, маска, шлюз, DNS, срок аренды.

### Шаг 7. Освободите и получите адрес заново

В Linux:

```bash
sudo dhclient -r
sudo dhclient -v
```

Если `dhclient` не установлен, подойдёт перезапуск сетевой службы:

```bash
sudo nmcli networking off
sudo nmcli networking on
```

В Windows:

```powershell
ipconfig /release
ipconfig /renew
```

Запишите, изменился ли адрес и почему. Обратите внимание на четыре шага обмена: поиск сервера, предложение, запрос, подтверждение.

### Шаг 8. Смените режим адаптера

Переключите адаптер на мост, переподключите и снова получите адрес. Заполните вторую строку таблицы аренды.

Сравните подсети и шлюзы двух режимов. Объясните, почему в NAT адрес всегда из одного диапазона, а в мосту зависит от сети организации.

### Шаг 9. Соберите отчёт

Заполните разделы: цель, таблица неисправностей, таблица аренды, вывод по каждой части.

## Что сдаётся

- `report.docx` с таблицами неисправностей и аренды, командами и выводом.
- Скриншоты вывода `ip addr` и `ipconfig /all` в двух режимах.

> [!PITFALL] Неверный DNS не мешает `ping` по адресу. Если имя не переводится, а адрес отвечает, ищите причину в настройках DNS, а не в кабеле.
