## Цель работы

Собрать учебный стенд `os-lab` в состояние, которое можно показать и повторить. В стенд входят две гостевые системы: `ubuntu-lab` с Ubuntu 22.04 и `win-lab` с Windows 10. Нужно проверить ресурсы машин, сеть с пробросом порта, общую папку, службы и учётные записи, затем сохранить конфигурацию и снимок.

Результат работы это паспорт стенда, карта проверок с фактическими результатами и архив конфигурации. Паспорт описывает, из чего собран стенд. Карта проверок доказывает, что он работает. Архив и снимок позволяют вернуться к этому состоянию, если следующая настройка что-то сломает.

## Оборудование и программное обеспечение

- Учебный стенд `os-lab` с VirtualBox.
- Гостевая система `ubuntu-lab` (Ubuntu 22.04), учётная запись `student` с правами `sudo`.
- Гостевая система `win-lab` (Windows 10), учётная запись `admin`.
- Общая папка `share`, подключённая к обеим машинам.
- Терминал Ubuntu, PowerShell и менеджер VirtualBox на хосте.
- Word или LibreOffice Writer для отчёта.

## Краткие теоретические сведения

Стенд это набор машин, сетей и настроек, собранных для одной учебной задачи. Хороший стенд воспроизводим: по паспорту другой человек может собрать такой же и получить тот же результат. Поэтому в паспорт записывают версии систем, число процессоров, объём памяти, размер диска, режим сети, имена учётных записей и список служб.

Состояние стенда со временем расходится с паспортом. Кто-то поставил лишний пакет, изменил адрес, оставил тестовую учётную запись. Такое расхождение называют дрейфом конфигурации. Паспорт и карта проверок нужны не для отчёта, а чтобы заметить дрейф до того, как он сломает следующую работу. Поэтому фактические значения записывают, даже если они совпадают с ожидаемыми.

Проверка стенда отличается от его настройки. Настройка меняет состояние, проверка подтверждает, что состояние соответствует ожидаемому. Проверку оформляют списком: что проверяем, какой командой, какой результат считаем нормой, что получилось фактически. Если проверка не имеет измеримого результата, она превращается в общее впечатление.

Сеть в VirtualBox строится на режиме NAT. Гостевая машина получает адрес из сети `10.0.2.0/24`, обычно `10.0.2.15`, шлюзом служит `10.0.2.2`. Проброс порта связывает порт хоста с портом гостя: хост `2222` направляется на гостевой `22`. Проверять проброс нужно с хоста, потому что изнутри гостя этот порт может быть недоступен.

Общая папка это каталог хоста, подключённый к гостю. В Linux он обычно виден в `/media/sf_share` и требует членства в группе `vboxsf`. В Windows он открывается по пути `\\VBOXSVR\share`. Общая папка удобна для обмена отчётами, но не заменяет резервную копию: при отказе хоста исчезнут и машина, и папка.

Служба отличается от обычной программы тем, что работает без входа пользователя и может запускаться при загрузке. В Linux это unit systemd с включённым автозапуском, в Windows служба с типом запуска Automatic. Проверка службы включает состояние, автозапуск и запись в журнале. Одного слова «работает» недостаточно.

Проверки выполняют в одинаковом порядке, иначе результат зависит от случайности. Сначала ресурсы, затем сеть, затем общая папка, затем службы. Если проверять службу до сети, можно принять сетевую ошибку за отказ службы и потратить время не на ту причину. В карте фиксируют время проверки: по нему видно, относится ли результат к текущему состоянию или к прошлой загрузке.

## Ход работы

### Шаг 1. Составьте паспорт стенда

Соберите сведения о машинах. На хосте в терминале VirtualBox выполните:

```text
VBoxManage list vms
VBoxManage showvminfo "ubuntu-lab" --machinereadable
VBoxManage showvminfo "win-lab" --machinereadable
```

В выводе найдите память, число процессоров, режим сети и правила проброса. В гостевой Linux проверьте систему:

```bash
hostnamectl
nproc
free -h
df -h /
ip -4 addr
ip route
```

Заполните паспорт. Первая строка дана как образец, остальные значения получите сами.

| Параметр | ubuntu-lab | win-lab |
|---|---|---|
| Операционная система | Ubuntu 22.04 |  |
| Процессоры | 2 |  |
| Память | 2048 МБ |  |
| Диск | 25 ГБ |  |
| Сеть | NAT 10.0.2.0/24 |  |
| Проброс порта | хост 2222 на гость 22 |  |
| Основная учётная запись | student |  |
| Общая папка | /media/sf_share |  |

### Шаг 2. Проверьте ресурсы и состояние систем

В `ubuntu-lab` убедитесь, что ресурсы соответствуют паспорту и нет неудачных служб:

```bash
nproc
free -h
df -h /
systemctl --failed
uptime -p
```

В `win-lab` откройте PowerShell и проверьте память, диск и систему:

```powershell
Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory, NumberOfLogicalProcessors
Get-PSDrive -PSProvider FileSystem
Get-Service | Where-Object {$_.Status -eq 'Stopped' -and $_.StartType -eq 'Automatic'} | Select-Object Name, DisplayName
```

Последняя команда показывает службы, которые должны работать автоматически, но остановлены. Пустой список это норма, одна-две записи требуют объяснения. Запишите результат в карту проверок.

Сравните выделенные ресурсы с возможностями хоста. Если обе машины получили по два процессора и по 2 ГБ памяти, а на хосте всего четыре ядра и 8 ГБ, одновременная работа может вызвать нехватку памяти. Виртуальная машина не должна занимать больше половины оперативной памяти хоста. Проверьте это по паспорту и запишите вывод: хватает ли ресурсов для одновременного запуска или машины придётся запускать по очереди.

Ресурсы проверяют не только по цифрам в настройках, но и по фактическому поведению. Если гость постоянно использует файл подкачки или процессор загружен на 100 процентов без полезной работы, выделенных ресурсов не хватает. На учебном стенде достаточно открыть монитор системы и посмотреть нагрузку в покое. Запишите наблюдение, даже если оно не совпадает с ожиданием.

### Шаг 3. Проверьте сеть и проброс порта

В `ubuntu-lab` посмотрите адрес, маршрут и открытые порты:

```bash
ip -4 addr
ip route
ss -tlnp
```

Адрес должен быть из сети `10.0.2.0/24`, маршрут по умолчанию через `10.0.2.2`, а порт `22` должен слушать SSH. Проверьте службу:

```bash
systemctl is-enabled ssh
systemctl is-active ssh
```

На хосте проверьте проброс. Сначала порт:

```powershell
Test-NetConnection 127.0.0.1 -Port 2222
```

Затем подключение по SSH, если клиент установлен:

```powershell
ssh -p 2222 student@127.0.0.1
```

Если подключение не проходит, проверьте правило проброса в настройках машины: имя `ssh`, протокол TCP, адрес хоста `127.0.0.1`, порт хоста `2222`, порт гостя `22`. Не меняйте настройки хоста и не используйте адаптер host-only. Запишите, что именно пришлось исправить.

Правило проброса удобно читать по полям. Имя отличает одно правило от другого, протокол задаёт TCP или UDP, адрес хоста ограничивает, с какого интерфейса принимается подключение, а пара портов связывает хост и гостя. Если адрес хоста пуст, правило может слушать все интерфейсы, и это менее безопасно. Для учебного стенда оставляйте `127.0.0.1`.

Отдельно проверьте, что гость видит шлюз: команда `ping -c 3 10.0.2.2` должна получать ответ. Если шлюз недоступен, проблема в настройках адаптера, а не в пробросе порта. Такой порядок проверки экономит время: сначала связность, потом служба, потом порт.

### Шаг 4. Проверьте общую папку

В `ubuntu-lab` убедитесь, что папка подключена:

```bash
mount | grep vboxsf
ls -la /media/sf_share
echo "test from ubuntu" > /media/sf_share/ubuntu-check.txt
cat /media/sf_share/ubuntu-check.txt
```

Если каталога нет, проверьте, что общая папка включена в настройках машины и что пользователь входит в группу `vboxsf`. После добавления в группу нужен повторный вход. В `win-lab` откройте папку и прочитайте файл:

```powershell
Get-ChildItem \\VBOXSVR\share
Get-Content \\VBOXSVR\share\ubuntu-check.txt
"test from windows" | Set-Content \\VBOXSVR\share\windows-check.txt
```

Вернитесь в Linux и прочитайте встречный файл. Обмен должен работать в обе стороны. Запишите имена файлов и результат.

Права на общую папку зависят от настроек VirtualBox и прав пользователя на хосте. Если Linux может читать файл, а записывать не может, проверьте, не включён ли режим только для чтения. Если Windows видит папку, а Linux нет, сравните имя папки в настройках машины и в команде `mount`. Одинаковое имя `share` во всех инструкциях избавляет от лишних ошибок.

### Шаг 5. Настройте службу и автозагрузку

Создайте службу, которая подтверждает, что стенд жив после перезагрузки. В `ubuntu-lab`:

```bash
mkdir -p ~/lab/bin
cat > ~/lab/bin/stand-heartbeat.sh <<'EOF'
#!/bin/sh
while true; do
  echo "$(date '+%F %T') stand alive" >> /home/student/lab/stand.log
  sleep 60
done
EOF
chmod +x ~/lab/bin/stand-heartbeat.sh
```

Создайте файл `~/lab/stand-heartbeat.service` с содержимым:

```ini
[Unit]
Description=Stand heartbeat
After=network.target

[Service]
Type=simple
ExecStart=/home/student/lab/bin/stand-heartbeat.sh
Restart=always
RestartSec=10
User=student

[Install]
WantedBy=multi-user.target
```

Установите и включите службу:

```bash
sudo cp ~/lab/stand-heartbeat.service /etc/systemd/system/stand-heartbeat.service
sudo systemctl daemon-reload
sudo systemctl enable --now stand-heartbeat
systemctl is-enabled stand-heartbeat
systemctl is-active stand-heartbeat
tail -n 2 ~/lab/stand.log
```

В `win-lab` проверьте службу печати и её тип запуска:

```powershell
Get-Service -Name Spooler | Select-Object Name, Status, StartType
Set-Service -Name Spooler -StartupType Automatic
Get-Service -Name Spooler | Select-Object Name, Status, StartType
```

Служба печати выбрана потому, что она безопасна для учебной машины и не требует установки дополнительного программного обеспечения. Если она остановлена, запустите её командой `Start-Service -Name Spooler` и объясните причину остановки.

Имя службы в Windows чувствительно к языку только для отображаемого названия. Командное имя `Spooler` одинаково на разных версиях, поэтому его удобно использовать в инструкции и отчёте.

### Шаг 6. Проверьте учётные записи и права

В Linux проверьте, что `student` имеет доступ к `sudo`, но не работает без пароля:

```bash
id student
sudo -l
getent group sudo
```

В Windows проверьте членство в администраторах и отсутствие лишних тестовых учётных записей:

```powershell
Get-LocalUser
Get-LocalGroup | Where-Object {$_.SID -like 'S-1-5-32-544'} | Get-LocalGroupMember
```

Запишите в паспорт, какие учётные записи используются людьми, а какие являются служебными. Если остались `labuser` или `labaudit` с прошлой работы, удалите их и отметьте это как отклонение.

Проверьте, что у `student` нет лишних групп. Команда `id student` показывает все группы, а `getent group sudo` список администраторов. Если в списке есть учётная запись, которая не должна администрировать стенд, удалите её из группы и запишите действие. На стенде, который сдаётся, не должно быть тестовых пользователей и паролей из инструкций.

### Шаг 7. Сохраните конфигурацию и снимок

Соберите конфигурацию стенда в архив и положите его в общую папку:

```bash
mkdir -p /media/sf_share/os-prakt-12
cd ~
tar -czf /media/sf_share/os-prakt-12/stand-config.tar.gz lab
sha256sum /media/sf_share/os-prakt-12/stand-config.tar.gz > /media/sf_share/os-prakt-12/stand-config.sha256
tar -tzf /media/sf_share/os-prakt-12/stand-config.tar.gz | head
```

Для снимка выключите машину, затем на хосте создайте точку:

```text
VBoxManage snapshot "ubuntu-lab" take "stand-ready" --description "Итоговый стенд после проверки"
VBoxManage snapshot "ubuntu-lab" list
```

Включите машину и убедитесь, что служба и общая папка работают. Снимок нужен как точка возврата перед следующей настройкой, а архив как копия конфигурации на хосте. Одно другое не заменяет.

Архив конфигурации должен быть понятен без автора. Внутри полезно иметь короткий файл с описанием: имя машины, дата, что изменено, какие службы включены. Если архив открывает другой человек, он не должен угадывать назначение каталогов. Контрольная сумма подтверждает, что файл не повредился при переносе, но не объясняет содержимое.

### Шаг 8. Проведите итоговый прогон и заполните карту

Перезагрузите `ubuntu-lab` и после входа проверьте службу, сеть и папку:

```bash
sudo reboot
```

После подключения:

```bash
systemctl is-active stand-heartbeat
systemctl is-enabled stand-heartbeat
tail -n 3 ~/lab/stand.log
ss -tlnp | grep ':22'
ls /media/sf_share
```

Заполните карту проверок. В столбце «Ожидаемо» указано требование, в столбце «Факт» запишите полученное значение, в последнем столбце отметьте отклонение. Первая строка дана как образец.

| Проверка | Команда | Ожидаемо | Факт | Отклонение |
|---|---|---|---|---|
| Имя машины | hostnamectl | ubuntu-lab | ubuntu-lab | нет |
| Процессоры Linux | nproc | 2 |  |  |
| Память Linux | free -h | около 2 ГБ |  |  |
| Свободное место | df -h / | не меньше 3 ГБ |  |  |
| Адрес Linux | ip -4 addr | 10.0.2.15 |  |  |
| Порт SSH | ss -tlnp | 22 слушается |  |  |
| Проброс с хоста | Test-NetConnection | порт 2222 открыт |  |  |
| Общая папка | mount | vboxsf подключён |  |  |
| Служба heartbeat | systemctl is-active | active |  |  |
| Автозапуск службы | systemctl is-enabled | enabled |  |  |
| Служба Windows | Get-Service Spooler | Running, Automatic |  |  |
| Тестовые учётные записи | Get-LocalUser | отсутствуют |  |  |

Если проверка не прошла, не исправляйте её молча. Запишите отклонение, причину и действие. Карта с одним честным отклонением полезнее карты, где все клетки заполнены словом «нет» без доказательств.

Итоговый прогон делают после перезагрузки, а не до неё. Именно загрузка показывает, включается ли служба сама, поднимается ли сеть и подключается ли общая папка без ручных команд. Если проверять только текущий сеанс, автозапуск останется непроверенным. Запишите время перезагрузки и время, когда стенд снова стал доступен.

Отклонения делятся на допустимые и требующие исправления. Если память машины 1900 МБ вместо 2048, это норма: часть занята видеоадаптером и системой. Если служба не включается в автозапуск или порт не проброшен, это требует исправления до сдачи. Разницу объясните в отчёте, а не скрывайте округлением.

### Шаг 9. Оформите отчёт

Соберите отчёт в Word или LibreOffice Writer. Структура: цель, состав стенда, паспорт, карта проверок, найденные отклонения, принятые меры, архив и снимок, вывод. Объём четыре-шесть страниц.

В отчёт вставьте скриншоты окна VirtualBox с настройками сети и списком снимков, вывода `systemctl status stand-heartbeat`, результата `Test-NetConnection` и списка файлов в общей папке. На каждом скриншоте должны быть видны команда или настройка, результат и время. Текстовые выписки дублируйте, чтобы отчёт читался без увеличения картинок.

Отчёт должен позволить повторить сборку. Если в нём нет имени снимка, параметров сети или списка служб, повторить стенд не получится. Проверьте, что каждое утверждение «работает» подкреплено командой и результатом. Слова «всё настроено» без доказательства в отчёт не включайте.

## Требования к отчёту

- Паспорт стенда с параметрами обеих машин.
- Карта проверок с фактическими результатами и отклонениями.
- Описание настроенной службы Linux и проверенной службы Windows.
- Подтверждение работы проброса порта и общей папки в обе стороны.
- Имя снимка, имя архива и значение контрольной суммы.
- Список отклонений с причиной и действием.
- Вывод на пять предложений: что подтверждено, что осталось хрупким, что проверить перед следующей работой.

## Что сдать

- паспорт стенда с параметрами машин и учётных записей;
- заполненную карту проверок с отклонениями;
- архив `stand-config.tar.gz` и файл контрольной суммы в общей папке;
- имя снимка `stand-ready` и подтверждение его наличия;
- отчёт с результатами проверки сети, папки и служб;
- вывод о готовности стенда и слабых местах.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.
- **5**: паспорт заполнен по фактическим данным, все проверки выполнены с командами и результатами, служба работает и включена в автозапуск, проброс и общая папка проверены в обе стороны, архив и снимок созданы, отклонения объяснены.
- **4**: работа выполнена полностью, но одна проверка пропущена или отклонение записано без причины, а вывод не называет слабое место.
- **3**: паспорт неполный, служба запущена без автозапуска, проверка сети или папки выполнена только с одной стороны, архив создан без контрольной суммы.
- **2**: работа не выполнена.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
