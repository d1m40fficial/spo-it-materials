## Цель работы

Научиться выполнять одну и ту же работу в двух операционных системах и видеть, где команды совпадают, а где расходятся. На стенде `os-lab` создаётся одинаковая структура каталогов в `ubuntu-lab` и `win-lab`, затем выполняются навигация, поиск файлов, поиск по содержимому, чтение журнала, подсчёт размеров и пакетное переименование. Каждая пара команд проверяется на одном и том же наборе данных.

Результат работы это сравнительная таблица команд и отчёт с фактическим выводом обеих систем. Таблица нужна не для заучивания: она показывает, что задача формулируется одинаково, а инструмент зависит от оболочки. В конце выбирается система, в которой конкретная операция оказалась короче и почему.

## Оборудование и программное обеспечение

- Персональный компьютер с VirtualBox.
- Виртуальная машина `ubuntu-lab` с Ubuntu 22.04, терминал и учётная запись `student`.
- Виртуальная машина `win-lab` с Windows 10, PowerShell и командная строка.
- Общая папка или другой согласованный способ переноса текста между гостями.
- Текстовый редактор для отчёта.

Гостевые машины запускаются одновременно, если хватает памяти. При 8 ГБ на хосте достаточно выделить по 2 ГБ каждой гостевой системе и не запускать лишние приложения.

## Краткие теоретические сведения

Командная оболочка читает строку, разбирает её на имя команды и аргументы и запускает программу. В Linux это чаще всего `bash`, в Windows командная строка `cmd.exe` или оболочка PowerShell. Имена команд исторически разные, но назначение похоже: навигация, работа с файлами, поиск, вывод справки, управление процессами.

Регистр букв различается. В Linux имена файлов и каталогов чувствительны к регистру: `Отчёт.txt` и `отчёт.txt` это два разных файла. В Windows регистр сохраняется при создании, но при поиске и обращении обычно не учитывается. Из-за этого файл, созданный в Linux как `Report.txt`, в Windows откроется по имени `report.txt`, а обратная операция может дать два файла.

Разделитель пути тоже разный. В Linux каталоги разделяются косой чертой `/`, корень один. В Windows используется обратная косая черта `\`, а у каждого диска свой корень. В PowerShell прямую косую черту тоже принимают, но в учебных командах лучше придерживаться принятого для системы вида, чтобы не путать одногруппников.

Потоки вывода устроены похоже. Стандартный вывод идёт на экран, ошибки тоже на экран, но в отдельный поток. Символ `>` перезаписывает файл, `>>` дописывает. В Linux поток ошибок направляют через `2>`, в PowerShell через `2>` или `*>`. Это позволяет сохранить журнал команды целиком.

Код возврата есть в обеих системах. В Linux успех это `0`, ошибка любое другое число. В Windows команда возвращает `%ERRORLEVEL%` в `cmd.exe` и `$LASTEXITCODE` в PowerShell. Проверка кода важна для сценариев, но в этой работе достаточно замечать, что команда завершилась ошибкой, по тексту сообщения.

Справка это отдельный навык. В Linux почти у каждой команды есть `man` и ключ `--help`, у встроенных команд оболочки `help`. В Windows у команд `cmd.exe` справка вызывается ключом `/?`, у команд PowerShell командлет `Get-Help`. Умение найти справку важнее знания всех ключей: набор команд меняется от версии к версии.

Кодировка и перевод строки тоже входят в сравнение. Linux обычно хранит текст в UTF-8 и завершает строку одним символом перевода строки. Windows долго использовала кодовую страницу 1251 для кириллицы и два символа в конце строки, а PowerShell 5.1 по умолчанию может записать файл в UTF-16. Из-за этого одинаковый по смыслу файл имеет разный размер, а поиск по русскому слову в одной системе работает, а в другой нет. В работе указывайте кодировку явно: `Set-Content -Encoding UTF8` и `iconv` или настройки редактора в Linux.

### Шаг 2. Выполнить навигацию по каталогам

Создайте одинаковое дерево каталогов в двух системах. В Linux используйте `mkdir -p`, в Windows `mkdir` создаёт вложенные каталоги при включённом расширении командной строки, а PowerShell делает это по умолчанию.

```bash
cd ~
mkdir -p os-lab/komandy/ishodnye os-lab/komandy/otchet
cd os-lab/komandy
pwd
ls -la
```

```powershell
Set-Location $env:USERPROFILE
New-Item -ItemType Directory -Force -Path 'os-lab\komandy\ishodnye','os-lab\komandy\otchet' | Out-Null
Set-Location 'os-lab\komandy'
Get-Location
Get-ChildItem -Force
```

`pwd` и `Get-Location` печатают текущий каталог. `ls -la` и `Get-ChildItem -Force` показывают скрытые объекты и подробные свойства. Ключ `-Force` в PowerShell аналогичен ключу `-a` в Linux, но не полностью: он показывает и скрытые, и системные объекты.

Проверьте переход в родительский каталог и возврат. Команды `cd ..` работают в обеих системах, а `cd ~` и `cd -` есть только в Linux. В PowerShell домашний каталог задаётся как `$env:USERPROFILE`, а возврат к предыдущему месту выполняет `Set-Location -`.

### Шаг 3. Создать одинаковый набор файлов

Создайте в каталоге `ishodnye` три текстовых файла, один из которых журнал. Содержимое журнала одинаковое в обеих системах, чтобы поиск дал сравнимый результат.

```text
2026-11-01 08:12:03 INFO  служба ssh запущена
2026-11-01 08:15:44 WARN  диск занят на 81%
2026-11-01 08:16:02 ERROR не найден файл расписания
2026-11-01 08:20:11 INFO  проверка завершена
2026-11-01 09:02:37 ERROR нет доступа к каталогу отчётов
2026-11-01 09:03:10 WARN  служба печати не отвечает
2026-11-01 09:04:55 ERROR не найден файл расписания
2026-11-01 09:10:00 INFO  повторная проверка
2026-11-01 09:15:21 ERROR таймаут подключения к базе
2026-11-01 09:20:00 INFO  проверка завершена
```

В Linux файл создаётся перенаправлением вывода. В PowerShell удобнее `Set-Content` с массивом строк, но подойдёт и последовательность `Add-Content`.

```bash
cat > ishodnye/журнал.txt <<'EOF'
2026-11-01 08:12:03 INFO  служба ssh запущена
2026-11-01 08:15:44 WARN  диск занят на 81%
2026-11-01 08:16:02 ERROR не найден файл расписания
EOF
printf 'строка один\nстрока два\n' > ishodnye/заметка.txt
printf 'яблоко\nбанан\nяблоко\n' > ishodnye/список.txt
```

```powershell
@'
2026-11-01 08:12:03 INFO  служба ssh запущена
2026-11-01 08:15:44 WARN  диск занят на 81%
2026-11-01 08:16:02 ERROR не найден файл расписания
'@ | Set-Content -Path 'ishodnye\журнал.txt' -Encoding UTF8
'строка один','строка два' | Set-Content -Path 'ishodnye\заметка.txt' -Encoding UTF8
'яблоко','банан','яблоко' | Set-Content -Path 'ishodnye\список.txt' -Encoding UTF8
```

Для полного журнала добавьте остальные строки тем же способом. Проверьте, что в обеих системах файл содержит десять строк, и только потом переходите к поиску.

### Шаг 4. Найти справку по команде

Выберите команду поиска файлов и посмотрите её справку. В Linux справка открывается по `man find`, в PowerShell по `Get-Help Get-ChildItem`.

```bash
man find
find --help | head -n 20
```

```powershell
Get-Help Get-ChildItem
Get-Help Get-ChildItem -Examples
```

`man` открывает полную страницу и выходит по клавише `q`. Ключ `--help` печатает краткую справку. `Get-Help` без ключей показывает описание и параметры, ключ `-Examples` только примеры. Запишите в отчёт по одному ключу из каждой справки, который пригодится для поиска по имени, и объясните его назначение.

### Шаг 5. Прочитать файл и сохранить вывод

Прочитайте журнал целиком и по частям. В Linux для этого есть `cat`, `head` и `tail`, в Windows `type`, `Get-Content` и `Select-Object`.

```bash
cat ishodnye/журнал.txt
head -n 3 ishodnye/журнал.txt
tail -n 2 ishodnye/журнал.txt
wc -l ishodnye/журнал.txt
```

```powershell
Get-Content 'ishodnye\журнал.txt'
Get-Content 'ishodnye\журнал.txt' -TotalCount 3
Get-Content 'ishodnye\журнал.txt' -Tail 2
(Get-Content 'ishodnye\журнал.txt').Count
```

Сохраните первые три строки в отдельный файл. В обеих системах используется `>`, но в PowerShell есть более явный командлет.

```bash
head -n 3 ishodnye/журнал.txt > otchet/начало.txt
```

```powershell
Get-Content 'ishodnye\журнал.txt' -TotalCount 3 | Set-Content 'otchet\начало.txt' -Encoding UTF8
```

Сравните размеры файлов в двух системах. Размер может отличаться из-за кодировки и перевода строки: в Linux строка заканчивается одним символом, в Windows двумя. Это не ошибка, а следствие разных соглашений.

### Шаг 6. Найти файлы по имени

Найдите все текстовые файлы в дереве `os-lab`. Сначала разберите пример: в Linux `find . -name "*.txt"` ищет от текущего каталога вниз, в PowerShell `Get-ChildItem -Recurse -Filter *.txt` делает то же самое.

```bash
find . -name "*.txt"
find . -type f -name "журнал*"
find . -type f -name "*.txt" -exec ls -l {} \;
```

```powershell
Get-ChildItem -Recurse -Filter *.txt | Select-Object FullName,Length
Get-ChildItem -Recurse -Filter 'журнал*'
Get-ChildItem -Recurse -Filter *.txt | ForEach-Object { $_.FullName }
```

`find` принимает шаблон в ключе `-name`, кавычки защищают звёздочку от подстановки оболочкой. `-type f` ограничивает поиск файлами, `-exec` выполняет команду над каждым результатом. В PowerShell фильтр передаётся параметру `-Filter`, а `Select-Object` оставляет нужные свойства.

Выполните вариацию: найдите файлы, имя которых начинается на `журнал`, и файлы, созданные сегодня. В Linux для второго случая подойдёт `-newermt` с датой, в PowerShell `Where-Object LastWriteTime -gt (Get-Date).Date`. Запишите обе команды в таблицу.

### Шаг 7. Найти строки по содержимому

Найдите все строки с уровнем `ERROR` и посчитайте их. В Linux это `grep`, в Windows `findstr` в командной строке или `Select-String` в PowerShell.

```bash
grep "ERROR" ishodnye/журнал.txt
grep -c "ERROR" ishodnye/журнал.txt
grep -rn "ERROR" .
grep -rni "ошибка" .
```

```powershell
Select-String -Path 'ishodnye\журнал.txt' -Pattern 'ERROR'
(Select-String -Path 'ishodnye\журнал.txt' -Pattern 'ERROR').Count
Get-ChildItem -Recurse -Filter *.txt | Select-String -Pattern 'ERROR'
```

Ключ `-c` считает совпадения, `-n` печатает номер строки, `-i` игнорирует регистр. В PowerShell `Select-String` по умолчанию показывает имя файла, номер строки и текст, а результат можно посчитать как массив. Командная строка Windows использует `findstr /s /n /i "ERROR" *.txt`, где `/s` означает поиск в подкаталогах, `/n` номера строк, `/i` игнорирование регистра.

Выполните вариацию: найдите строки `WARN` и строки, где встречается слово `расписание`. Сравните число найденных строк в двух системах. Если числа разошлись, проверьте кодировку файла и регистр букв, а не только команду.

### Шаг 8. Посмотреть метаданные и размеры

Сравните свойства файла и размер каталога. В Linux это `stat`, `du` и `df`, в PowerShell `Get-Item`, `Measure-Object` и `Get-Volume`.

```bash
stat ishodnye/журнал.txt
du -sh os-lab
df -h .
```

```powershell
Get-Item 'ishodnye\журнал.txt' | Select-Object Name,Length,LastWriteTime
(Get-ChildItem -Recurse -File | Measure-Object -Property Length -Sum).Sum
Get-Volume | Select-Object DriveLetter,FileSystemLabel,SizeRemaining,Size
```

`stat` показывает inode, права, владельца и время изменения. В PowerShell те же сведения разложены по свойствам объекта. `du -sh` считает занятое место с учётом блоков, а сумма `Length` считает логический размер файлов; значения могут немного отличаться.

### Шаг 9. Построить конвейер

Конвейер передаёт вывод одной команды на вход другой. Найдите пять процессов, которые сильнее всего загружают процессор, и посчитайте строки журнала по уровням.

```bash
ps aux --sort=-%cpu | head -n 6
awk '{print $3}' ishodnye/журнал.txt | sort | uniq -c
```

```powershell
Get-Process | Sort-Object CPU -Descending | Select-Object -First 5 Name,CPU
Get-Content 'ishodnye\журнал.txt' | ForEach-Object { ($_ -split '\s+')[2] } | Group-Object | Select-Object Name,Count
```

`ps aux` печатает процессы, `--sort=-%cpu` сортирует по убыванию, `head` оставляет первые строки. `awk '{print $3}'` вырезает третье поле, где разделителем считается любой пробел, `sort` сортирует, `uniq -c` считает повторы. В PowerShell `Group-Object` сразу выдаёт группы с количеством, что короче цепочки `sort | uniq`.

Проверьте, что число строк в журнале совпадает с суммой counts. Если не совпадает, значит разделитель полей выбран неверно: в журнале между уровнем и сообщением может быть два пробела.

### Шаг 10. Выполнить пакетное переименование

Создайте в каталоге `ishodnye` три файла с расширением `.bak`: `отчёт.bak`, `список.bak`, `заметка.bak`. Переименуйте их в `.txt` одной командой в каждой системе. Сначала разберите пример на одном файле, затем примените ко всем.

```bash
cd ishodnye
cp журнал.txt отчёт.bak
cp список.txt список.bak
cp заметка.txt заметка.bak
for f in *.bak; do mv "$f" "${f%.bak}.txt"; done
ls -l *.txt
```

```powershell
Set-Location 'ishodnye'
Copy-Item 'журнал.txt' 'отчёт.bak'
Copy-Item 'список.txt' 'список.bak'
Copy-Item 'заметка.txt' 'заметка.bak'
Get-ChildItem *.bak | Rename-Item -NewName { $_.Name -replace '\.bak$','.txt' }
Get-ChildItem *.txt | Select-Object Name
```

В Linux `${f%.bak}` отрезает самое короткое совпадение с конца, поэтому имя теряет расширение и получает новое. В PowerShell `-replace` работает с регулярным выражением, а точка экранирована обратной косой чертой. Обратная косая черта в PowerShell не является escape-символом в обычной строке, но в шаблоне регулярного выражения она обязательна.

Проверьте, что файлов `.bak` не осталось, а число `.txt` увеличилось на три. Вернитесь в каталог `komandy` командой `cd ..` или `Set-Location ..`.

5. Сравнительная таблица из шести задач с командами Linux, `cmd.exe` и PowerShell.
6. Вывод о двух различиях, которые чаще всего мешают переносить команды между системами.

Экранные снимки допускаются как дополнение. На снимке должны быть видны команда, вывод и приглашение с именем машины, иначе проверить источник результата нельзя.
## Что сдать

- отчёт с таблицами версий, навигации и метаданных;
- текстовые блоки вывода поиска по имени и по содержимому для обеих систем;
- сравнительную таблицу шести задач с тремя вариантами команд;
- результат пакетного переименования с проверкой числа файлов;
- вывод о различиях, которые влияют на перенос команд.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.
- **5**: все шесть задач выполнены в двух системах, команды записаны без ошибок, вывод подтверждает результат, таблица содержит `cmd.exe` и PowerShell, различия объяснены на примерах из своей работы.
- **4**: работа выполнена полностью, но в двух задачах указан только один вариант команды Windows или вывод приведён без проверки количества найденных строк.
- **3**: выполнены четыре задачи из шести, сравнительная таблица заполнена частично, различия описаны общими словами, пакетное переименование не проверено.
- **2**: работа не выполнена или команды выполнялись только в одной системе.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
