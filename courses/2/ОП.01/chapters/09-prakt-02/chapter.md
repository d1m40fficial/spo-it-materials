## Цель работы

Научиться отвечать на три вопроса о любой операционной системе: сколько памяти она использует, сколько места осталось на диске и как устроен каталог, в котором ведётся работа. Проверка выполняется на учебном стенде `os-lab` в гостевой Ubuntu `ubuntu-lab` и в гостевой Windows `win-lab`. Результат работы это набор измерений, текстовое дерево каталогов и обоснованный вывод о том, где заканчивается свободное место и почему.

Измерения нужно снимать до и после нагрузки, а не один раз. Одно число свободной памяти почти ничего не говорит: ядро заняло кэш, процессы выделили память, своп подключён, но не используется. Сравнение двух срезов показывает, что именно изменилось и какой процесс стал причиной.

## Краткие теоретические сведения

Память в Linux учитывается по категориям. `total` это весь объём, доступный системе. `used` это память, занятая процессами и ядром. `free` это совсем не занятые страницы. `buff/cache` это кэш файлов и буферы, которые ядро готово освободить при необходимости. `available` это оценка памяти, которую можно выделить новому процессу без активной подкачки. Столбец `available` важнее `free`, потому что кэш не является потерей.

Своп это область на диске для страниц, которые не поместились в память. Ненулевой `used` в строке свопа сам по себе не является ошибкой. Ошибкой считается постоянный обмен со свопом, когда ядро непрерывно вытесняет и возвращает страницы.

Диск учитывается двумя разными способами. `df` спрашивает файловую систему и показывает занятость разделов. `du` обходит файлы и суммирует их блоки. Расхождение возможно из-за удалённых открытых файлов, скрытых точек монтирования и резервных блоков ext4. Отдельно учитываются inode: таблица метаданных может закончиться раньше, чем свободные блоки, и тогда новый файл не создастся при видимом запасе места.

Каталог это файл, в котором хранятся пары «имя, номер inode». Дерево каталогов показывает вложенность, но не показывает размеры. Для размеров нужны `du`, `find` и сортировка. В Windows ту же роль играют `Get-ChildItem`, `Measure-Object` и `Get-Volume`.

### Шаг 2. Разберите вывод free и снимите профиль памяти

Выполните `free -h` и сохраните вывод в файл, чтобы вернуться к нему после нагрузки.

```bash
free -h | tee memory-before.txt
```

Пример вывода на стенде с 2 ГиБ памяти:

```text
               total        used        free      shared  buff/cache   available
Mem:           1.9Gi       612Mi       214Mi        12Mi       1.1Gi       1.2Gi
Swap:          2.0Gi          0B       2.0Gi
```

Столбец `shared` показывает память, которую делят процессы, например через `tmpfs`. Столбец `available` учитывает кэш, который можно освободить. Если `available` больше `free` в несколько раз, это нормально.

`free` показывает двоичные единицы: 1 ГиБ равен 1024 МиБ. Производители дисков и некоторые программы используют десятичные единицы, где 1 ГБ равен 1000 МБ. Поэтому диск на 64 ГБ в системе может выглядеть как 59,6 ГиБ. Это не пропажа места, а разные единицы измерения. При сравнении чисел из разных отчётов сначала приведите их к одной единице.

Уточните значения в килобайтах командой `free -k`. Она печатает те же строки, что `free -h`, но в килобайтах.

```bash
free -k | tee memory-before-kb.txt
```

Переведите килобайты в мебибайты делением на 1024. Например, total 2048000 даёт 2000 МиБ, или около 1,95 ГиБ. Заполните таблицу, первая строка показывает формат.

| Показатель | Значение из free -h | Значение из free -k, КиБ | Комментарий |
|---|---|---|---|
| Всего памяти | 1.9Gi | 2048000 | объём, доступный гостю |
| Занято |  |  |  |
| Свободно |  |  |  |
| Кэш и буферы |  |  |  |
| Доступно |  |  |  |
| Своп всего |  |  |  |
| Своп занято |  |  |  |

Снимите динамику командой `vmstat 1 3`. Она печатает три среза с интервалом в одну секунду.

```bash
vmstat 1 3 | tee vmstat-before.txt
```

Обратите внимание на столбцы `si` и `so`. Это обмен со свопом в килобайтах в секунду. Если оба равны нулю, активной подкачки нет. Столбец `wa` показывает долю времени ожидания ввода-вывода. Запишите значения `free`, `buff`, `cache`, `si`, `so` и `wa` для трёх срезов.

### Шаг 3. Проверьте реакцию памяти на нагрузку

Запустите программу, которая выделяет 300 МиБ и удерживает их несколько секунд. Разберите команду по частям: `python3 -c` выполняет одну строку кода, `&` отправляет процесс в фон, `$!` содержит идентификатор последнего фонового процесса, `wait` ждёт его завершения.

```bash
python3 -c "block = b'x' * (300 * 1024 * 1024); import time; time.sleep(20)" &
PID=$!
sleep 2
free -m
ps -o pid,rss,vsz,comm -p $PID
wait $PID
free -m
```

Пока программа работает, снимите её память. `RSS` это резидентная память, то есть страницы в физической памяти. `VSZ` это виртуальный размер, который включает резервирование и может быть больше RSS.

Заполните таблицу до и после нагрузки. Разницу считайте по RSS и по `used`, а не по `free`.

| Момент | used, МиБ | free, МиБ | available, МиБ | RSS процесса, КиБ |
|---|---|---|---|---|
| До нагрузки |  |  |  |  |
| Во время нагрузки |  |  |  | 307200 |
| После нагрузки |  |  |  |  |

Сравните RSS процесса с 300 МиБ. Небольшое расхождение нормально: интерпретатор Python и его библиотеки тоже занимают память, а выделение идёт страницами по 4 КиБ.

### Шаг 4. Снимите занятость диска и inode

Посмотрите разделы и точки монтирования.

```bash
df -h
df -T
df -i
lsblk
findmnt
```

`df -h` печатает размеры в удобных единицах, `df -T` добавляет тип файловой системы, `df -i` показывает inode. `lsblk` выводит блоки устройств, `findmnt` дерево монтирования. В строке `df -h` видны файловая система, размер, занятое и свободное место, процент использования и точка монтирования.

Заполните таблицу по своему выводу. Первая строка показывает формат, остальные строки относятся к вашим разделам.

| Файловая система | Тип | Размер | Занято | Свободно | Use% | Точка монтирования |
|---|---|---|---|---|---|---|
| ... | ext4 | 24G | 8.1G | 15G | 36% | ... |
|  |  |  |  |  |  |  |

Отдельно запишите inode. Если `IUse%` близок к 100, новые файлы перестанут создаваться даже при свободных блоках.

| Файловая система | Inodes | IUsed | IFree | IUse% |
|---|---|---|---|---|
|  |  |  |  |  |

Обратите внимание на разницу между размером раздела и доступным местом. ext4 по умолчанию резервирует около 5 процентов блоков для суперпользователя, поэтому обычный пользователь видит меньше свободного места, чем показывает общий объём минус занятое. Команда `df -h` округляет значения, а `df -k` печатает килобайты и удобна для точного расчёта. Если свободного места меньше одного процента, система может работать нестабильно: службы не смогут писать журналы и временные файлы.

Сравните `df -h ~/os-lab` и `du -sh ~/os-lab`. Первая команда показывает весь раздел, вторая только ваш каталог. Объясните в отчёте, почему числа разные и что именно считает каждая команда.

### Шаг 5. Постройте дерево каталогов и найдите крупные файлы

Создайте учебную структуру и несколько файлов разного размера. `mkdir -p` создаёт все недостающие каталоги, `fallocate -l` выделяет файл заданного размера без записи случайных данных.

```bash
mkdir -p ~/os-lab/prakt-02/{docs,logs,data/2026}
fallocate -l 2M ~/os-lab/prakt-02/data/big.bin
for i in 1 2 3; do echo "line $i" > ~/os-lab/prakt-02/logs/app-$i.log; done
```

Постройте дерево и проверьте его содержимое. Ключ `-maxdepth` ограничивает глубину, `-type d` выбирает только каталоги, `-type f` только файлы. В `-printf` заполнитель `%s` печатает размер в байтах, а `%p` полный путь.

```bash
find ~/os-lab/prakt-02 -maxdepth 3 -print | sort
find ~/os-lab/prakt-02 -type d | sort
find ~/os-lab/prakt-02 -type f -printf '%s\t%p\n' | sort -n
```

Нарисуйте дерево в отчёте в виде текстовой схемы. Пример формата для другого каталога:

```text
sample/
├── docs/
│   └── readme.txt
├── logs/
│   └── app.log
└── data/
    └── big.bin
```

Посчитайте файлы и каталоги, найдите самый крупный файл и общий размер каждого подкаталога.

```bash
du -h --max-depth=2 ~/os-lab/prakt-02 | sort -h
find ~/os-lab/prakt-02 -type f -size +1M
```

Ключ `sort -h` сортирует с учётом единиц измерения, поэтому `2,0M` окажется после `900K`. Без `-h` строка `2,0M` считалась бы меньше `900K`, потому что сравнивались бы символы, а не числа.

Заполните таблицу. Первая строка дана как образец.

| Каталог | Число файлов | Занято | Самый крупный файл |
|---|---|---|---|
| data | 1 | 2,0M | big.bin, 2 МиБ |
| docs |  |  |  |
| logs |  |  |  |

Проверьте, как расходуются inode. Создайте тысячу пустых файлов и сравните `IUsed` до и после. Конструкция `$(seq 1 1000)` подставляет числа от 1 до 1000, а `:` это встроенная команда, которая ничего не делает и завершается успешно.

```bash
mkdir ~/os-lab/prakt-02/many
df -i ~/os-lab/prakt-02 | tail -n 1
for i in $(seq 1 1000); do : > ~/os-lab/prakt-02/many/f-$i; done
df -i ~/os-lab/prakt-02 | tail -n 1
```

Запишите разницу в `IUsed`. Объясните, почему занятое место почти не изменилось, а inode израсходовались.

### Шаг 6. Сравните Linux и Windows

Переключитесь на гостевую Windows и откройте PowerShell. Посмотрите тома, память и дерево домашнего каталога.

```powershell
Get-Volume
Get-PSDrive -PSProvider FileSystem
Get-CimInstance Win32_OperatingSystem |
  Select-Object TotalVisibleMemorySize, FreePhysicalMemory
Get-ChildItem $HOME -Force | Measure-Object
```

`Get-Volume` показывает метку, файловую систему, состояние и размер. `Get-CimInstance` возвращает объём памяти в килобайтах. `Measure-Object` считает число объектов в каталоге. Пример вывода без колонки с буквой тома:

```text
FriendlyName FileSystemType HealthStatus SizeRemaining      Size
------------ -------------- ------------ -------------      ----
Windows      NTFS           Healthy             41.2 GB   63.5 GB
DATA         exFAT          Healthy            118.4 GB  119.5 GB
```

Заполните таблицу томов. Первая строка показывает формат.

| Том | Метка | Файловая система | Размер | Свободно | Свободно, % |
|---|---|---|---|---|---|
| Системный | Windows | NTFS | 63,5 ГБ | 41,2 ГБ | 65 |
|  |  |  |  |  |  |

Переведите память из килобайтов в мебибайты и сравните с показателями Ubuntu. Затем постройте дерево и найдите крупные файлы.

```powershell
Get-ChildItem $HOME -Recurse -Directory -ErrorAction SilentlyContinue |
  Select-Object -First 20 FullName
Get-ChildItem $HOME -Recurse -File -ErrorAction SilentlyContinue |
  Sort-Object Length -Descending | Select-Object -First 5 Name, Length, DirectoryName
```

Ключ `-ErrorAction SilentlyContinue` скрывает ошибки доступа к системным папкам. Без него часть каталогов может быть недоступна, и команда напечатает красные сообщения, хотя результат всё равно будет получен.
