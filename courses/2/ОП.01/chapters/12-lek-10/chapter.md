## Одна задача на двух стендах

На стенде `os-lab` нужно найти все файлы журналов старше тридцати дней, посчитать их число и сложить в архив. В графическом файловом менеджере это несколько десятков кликов, и повторить их на втором стенде придётся заново. В командной строке задача решается одной строкой, а строка одинаково работает сегодня, завтра и на другом компьютере.

Командная строка это не пережиток прошлого, а интерфейс, который легко повторять и автоматизировать. Администратор вводит команду один раз, а затем сохраняет её в сценарий и запускает по расписанию. Именно поэтому обе операционные системы, Linux и Windows, сохраняют мощные оболочки, несмотря на развитые графические интерфейсы.

**Командная строка это способ управлять системой текстовыми командами, где каждая команда имеет имя, параметры, аргументы и код возврата.** Разобрав эту структуру один раз, легче переносить знания между bash и PowerShell, даже если имена команд различаются.

## Как устроена команда

Команда состоит из имени программы, параметров и аргументов. Параметры меняют поведение, аргументы указывают, с чем работать. В Linux короткие параметры начинаются с одного дефиса, длинные с двух: `ls -l` и `ls --human-readable`. Короткие можно объединять: `ls -la` означает `ls -l -a`. Два дефиса без имени (`--`) прекращают разбор параметров, если дальше идёт имя файла, похожее на параметр.

```bash
ls -la ~/os-lab
```

Здесь `ls` это имя команды, `-la` два параметра, `~/os-lab` аргумент. Символ `~` оболочка заменяет на домашний каталог до запуска программы. Программа получает уже готовый путь.

В PowerShell команда называется **командлетом** и строится по схеме «глагол и существительное»: `Get-ChildItem`, `Set-Location`, `Copy-Item`. Параметры начинаются с одного дефиса и обычно имеют полные имена, например `-Recurse` или `-Force`. Командлет возвращает не текст, а объекты с полями, поэтому результат можно сортировать и фильтровать без разбора строк.

```powershell
Get-ChildItem -Path $HOME\os-lab -Force
```

После выполнения команда возвращает **код завершения**. В Linux и в обычных программах Windows код 0 означает успех, а любое другое число ошибку. В bash код последней команды лежит в переменной `$?`, в PowerShell для внешних программ используется `$LASTEXITCODE`, а `$?` показывает логический признак успеха.

```bash
ls missing.txt
echo $?
```

```text
ls: cannot access 'missing.txt': No such file or directory
2
```

Код возврата важен в сценариях. Если команда завершилась с ошибкой, следующие шаги могут работать с пустым результатом и создавать ложное ощущение успеха. Проверка кода это часть нормальной автоматизации, а не дополнительная роскошь.

| Элемент | bash | PowerShell |
|---|---|---|
| Имя команды | `ls`, `grep`, `find` | `Get-ChildItem`, `Select-String` |
| Короткий параметр | `-l`, `-a` | `-Force`, `-Recurse` |
| Длинный параметр | `--help` | `-Examples` |
| Аргумент | путь или строка | значение параметра |
| Код успеха | `$?` равно 0 | `$?` равно True, `$LASTEXITCODE` равно 0 |

Оболочка раскрывает шаблоны имён до запуска команды. Звёздочка `*` заменяет любую последовательность символов, знак вопроса `?` один символ, квадратные скобки `[abc]` один символ из набора. Запись `ls *.log` сначала превращается в список файлов, а уже потом передаётся команде `ls`. Если файлов нет, шаблон может остаться без изменений, и команда получит буквальное имя со звёздочкой.

```bash
ls *.log
ls report-?.txt
ls report-[12].txt
```

В PowerShell шаблоны обрабатывают сами командлеты, а не оболочка. Поэтому `Get-ChildItem -Filter *.log` работает даже тогда, когда подходящих файлов нет, и не зависит от раскрытия до запуска. Для сложных шаблонов применяют `-Include` и `-Exclude`.

## Навигация и файлы

Навигация начинается с определения текущего каталога. В Linux это `pwd`, в PowerShell `Get-Location`. Переход выполняется командой `cd` в обоих случаях, но в PowerShell `cd` это псевдоним для `Set-Location`.

```bash
pwd
ls -la
cd ~/os-lab
cd ..
```

```powershell
Get-Location
Get-ChildItem -Force
Set-Location $HOME\os-lab
Set-Location ..
```

Файловые операции тоже образуют пары. Важно помнить, что псевдонимы PowerShell не повторяют параметры Linux. Команда `ls -la` в PowerShell не сработает так, как в bash, потому что у `Get-ChildItem` нет параметра `-la`. Нужно писать `Get-ChildItem -Force`.

| Задача | Linux | Windows PowerShell |
|---|---|---|
| Текущий каталог | `pwd` | `Get-Location` |
| Список файлов | `ls -la` | `Get-ChildItem -Force` |
| Перейти в каталог | `cd путь` | `Set-Location путь` |
| Создать каталог | `mkdir -p путь` | `New-Item -ItemType Directory -Force путь` |
| Копировать | `cp -r источник приёмник` | `Copy-Item -Recurse источник приёмник` |
| Переместить | `mv источник приёмник` | `Move-Item источник приёмник` |
| Удалить | `rm -r путь` | `Remove-Item -Recurse путь` |
| Создать пустой файл | `touch файл` | `New-Item -ItemType File файл` |
| Прочитать файл | `cat файл` | `Get-Content файл` |
| Начало файла | `head -n 5 файл` | `Get-Content файл -TotalCount 5` |
| Хвост файла | `tail -n 5 файл` | `Get-Content файл -Tail 5` |
| Следить за файлом | `tail -f файл` | `Get-Content файл -Wait` |

Вывод `ls -la` показывает скрытые файлы, права, владельца, размер и время. Скрытыми в Linux считаются имена, начинающиеся с точки. В Windows скрытость это атрибут файла, а не часть имени.

```text
$ ls -la
total 16
drwxr-xr-x 3 student student 4096 ноя  3 09:12 .
drwxr-xr-x 8 student student 4096 ноя  3 09:10 ..
drwxr-xr-x 2 student student 4096 ноя  3 09:12 logs
-rw-r--r-- 1 student student  128 ноя  3 09:12 notes.txt
```

PowerShell выводит объекты в таблицу с колонками Mode, LastWriteTime, Length и Name. Режим `d-----` означает каталог, `-a----` обычный файл. Атрибут `h` в колонке Mode означает скрытый файл.

```text
PS> Get-ChildItem -Force

    Directory: ...\os-lab

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d-----         03.11.2026     09:12                logs
-a----         03.11.2026     09:12            128 notes.txt
```

Пути различаются разделителем. В Linux разделитель `/`, в Windows `\`. В PowerShell прямой слэш тоже обычно работает, но в сценариях лучше придерживаться родного разделителя. Домашний каталог в Linux обозначается `~`, в PowerShell переменной `$HOME`, а в командной строке `cmd` переменной `%USERPROFILE%`.

Путь бывает абсолютным и относительным. Абсолютный начинается от корня файловой системы, относительный от текущего каталога. Точка `.` означает текущий каталог, две точки `..` родительский. Команда `cd -` в bash возвращает в предыдущий каталог, а `Set-Location -` делает то же в PowerShell. Если в пути есть пробелы, его заключают в кавычки, иначе оболочка разобьёт путь на несколько аргументов.

## Поиск файлов и текста

Поиск файла по имени в Linux выполняет `find`. Первый аргумент задаёт каталог, `-name` шаблон имени, `-type f` ограничивает поиск файлами. Шаблон в кавычках защищает звёздочку от преждевременного раскрытия оболочкой.

```bash
find . -type f -name "*.log"
find . -type f -name "*.log" -mtime +30
```

Ключ `-mtime +30` означает, что файл изменялся более тридцати суток назад. Найденные имена можно сразу передать в другую команду через `-exec` или `xargs`.

```bash
find . -type f -name "*.log" -mtime +30 -exec wc -l {} \;
find . -type f -name "*.log" -mtime +30 -print0 | xargs -0 -r wc -l
```

`-exec` запускает команду для каждого найденного файла, а `{}` подставляет его имя. Конструкция `xargs` собирает имена в пакет и запускает команду реже, поэтому работает быстрее на большом числе файлов. Ключ `-print0` вместе с `xargs -0` разделяет имена нулевым байтом и не ломается, если в имени есть пробел или перевод строки. Ключ `-r` запрещает запуск команды при пустом списке.

В PowerShell ту же задачу решает `Get-ChildItem` с ключами `-Recurse`, `-Filter` и `-File`. Фильтр применяется на стороне файловой системы и работает быстрее, чем отбор через `Where-Object`.

```powershell
Get-ChildItem -Path . -Recurse -File -Filter *.log
Get-ChildItem -Path . -Recurse -File -Filter *.log |
  Where-Object LastWriteTime -lt (Get-Date).AddDays(-30)
```

Поиск текста внутри файлов в Linux выполняет `grep`. Ключ `-r` включает рекурсивный обход, `-n` печатает номера строк, `-i` игнорирует регистр.

```bash
grep -rn "ERROR" logs/
```

В PowerShell поиск строк выполняет `Select-String`. Он принимает файлы из конвейера и печатает имя файла, номер строки и совпадение.

```powershell
Get-ChildItem logs -Recurse -File |
  Select-String -Pattern "ERROR"
```

Команда `where.exe` в Windows ищет исполняемые файлы по путям, а с ключом `/r` умеет обходить каталог рекурсивно. В Linux команда `which` показывает, какой исполняемый файл будет запущен, а `type` дополнительно сообщает, является ли имя псевдонимом или встроенной командой.

```bash
which python3
type ls
```

```powershell
Get-Command python
where.exe python
```

> [!PITFALL] Поиск по имени и поиск по содержимому это разные задачи
> `find` и `Get-ChildItem -Filter` ищут имена файлов. `grep` и `Select-String` ищут текст внутри. Если нужен файл, в котором встречается слово, сначала находят файлы, затем передают их в поиск строк. Если нужно имя, поиск строк только запутает.

## Конвейер, перенаправление и условия

**Конвейер** передаёт вывод одной команды на вход другой. В bash это вертикальная черта `|`, в PowerShell тоже. Разница в том, что bash передаёт текст, а PowerShell объекты.

```bash
ls -l | sort -k5 -n | tail -n 5
```

Здесь `ls -l` печатает строки, `sort -k5 -n` сортирует по пятому полю как по числу, `tail` оставляет последние пять строк. В PowerShell сортировка идёт по свойству объекта, а не по номеру поля.

```powershell
Get-ChildItem -File |
  Sort-Object Length -Descending |
  Select-Object -First 5 Name, Length
```

**Перенаправление** меняет поток вывода. Знак `>` записывает стандартный вывод в файл и перезаписывает его, `>>` дописывает в конец. Запись `2>` отправляет стандартный поток ошибок, `2>&1` объединяет ошибки с обычным выводом.

```bash
find . -name "*.log" > logs.txt 2> errors.txt
```

```powershell
Get-ChildItem -Recurse -Filter *.log |
  Out-File logs.txt -Encoding utf8
```

В Windows PowerShell 5.1 знак `>` по умолчанию создаёт файл в кодировке UTF-16, а не UTF-8. Для обмена с Linux и другими программами лучше явно указывать `-Encoding utf8` через `Out-File` или `Set-Content`. В PowerShell 7 кодировка по умолчанию уже UTF-8.

Условия в bash записывают через `&&` и `||`. `&&` выполняет вторую команду только при успехе первой, `||` только при ошибке. PowerShell 7 поддерживает те же операторы, а Windows PowerShell 5.1 их не понимает и требует `;` с проверкой `$?`.

```bash
mkdir -p backup && cp notes.txt backup/ || echo "копирование не удалось"
```

```powershell
New-Item -ItemType Directory -Force backup
if ($?) { Copy-Item notes.txt backup\ } else { Write-Output "копирование не удалось" }
```

| Оператор | bash | PowerShell 5.1 | PowerShell 7 |
|---|---|---|---|
| Конвейер | `|` | `|` | `|` |
| Запись с перезаписью | `>` | `>` | `>` |
| Дозапись | `>>` | `>>` | `>>` |
| Ошибки в файл | `2>` | `2>` | `2>` |
| И при успехе | `&&` | нет | `&&` |
| Или при ошибке | `||` | нет | `||` |

## Справка и обнаружение команд

В Linux справка встроена в систему страниц руководства. `man ls` открывает полное описание, `ls --help` краткую справку, `apropos copy` ищет команды по описанию. Если страница не установлена, `man` сообщит об этом, и тогда остаётся `--help`.

```bash
man ls
ls --help
apropos "copy files"
```

В PowerShell справка построена на командлетах. `Get-Help Get-ChildItem` показывает описание, `-Examples` примеры, `-Full` все разделы. `Get-Command` ищет команды по имени, а `Get-Help about_Redirection` объясняет тему целиком.

```powershell
Get-Help Get-ChildItem -Examples
Get-Help about_Redirection
Get-Command *service*
```

Старые программы Windows часто не имеют командлетной справки и отвечают на ключ `/?`. Например, `dir /?` печатает краткую справку по встроенной команде `dir`. Это не то же самое, что `Get-Help dir`, потому что `dir` в PowerShell это псевдоним для `Get-ChildItem`, и справка будет о командлете.

Автодополнение экономит время и уменьшает число ошибок. В bash работает клавиша Tab, история доступна по стрелке вверх и по `Ctrl+R`. В PowerShell Tab дополняет команды и параметры, история доступна через `Get-History` и клавишу F7.

Сокращения создают командой `alias`. В bash строка `alias ll='ls -la'` живёт до конца сеанса, а для постоянного использования её добавляют в `~/.bashrc`. В PowerShell `Set-Alias ll Get-ChildItem` действует в текущем сеансе, а постоянный псевдоним сохраняют в профиле. Псевдоним не создаёт новую программу, он только подставляет имя и не меняет поведение исходной команды, поэтому справка по нему показывает исходную команду.

## Переменные, кавычки и сценарии

Переменная хранит значение, которое подставляется в команду. В bash присваивание не должно содержать пробелов вокруг знака равенства, а обращение к переменной начинается со знака доллара.

```bash
NAME="os-lab"
echo "Стенд: $NAME"
```

В PowerShell переменная начинается со знака доллара, а присваивание допускает пробелы.

```powershell
$Name = "os-lab"
Write-Output "Стенд: $Name"
```

Кавычки управляют подстановкой. В bash одинарные кавычки сохраняют всё буквально, двойные раскрывают переменные и команды. В PowerShell одинарные кавычки тоже буквальные, а двойные раскрывают переменные. Разница в деталях, но правило похожее: если нужен точный текст, берите одинарные кавычки.

```bash
echo '$HOME'
echo "$HOME"
```

```powershell
Write-Output '$HOME'
Write-Output "$HOME"
```

Сценарий в Linux это текстовый файл с первой строкой `#!/bin/bash`, которая указывает интерпретатор. Файлу нужно дать право на выполнение командой `chmod +x`, после чего его запускают как `./script.sh`. В PowerShell сценарий имеет расширение `.ps1`, а запуск может блокироваться политикой выполнения.

```bash
#!/bin/bash
set -e
for file in *.log; do
  echo "Обработка $file"
done
```

```powershell
$files = Get-ChildItem -Filter *.log
foreach ($file in $files) {
  Write-Output "Обработка $($file.Name)"
}
```

Политика выполнения PowerShell по умолчанию на Windows 10 запрещает запуск сценариев. Для учёбы её меняют в области текущего пользователя, не затрагивая всю систему.

```powershell
Get-ExecutionPolicy
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Строка `set -e` в bash останавливает сценарий при первой ошибке. В PowerShell аналогичное поведение задают параметром `$ErrorActionPreference = "Stop"`. Без этого сценарий может продолжить работу после ошибки и испортить результат.

## Процессы и состояние системы

Командная строка нужна не только для файлов. Через неё смотрят процессы, занятость диска, адреса и порты. Команды снова образуют пары, хотя названия различаются сильнее, чем в файловых операциях.

```bash
ps aux
ps -eo pid,comm,%cpu,%mem --sort=-%cpu | head -n 5
kill 2143
```

`ps aux` печатает все процессы с идентификатором, владельцем и потреблением ресурсов. Сортировка по `%cpu` показывает самых активных. Команда `kill` посылает процессу сигнал завершения, по умолчанию SIGTERM, который даёт программе время закрыть файлы. Ключ `-9` посылает SIGKILL и завершает процесс немедленно, без очистки, поэтому его применяют только когда обычное завершение не сработало.

```powershell
Get-Process
Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
Stop-Process -Id 2143
```

В PowerShell `Get-Process` возвращает объекты с полями Id, ProcessName, CPU и WorkingSet64. `Stop-Process` завершает процесс по идентификатору или имени. Как и `kill -9`, ключ `-Force` не даёт программе корректно закрыть ресурсы, поэтому сначала пробуют обычное завершение.

| Задача | Linux | Windows PowerShell |
|---|---|---|
| Список процессов | `ps aux` | `Get-Process` |
| Завершить процесс | `kill PID` | `Stop-Process -Id PID` |
| Свободное место | `df -h` | `Get-Volume` |
| Память | `free -h` | `Get-CimInstance Win32_OperatingSystem` |
| Адреса интерфейсов | `ip addr` | `Get-NetIPAddress` |
| Открытые порты | `ss -tulpn` | `Get-NetTCPConnection` |
| Версия системы | `uname -a` | `Get-ComputerInfo` |

Идентификатор процесса PID уникален только в момент жизни процесса. После завершения он может достаться новой программе, поэтому сохранять PID надолго нельзя. Если нужно найти процесс по имени, в Linux используют `pgrep имя`, в PowerShell `Get-Process -Name имя`. Для поиска по порту в Linux удобен `ss -tulpn`, в Windows `Get-NetTCPConnection -LocalPort 22`.

## Сравнение и типичные ошибки

Linux и Windows выросли из разных традиций, поэтому различия есть даже там, где команды выглядят одинаково. Сравнивать команды удобнее не по названию, а по задаче: что подаётся на вход, что получается на выходе и как обрабатывается ошибка.

| Свойство | Linux | Windows |
|---|---|---|
| Оболочка по умолчанию | bash | Windows PowerShell 5.1 |
| Регистр в именах файлов | учитывается | не учитывается, но сохраняется |
| Разделитель пути | `/` | `\` |
| Скрытый файл | имя начинается с точки | атрибут Hidden |
| Исполняемость | бит выполнения | расширение и `PATHEXT` |
| Конец строки | LF | CRLF |
| Кодировка по умолчанию | UTF-8 | UTF-16 в PowerShell 5.1 |
| Повышение прав | `sudo` | запуск от имени администратора |

**Псевдонимы PowerShell не равны командам bash.** `ls`, `cat`, `rm`, `cp`, `mv` в PowerShell существуют, но принимают другие параметры и работают с объектами. Строка `ls -la` из инструкции для Linux в PowerShell не выполнится. Нужно либо использовать `Get-ChildItem -Force`, либо помнить, что псевдоним это только короткое имя.

**Регистр имеет значение в Linux.** Файлы `Report.txt` и `report.txt` это два разных файла. В Windows они считаются одним именем. Сценарий, написанный на Windows, может сломаться на Linux из-за одной заглавной буквы.

**Кодировка и конец строки ломают переносимые сценарии.** Файл, созданный в Windows с CRLF, в Linux может дать ошибку `bad interpreter: /bin/bash^M`. Кодировка UTF-16, привычная для PowerShell 5.1, не читается многими Linux-утилитами. Для обмена используют UTF-8 и LF.

**Перенаправление `>` затирает файл без вопросов.** Если в файле были данные, они исчезнут. Для дописывания нужен `>>`. В PowerShell полезен ключ `-WhatIf` у командлетов изменения: он показывает, что было бы сделано, и не трогает данные.

**Удаление необратимо.** В Linux `rm -rf` удаляет каталог со всем содержимым без корзины. В PowerShell `Remove-Item -Recurse -Force` делает то же самое. Перед удалением проверяют путь командой `pwd` или `Get-Location`, а шаблон сначала выводят через `ls` или `Get-ChildItem`.

**Политика выполнения блокирует сценарии.** Это не ошибка синтаксиса. Сообщение `running scripts is disabled on this system` говорит о настройке безопасности, а не о том, что файл повреждён.

**Команда не найдена по трём причинам.** Программа не установлена, её каталог отсутствует в переменной `PATH` или имя набрано с другим регистром. Проверка `command -v имя` в Linux и `Get-Command имя` в PowerShell показывает, существует ли команда и откуда она берётся. Иногда имя занято псевдонимом, и тогда стоит вызвать программу по полному пути.

**Повышение прав не одинаково.** В Linux `sudo` повышает права одной команды и спрашивает пароль пользователя. В Windows нужно открыть новый терминал от имени администратора, и только в нём команда получит полный маркер. Попытка выполнить административную команду в обычном окне завершится отказом, даже если учётная запись входит в Administrators.

## Итоги

- Команда состоит из имени, параметров и аргументов, а результат сопровождается кодом возврата.
- bash работает с текстом, PowerShell с объектами, поэтому одинаковые задачи записываются по-разному.
- Навигация, файловые операции, поиск и справка образуют пары команд, которые полезно держать в таблице.
- Конвейер и перенаправление соединяют команды в цепочки, а условия управляют выполнением.
- Кавычки, кодировка, регистр и конец строки чаще всего ломают переносимые сценарии.
- Перед удалением или перезаписью проверяют путь и результат, потому что отмена в командной строке не предусмотрена.
